## 【対応確認】HIGH1 — 当たり判定は独立検証で決着

### 実装

[`hittest.ts`](../poc/hittest.ts) の `hitTest` が2段構成になった。ブロードフェーズは従来どおり
1辺 2r の bbox で `queryRenderedFeatures`、ナローフェーズで候補の各セグメントに対し
`distToSegment`（ユークリッド）を計算し `<= r` で絞る。頂点は `map.project()` で
**スクリーン座標に変換してから**距離を測っている（経緯度のまま測ると緯度で歪むため、これが正しい）。

「円は正方形 bbox に内接するのでブロードフェーズが取りこぼさない」というコメントも正しい。

### 独立検証（レビュー側で実施）

PoC dev サーバー（`npm run dev:poc` → `:5173`）で `/poc/hittest.html` を開き、
`__hitTest`（修正後）と `map.queryRenderedFeatures` 直呼び（修正前相当）を**同一点で比較**した。
テスト線は水平のため、**線の端点の外側**にオフセットした点を使うと最近点が端点になり、
ユークリッド距離が効く（線の中点では斜めにずらしても距離は垂直成分だけになり、差が出ない）。

| 判定点 | ユークリッド距離 | 円の正解 | bbox のみ（修正前） | ナローフェーズ有（修正後） |
|---|---|---|---|---|
| 中点・垂直 dy=7.5 | 7.50 | ヒット | ヒット | ヒット |
| 中点・垂直 dy=8.6 | 8.60 | 非ヒット | 非ヒット | 非ヒット |
| **端点・斜め 7.2/7.2** | **10.18** | **非ヒット** | **ヒット（誤）** | **非ヒット（正）** |
| 端点・斜め 5.0/5.0 | 7.07 | ヒット | ヒット | ヒット |
| **端点・斜め 7.9/7.9** | **11.17** | **非ヒット** | **ヒット（誤）** | **非ヒット（正）** |

（zoom 8・テスト線中点 `(952, 464.5)`・東端点 `(1316.1, 464.5)`）

**垂直軸の2件は修正前後が完全に一致する** — 前レビュー HIGH1 の主張
「差が出ない軸だけを測っていた」がこれで独立に実証された。
**斜め軸の2件は修正前がいずれも誤ヒットし、修正後は正しく除外される** — ナローフェーズが
効いていることの直接証拠。

**この項目は決着とする。**

### 良かった点

`DEFAULT_R` のコメントで、Leaflet の実効許容半径が厳密には `tolerance + weight/2` であり、
本番はレイヤーごとに weight が異なる（活断層1.2・プレート境界2・津波海岸線は可変）ため
**単一の r で全レイヤーに厳密一致させられない**と明記したのは適切。
「一致した」と言い切らず残差を残す判断は、前回の「境界一致」の反省が効いている。

## 【新規 HIGH】MEDIUM3 対応 — ラベル計測が狙った負荷を一度も踏んでいない

### 観測

`/poc/label.html` で `__runLabelZoomSuite()` を2回連続実行した:

| 段 | 初回 `elapsedMs` | 2回目 `elapsedMs` | longtask |
|---|---|---|---|
| `z-any->z6`（地方9件） | **3.3** | 318.0 | 0 |
| `z6->z8`（県47件） | 608.4 | 612.1 | 0 |
| `z8->z11`（区域192件・最多ユニーク漢字） | 915.9 | 610.6 | 0 |

一見「longtask 0 ＝ 安い」と読めるが、**各ズームで実際に何が描かれたか**を
`queryRenderedFeatures` で確認すると様子が違う:

| ズーム | 描画シンボル数 | 内訳 |
|---|---|---|
| z6 | 29 | `intensity-label` 26 / `regions-label` 3 |
| z8 | 5 | `intensity-label` 2 / `prefectures-label` **3** |
| **z11**（「192件」の段） | **0** | **なし** |
| 日本全体（z5.13・`fitBounds(JAPAN_BOUNDS)`） | **0** | `regions-label` の `minzoom 5.5` に届かず |

決定的なのは MapLibre のグリフキャッシュ（`map.style.glyphManager.entries`）の直接観測:

| 状態 | 生成済みグリフ種数 |
|---|---|
| z6 到達後 | **40** |
| z8 到達後 | **40** |
| z11 到達後 | **40** |
| 日本全体（z5.13）到達後 | **40** |

**全ズーム帯を通じて 40 種のまま一度も増えていない。**
40 種は初期表示（初期 zoom 6）で生成された震度ラベル（`"1"`〜`"7"`・`"5弱"` 等）と
地方名9件のぶんに相当する。**県名47件・区域名192件のグリフは一度も生成されていない。**

### 原因

ズームインすると視野が狭まり、対象点がすべて画面外に出る。z11 の視野は数 km しかなく、
`subregions.json` のラベル座標が1点も入らない。逆にズームアウトすれば `minzoom` で
レイヤーが消える。**この構成では「多数の文字種が同時に初出現する状態」が原理的に存在しない。**

つまり `longtask 0` は「グリフ生成が安い」の意味ではなく「**ほとんど何も生成していない**」。
`elapsedMs` の 608〜916ms も、その大半はタイル読み込み待ち（`idle` までの時間）であり、
グリフ生成コストと分離できていない。

### この失敗の構造

**前レビュー HIGH1（当たり判定の垂直軸）と同型で、通算3度目である。**

| 項目 | 測ろうとしたもの | 実際に測っていたもの |
|---|---|---|
| 層B・検証項目1 | 描画負荷の律速 | vsync 天井（飽和した指標） |
| 項目4（前レビュー HIGH1） | 円と正方形の差 | 両者が恒等的に一致する軸 |
| **§8 ラベル（本件）** | **多数グリフの生成コスト** | **空の視野（生成が起きない状態）** |

いずれも「**差の出ない条件で差が出なかった**」を良い結果として読む形。
共通の対策は「**その計測が狙った負荷を本当に踏んだかを、結果自身に含める**」ことに尽きる。

### 対処（2点・(2) は必須）

**(1) ズーム帯での切り替えをやめ、広域ビューのまま表示を切り替える**

各ラベルレイヤーの `minzoom`/`maxzoom` を計測時だけ外し、日本全体が映るビュー
（`fitBounds(JAPAN_BOUNDS)`）を保ったまま `setLayoutProperty(id, 'visibility', 'visible')` で
順に出す。これなら県47件・区域192件が同時に視界へ入り、狙ったユニーク文字種が一度に初出現する。

なお、この構成は**本番の表示条件とは異なる**（本番も `z9` 以上でしか区域名を出さない）。
逆に言えば「本番では数百グリフが一度に生成される局面が存在しない」可能性もあり、
それ自体が §8 への答えになりうる。**どちらであるかを、まず測って確かめるべきである。**

**(2) 計測結果に「実際に描かれた件数」と「生成済みグリフ種数」を含める**

```ts
renderedSymbols: map.queryRenderedFeatures({ layers: [...] }).length,
glyphsGenerated: Object.keys(map.style.glyphManager.entries[stack]?.glyphs ?? {}).length,
```

これが結果に入っていれば、`longtask 0` が「安い」か「動いていない」かを後から判別できる。
**LOW（`tracked` フラグ）で入れてもらった処方箋とまったく同じもの**であり、
今回レビュー側がグリフキャッシュを直接覗くまで気づけなかったのは、
結果にこの情報が無かったためである。

## 【対応確認】HIGH2 — vsync 実測の伝播

[`measure.ts`](../poc/measure.ts) の対応:

- モジュールスコープに `lastEstimatedVsyncMs` を持ち、`measureOnce` の `phase === 'static'` 時に更新
- `measureOneFly` の `meta` に `estimatedVsyncMs: lastEstimatedVsyncMs` を追加
- `__runCameraSuite` の先頭で `measureOnce(deps, 'static', 2000, \`${labelBase}-vsync-check\`)` を一度踏む

構造は正しい。`meta` 内でのキー順（`...extraMeta` / `...snapshot()` より前）についても、
両者に `estimatedVsyncMs` キーは無く上書きの心配は無い。

**キャッシュ陳腐化の注記を自分で書き添えている点を評価する** — 「`__runCameraSuite` 実行後に
`static` を挟まず単発計測だけを繰り返すと直近スイート時点の古い値が使われ続ける」という
限界が、コメントとして明示されている。

### 実行確認を行わなかった理由

`scripts/perf/results/` は **Git 管理下**（`git check-ignore` で確認）であり、
開発機（Playwright の Chromium・ヘッドレス）の証跡を実機（Surface Go 2）の証跡群に
混ぜたくない。加えて Playwright の Chromium は vsync 周期が実機と異なるため、
**開発機で回しても計画書の食い違い（「16.7ms＝60Hz」対 `b5d8bae` の「170Hz」）は解決しない。**
このフィールドの実効確認は実機計測時に行われるべきものとして残す。

## 【対応確認】LOW — `tracked` フラグ

`WebglMemorySnapshot` に `tracked: boolean` を追加し、webgl2 コンテキストを一度でも
捕捉できたかを区別できるようにした。stat パネルにも未計測表示を出す。妥当。

## 軽微 — `runLabelZoomSuite` のコメントと実装の乖離

コメントは「`z5(非表示)→z6(地方)→z8(県)→z11(区域)`」と4段を謳っているが、実装は
`measureLabelZoomTransition(6, ...)` から始まり **z5 を踏まない**。
さらに地図の初期 zoom が 6（[`label.ts:109`](../poc/label.ts)）なので、
**初回1件目は `setZoom(6)` が実質 no-op** になる。初回の `elapsedMs` が 3.3ms で、
2回目（z11 からの復帰）が 318ms である事実がその証拠。

上記 HIGH の対処でスイート構成自体を見直すため、その際に併せて解消されたい。

| 型チェック | `npx tsc -b` | **エラー 0** |

### 前レビューでの自分の懸念の撤回

前レビューで `label.ts` の `map.once('idle', finish)` について
「タイムアウト経路で `map.off('idle', finish)` が効かずリスナーが残るのでは」と疑ったが、
**これは誤り**。MapLibre の `Evented.off` は `_listeners` と `_oneTimeListeners` の
**両方**から削除し、`once` はラッパを介さず元の listener をそのまま登録する
（`maplibre-gl-shared-dev.mjs:3079-3089`）。`off` で正しく外れる。実装に問題は無い。
