## 1. `a455644`・`fd86e16`（高精細ソース切替・間引き撤廃）— 問題なし

`5fba87b`と同じ方針（EPSILON=0で全頂点保持）をソース自体の高精細版(`_1`)切替・活断層・津波海岸線にも
拡張したもの。理由（三陸リアス海岸の角張り解消・産総研DBの密集域描画）・トレードオフ（ダウンロード量増・
描画性能不変）の説明は一貫しており、PoCの検証項目1（律速切り分け）の結論とも整合する。

## 2. `c70d63e`（県境の融合生成）— 優れた設計

県境と一次細分区域の境界が別々のGISデータから独立生成されていたために極拡大でズレる問題を、
**「区域を県ごとにdissolveして県ポリゴンを作る」方式に変更して原理的に解消**している。

- `mapshaper`の`largest-overlap`join・`dissolve2`を使った実装は標準的かつ適切
- 重ならない孤立離島（鷹島(甑島南方)等）への最近傍県フォールバック（`nearestPrefName`）は
  頂点への最小二乗距離によるブルートフォースだが、ビルド時スクリプト（ブラウザに載らない）かつ
  高精細化後は境界頂点が密なため、この近似で実用上十分
- geometry を持たない岩礁の除外が`subregions.json`側の除外と整合していることも確認・記載されている
- 検証（県境頂点の97.15%が細分区分頂点と完全一致・残り2.85%もサブ11m差）は具体的で説得力がある

## 4. [MEDIUM/情報] 頂点数の合計がPoC検証範囲を大きく超えている

PoC（検証項目6・§6「本番相当ベースマップ」）が実機で検証した基準は
**「区域境界＋県塗り＋県境線＝40,917頂点」**だった。

今回の4コミットを経て、地図上の主要な線・塗りの頂点数は:

| データ | 頂点数（今回時点） |
|---|---|
| 一次細分区域 | 142,471 |
| 都道府県（融合後） | 97,562 |
| 活断層線 | 31,436 |
| 津波海岸線 | 86,846 |
| **合計** | **約358,000（PoC基準の約8.75倍）** |

PoCの検証項目1（律速切り分け）は「塗り面積4倍・線幅10倍」という**合成的なスケーリング**で
律速に到達しないことを確認したものであり、**実際の複雑な海岸線ジオメトリでの生の頂点数増加**とは
負荷の性質が異なる可能性がある（頂点シェーダ処理・ラインのマイタージョイント数など、
単純倍率のテストでは代表しきれない要素がある）。

**コードとしての正しさに問題は無く、これはブロッカーではない。** ただし「移行せずに直せる余地は
静止時より小さい」というGO判断の前提が、ここまでの頂点数増加後も保たれているかは、
**軽い実機確認（最大ズームで全レイヤー表示・fps/blockMaxMs一目盛り）で裏取りしておくと安心**。
本番実装が進んでいる最中の作業を止めるほどの懸念ではないため、区切りの良いタイミングで
確認することを推奨する。
