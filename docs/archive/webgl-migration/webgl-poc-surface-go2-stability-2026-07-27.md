## 1. 経緯 — 1回目は中断、2回目で完走

1回目（15:27〜、42サンプル）は、レビュー側が別環境からのプッシュ（`546ee9f`）を実行中に
`git pull` したことが原因で、PoC 用 dev サーバー（`:5173`）が依存グラフ変化を検知して自動再起動し、
接続中のページがフルリロードされて中断した（詳細は [[feedback-no-pull-during-long-measurement]]）。
以後は長時間計測中の pull を控える運用に変更し、2回目を実行した。

2回目（15:59〜16:26、**61サンプル・1804秒＝30分04秒で完走**）が本文書の判定対象。

## 3. 時系列トレンド（summary の first/last だけでは判別できないため個別サンプルを確認）

- **`jsHeapMB`**: 全期間を通じて 27.9〜38.8MB の範囲で振動（GC によるノイズ）。トレンドなし。
- **`webglTotalMB`**: 最初の約3.5分（サンプル1〜7）で **6.98MB → 39.4MB** と急上昇（タイル・テクスチャが
  ワーキングセットに埋まる立ち上がり）。以降、残り約26.5分（サンプル8〜61）は **41〜44MB の帯で振動する
  だけでプラトー**。単調増加は継続していない。

計画書の PASS 条件「初期の立ち上がり増加は正常、後半で持続的・単調に増え続けるかだけを見る」に照らし、
**後半は増え続けていない＝リークの兆候なし**。

## 4. 判定

| FAIL 条件 | 該当 |
|---|---|
| `contextLost > 0` | 否（0） |
| 途中終了（タブ kill・意図時間より前に途切れる） | 否（1804秒＝意図した30分を完走） |
| メモリが頭打ちにならず単調増加継続 | 否（サンプル8以降プラトー） |

**PASS。** §8 実行時メモリの安定性観測は完了とする。

## 5. 残る留保

- 本観測は PoC（`poc/index.html`）でのものであり、**本番アプリでの長時間稼働は未観測**。
  ただし §8 の目的は「WebGL コンテキストの長時間安定性」というエンジン一般の性質を問うものであり、
  PoC と本番でこの性質が変わる理由は無いと考えられる（**未検証**）。
- `webglMemoryTracker` はバッファ・テクスチャの確保量推定であり VRAM の直接計測ではない
  （計画書 §8 に記載済みの既知の限界）。
- 実機の物理メモリ使用（タブのフットプリント）はタスクマネージャ併用が別途必要（§8 記載の既知の限界）。
