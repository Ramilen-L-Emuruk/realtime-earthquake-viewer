# 公開観測点の波形（設計）

気象庁が運用する広帯域地震計の網（FDSN の網コード `JP`）の波形を、米国の EarthScope が公開している。
その波形を、地図の下の波形の枠と地震カードに出す。自作地震計を持っていない人でも、
近くで起きた地震の揺れを波形で見られるようにする。

**この資料はまだ実装していないものの設計**で、実装したら中身を
[`data-sources-spec.md`](spec/data-sources-spec.md)（取得）と、画面を扱う仕様書の該当節へ移す。

**読者は、波形の枠（`components/SeismoWaveChart/`）・地震カードの波形（`components/EarthquakeTab/QuakeSeismoWave.tsx`）・
地図の印を触る開発者。** 自作地震計の波形がいまどう出ているかは
[`data-sources-spec.md`](spec/data-sources-spec.md) §4.5 にあり、この資料はそれを知っている前提で書く。

## 用語

| 語 | 意味 |
|---|---|
| FDSN | 国際デジタル地震計網連合。観測網ごとに 2 文字の網コードを割り当て、データの取り出し方（FDSN Web サービス）を定めている |
| 公開観測点 | この資料で扱う、気象庁の広帯域地震計の網 `JP` の観測点。EarthScope のリングに流れているのは 20 点（§3.1） |
| 自作地震計 | 開発者が自宅に置いている観測点（`seismo-host/`）。アプリへはホストからの押し出しと読み返し（`/waves`）で届く |
| EarthScope | 米国の地震観測データの公開機関（旧 IRIS）。この資料では、そのリングと保存庫を使う |
| リング | EarthScope の配信サーバーが抱えている直近のデータ。約 1 時間 40 分ぶん（§3.2） |
| SeedLink | リングからデータを受ける手順。WebSocket（`wss://rtserve.earthscope.org/seedlink`、副プロトコル `SeedLink3.1`）で繋ぐ |
| 保存庫 | EarthScope の FDSN Web サービス（`service.earthscope.org/fdsnws/dataselect`）。時刻の範囲を指定して過去の波形を返す |
| miniSEED | 地震波形の交換形式。リングも保存庫も 512 バイトのレコード（版 2・圧縮つき）で返す |
| レコード | miniSEED の 1 区切り。1 成分の、続いたサンプルの塊 |
| 成分 | 東西・南北・上下の 3 つ。公開観測点ではチャンネル名 `BHE`・`BHN`・`BHZ` |
| STS-2 | 公開観測点の地震計の機種。地面の揺れの速さ（速度）を測る広帯域の地震計 |
| 予測計測震度 | 地震の規模・深さ・震源距離から、ある地点の計測震度を見積もった値（`utils/eew.ts` の `predictMeasuredIntensity`） |
| 有感範囲 | この資料では、予測計測震度が −1.5 以上になる観測点の集まり（§0・§4） |
| RMS | 二乗平均の平方根。ここでは揺れの前の雑音の大きさを表すのに使う |

## 0. 決まっていること

**ここでいうユーザーは、開発者（リポジトリの所有者）。** 日付は会話記録の UTC の日付で、下の行はすべて 2026-10-14
（会話記録で行ごとに確かめた）。行ごとに、ユーザーの発言か、問いと選んだ選択肢を原文のまま添える。
**原文を添えられないものはここに書かず、§12 に置く。**

**構想（原文）**: 「揺れ検知やEEWが起こったら画面下部に有感範囲の観測点の波形を描画する。地震カードに自作地震計と同じような形で有感範囲の観測点の該当時刻の波形を描画するとかやりたいです。その際にどこの観測点かは地図に線引っ張るとか点を描画するとかしてわかりやすい方法にする必要があると思いますが、これは後で決めましょう。」

**原則（原文）**: 「前なんかのときも言っていますが、観測できている波形を落とすよりは観測できていない波形を出してください。」
これは、問い「公開観測点の波形の見せ方と、出すしきい値の組をどれにしますか？」（選択肢「生の波形・0.5（推奨）」「遅い揺れを落とす・0.0」「両方を切り替えで」）への答え。
→ 迷ったら出す側へ倒す。波形が映らない観測点を出してしまうほうが、映る観測点を出し損なうよりよい。以下の判断はすべてこれに合わせる。

| 自作地震計の観測点には地図の印を出さない（今のまま） | 問い「自作地震計の観測点にも、地図に印を出しますか？」に選択肢「出さない（今のまま）」。ほかは「出す。共有カードの画像からは外す」「出す。共有カードにも写る」「今は決めない」 |
| 公開観測点の機能を入れるときに合わせて、下部の波形をもっと滑らかに流す（§5.4） | 「あと機能入れるときついでに下部の波形をもっと滑らかに流してほしいです。」 |
| 下部の波形の右端は、届いたサンプルではなく時計の「いま」にする | 問い「自作地震計の下部の波形の右端を、どの時刻にしますか？（滑らかに流すには、右端を時計で進める必要があります）」に選択肢「いま」（説明「遅れは足さない。右端には常に、まだ届いていない 0.3 秒ほどの空白がちらつく」）。ほかは「いま−0.5秒（推奨）」「いま−1秒」 |

**予報業務との関係（開発側の読み。気象庁の見解を得たものではない）**: 気象庁の FAQ
（<https://www.jma.go.jp/jma/kishou/minkan/q_a_s.html>、2026-10-14 に読んだもの）は、
「個別地点の震度や地震動の到達時刻の予想を行い、その結果を即時的に利用者に提供する」ことを予報業務としている。
予測計測震度は観測点を選ぶのに使うだけで、予想した震度の値は画面に出さない。だから当たらないと読んでいる。
緊急地震速報の最中に選んだ観測点の印を出すこと・P 波 S 波の線を引くことが同じ読みで済むかは、§12 で確かめる。
自前で解いている計算の全件は [`forecast-computation-audit.md`](forecast-computation-audit.md) が持つので、実装したら観測点の選び方をそこへ足す。

## 1. 何をして、何をしないか

**する**

- 揺れ検知か緊急地震速報が起きたら、有感範囲の公開観測点の波形を地図の下へ流す（§5）
- 有感の地震カードを開いたら、有感範囲の公開観測点の、その地震の区間の波形を出す（§6）
- 波形を出している公開観測点を地図に印で示す（§7）

**しない**

- 自作地震計の観測点を地図に描かない（§0）

公開観測点の波形から計測震度は出せない（§3.3）。ほかに決まっていないことは §12。

## 3. 実測で分かったこと

すべて 2026-10-14 の実測。測った道具はリポジトリに入れていないので、§3.4 は手順と判定を再現できる粒度で書く。
実装の段で、確かめ直す道具を `scripts/` に置く（§11）。

### 3.1 観測点

- リングに流れている `JP` 網は 20 点: JCJ JEM JEW JGF JHJ2 JHS JKA JMM JMN JMZ JNU JOW JSD JSG JSU JTM JTU JWT JYT YOJ
- 観測点情報（`fdsnws/station`）には `JMJ2`（宮古島）もあるが、リングの流れの一覧には無かった
- 20 点すべて STS-2。成分は `BHE`・`BHN`・`BHZ` だけで、20 Hz（50 ms 刻み）。感度は 1.0×10⁹ カウント/(m/s)（8 Hz で）
- 観測点名は英字の地名（例: `JMN` は「Kochi Monobe」、`JEM` は「Erimo」）。日本語の名前は持っていない（§12）

### 3.2 リング（SeedLink）

- **動いた命令の列**: 観測点ごとに `STATION <観測点> JP` と `TIME <年>,<月>,<日>,<時>,<分>,<秒>`（UTC・始めだけ）を送り、最後に `END`。命令ごとに `OK` が返り、その後は `SL` ＋ 6 文字の連番 ＋ 512 バイトのレコードが続けて届く
- **`SELECT ??BH?.D` を付けると `OK` が返るのにレコードが 1 件も来ない**（TCP の 18000 番でも WebSocket でも同じ）。外すと届く。`JP` 網は `BH?` しか持たないので、絞る必要がそもそも無い
- **1 本の接続で複数の観測点を受けられる**。JMN・JOW・YOJ の 3 点を 1 本で受け、9 成分すべてにレコードが届いた
- 始めの時刻を数分前にすると、その分がまとめて 1.5 秒ほどで届き、以後は届いたそばから流れる
- **静かなとき、1 レコードは約 21 秒ぶん**。成分ごとに約 21 秒おきに届き（成分の間で数秒ずれる）、最後のサンプルから受け取るまで 4〜5 秒。**いちばん新しいサンプルが画面に出るまで、最大で約 26 秒遅れる**。揺れている間（圧縮が効かずレコードが短くなるはず）の間隔は測っていない
- 量: 3 点を「2 分前から」60 秒受けて 35 KB（3 分ぶん。9 成分 × 180 秒 ÷ 21 秒 ≒ 77 レコードと合う）。**静かなとき 20 点を受け続けると、1 分あたり約 90 KB・1 日で約 130 MB**（60 成分 × 60 秒 ÷ 21 秒 × 520 バイトの換算。揺れている間はこれより増える）
- 流れの一覧（`/streams`）の最古の時刻から、リングが抱えているのは約 1 時間 40 分ぶん
- **存在しない観測点を `STATION` で指定したときの応え**（`ERROR` が返るか・他の観測点に響くか）は測っていない

### 3.3 波形の大きさ

- 2026-10-13 20:44 の紀伊水道 M3.8 を JMN（約 75 km）で描いた。P 波 20:44:29.3（日本時間）、S−P は約 10 秒、最大は約 257 μm/s
- 揺れの前の雑音は、加速度に直して 0.0001 gal 程度。自作地震計より 100 倍以上静か
- 速度計なので、計測震度（加速度に気象庁のフィルタを掛けて求める）は出せない
- 生のカウントには一定のずれ（直流分）が乗る。描くときは中心を引く必要がある（§5.4）

### 3.4 有感範囲のしきい値

- **抜き出し**: 2025-01-01〜2026-10-12 の長期震源カタログ（`public/data/hypocenter/2025.json`・`2026.json`）の地震と、リングの 20 点の組を全部作り（約 23 万組）、
  予測計測震度を −2.5 から 0.5 刻みの 10 帯に分けた。帯ごとに 50 組を、乱数の種 20261014 の貯水池抜き出しで選んだ（計 500 組）
- **取得**: 組ごとに、保存庫から発生の 60 秒前〜S 波の 60 秒後（S 波は JMA2001 走時表）の `BH?` を、1 秒おきに直列で取った（失敗 0・データ無し 0）
- **判定**: P 波の 2 秒前〜S 波の 30 秒後の最大振幅（中心を引いた値）が、発生の 60 秒前〜5 秒前の雑音の RMS の 10 倍以上なら「映った」（3 成分のどれか）
- **観測点の仕分け**（予測 1.5 以上の組で、映った割合が 2 割に届かない点を「記録していない」とした。組の少ない点は、500 組全体での割合も添える）:
  - **地震を記録していない 7 点**: JEW 0/7・JHS 0/3・JMM 1/7・JNU 1/6・JYT 1/10、JWT 0/1（組は 1 つだけだが、全体でも 0/11）、JSG は全部 0（振幅が 0 のまま）。リングも保存庫もデータは普通に返す。雑音の大きさでは見分けられない（JEM は雑音 1 カウントでも 9/9 映る）
  - **生きている 9 点**: JCJ JEM JGF JHJ2 JMN JOW JSU JTM YOJ
  - **判断できない 4 点**: JKA・JSD（予測 1.0 以上の組は全部映ったが、1.5 以上の組が足りない）、JMZ・JTU（予測の大きい組が無い）
- **しきい値の帯**（生きている 9 点・生の波形。しきい値は 1.5 未満の帯だけで引き、仕分けに使った組と重ねていない）:

  | 予測計測震度 | 映った割合 |
  |---|---|
  | −2.5〜−1.5（2 帯） | 0/37 |
  | −1.5〜0.0（3 帯） | 帯ごとに 15〜24% |
  | 0.0〜0.5 | 50% |
  | 0.5〜1.0 | 87% |
  | 1.0〜1.5 | 96% |

  帯あたり 20〜30 組（生きている 9 点に当たった組だけ）なので ±10〜20% ぶれる
- 長期震源カタログ（確定した震源）で測った値で、**緊急地震速報の初報の震源（規模・深さが大きくずれうる）では測っていない**
- M3 未満の地震は、`predictMeasuredIntensity` が規模を 3.0 へ切り上げるので、予測が大きく出る（予測 0.5〜1.0 でも映るのは 33〜40%）。§12

### 3.5 保存庫

- 直近 15 分を問い合わせたら、最後のサンプルは問い合わせの 8〜19 秒前だった（成分ごとに違う）。**保存庫にも、リングとほぼ同じ遅れで入る**
- 裏を返すと、**揺れの最中や直後に問い合わせると、後ろが入っていない応えが返る**（§6.2）

## 4. どの観測点を出すか

### 4.1 震源があるとき

**予測計測震度が −1.5 以上の公開観測点を全部出す**（§0）。予測は震源（緯度・経度・深さ）と規模から
`predictMeasuredIntensity` で求める。

- **自作地震計の地震カードの判定（`utils/seismoQuakeReach.ts`）と共通なのは、予測の式だけ。** あちらは「普段の計測震度 − 0.5」を下限にし、
  震源の要素が欠けると「近所の震度」で補う。公開観測点はしきい値を −1.5 に固定し、補い先も持たない
- 選ぶ材料は、下部の波形なら発表中の緊急地震速報、地震カードならそのカードの震源
- 2025〜2026 の震源カタログで数えると、1 地震で最多 19 点。7 日あたりの中央値で、有感範囲に 1 点以上入る地震は 427 件、地震と観測点の組は 1,012 組。巨大な地震なら 20 点すべてが入りうる
- **地震を記録していない観測点も外さない**（§0・§3.4）
- **震源の要素が欠けるとき**（緊急地震速報の仮定震源要素・深さ不明・規模不明）にどう選ぶかは決まっていない（§12）

### 4.2 揺れ検知だけのとき

震源がまだ無いときは、**検知点から仮に選び、震源が届いたら §4.1 で選び直す**（§0）。
仮の選び方の中身は決まっていない（§12）。

### 4.3 番号の振り方

地図の印と波形の見出しに同じ番号を付ける（§0）。振り方は決まっていない（§12）。

## 5. 下部の波形

### 5.1 いつ出すか

構想は「揺れ検知やEEWが起こったら」（§0）。いまの自作地震計の下部の波形は、ホーム地点の周りで震度1以上のとき出し、
外れてから 60 秒は出したまま（`utils/seismoWaveTrigger.ts`・`hooks/useSeismoWaveVisibility.ts`）。
公開観測点は「有感範囲に公開観測点が 1 点でもある揺れ検知・緊急地震速報」で出す形になる。
設定（`seismoWave` の `off`・`auto`・`always`）との関係は決まっていない（§12）。

### 5.2 受け方

SeedLink の 1 本の接続に、選んだ観測点を全部載せられる（§3.2）。いつ繋ぎ、いつ切るか、`TIME` をどこまで遡るかは決まっていない（§12）。
どの形にしても、次は守る。

- **同時接続は IP ごとに 5 本**（§2）。同じ端末の複数のタブ・同じ回線の端末がそれぞれ繋ぐと超えうる。超えて断られたときに、それと分かる形で止まること
- 繋ぎ直しの待ちは倍々で伸ばし、**ゆらぎを足す**。EarthScope が止まったとき、全端末が同じ時刻に繋ぎ直さないようにする
- `TIME` で遡る長さは要る分だけにする。大きな地震では全端末が同時に遡って取るので、その分がそのまま配信元の負荷になる
- 選び直し（§4.2 → §4.1、緊急地震速報の続報）で観測点が変わる。`END` の後から観測点を足せるかは測っていない。足せなければ繋ぎ直しになり、
  その間は一時的に 2 本を使い、`TIME` で遡った分が重なって届く。扱いは §12（選び直しで外れた観測点を出し続けるかも §12）

### 5.3 「まだ届いていない」と「欠けている」

公開観測点は、届く単位が約 21 秒と粗い（§3.2）。自作地震計の「5 秒届かなければ途絶」（`WAVE_STALE_MS`）を当てると、正常なのに途絶と出る。

- **まだ届いていない**: 最後に届いたサンプルより右。何も描かず、何も書かない（§0）
- **欠けている**: 届いたサンプルどうしの間の穴。自作地震計と同じく `NaN` で持ち、線を切る
- **途絶**: 届く間隔（約 21 秒）と遅れ（数秒）を足した時間を過ぎても届かなければ薄くする。長さは揺れている間の間隔を測ってから決める（§12）
- 窓の右端と `TIME` は端末の時計ではなく `serverNow()` で測る。サンプルの時刻は miniSEED が持つ UTC
- 途絶は、自作地震計と同じく受け取ってからの経過（`useSeismoStation.ts` の `waveStale` は `performance.now()` で測る）で判定し、右端の時計とは切り離す。右端とサンプルの時刻の差で測ると、時計のずれがそのまま偽の途絶になる

### 5.4 描き方

- 縦軸は速度（μm/s）。生のカウントを感度（1.0×10⁹ カウント/(m/s)）で割り、直流分を引いてから描く
- 合成（3 成分のベクトルの大きさ）と展開の形は、自作地震計の枠と揃える
- いまの部品は自作地震計の加速度（gal）と 0.3 秒ごとの到着を前提にした箇所を持つ。読んだ範囲（網羅ではない）では、型の名前（`gal`）・縦の範囲の文字列・静かさの下限（`utils/seismoQuietScale.ts`）・合成の裏付けの本数（`memberCount`。1 本以下の区間を薄く塗るので、1 台の公開観測点はそのままだと全面が塗られる）・描き直しと継ぎ足しの間隔（300 ms）。実装の段で、観測点の種類ごとに持たせる
- 静かさの下限は、自作地震計と同じく測った静かさの倍率で決める。公開観測点の雑音は自作地震計より桁違いに小さいので、値は測り直す
- 刻み（50 ms）は、入れ物も列の作り方も `msPerSample` を読むので通るとみている（推測）
- **右端は時計の「いま」（`serverNow()`）で進め、少しずつずらして描く**（§0。描き直しの頻度は §12）。いまの自作地震計は右端を「最後に届いたサンプル」に固定し、0.3 秒ごとにしか描かない（`components/SeismoWaveChart/index.tsx` の `MIN_REDRAW_MS`）ので、届くたびに 0.3 秒ぶん跳ぶ。公開観測点も同じ仕組みに載せる（届く単位が約 21 秒なので、右端の空白は §5.3 のとおり何も描かない）
  - **描き方**: データの読み出し（`readWave()` は 1 回で 96 KB を確保する）と列の組み立ては今の 0.3 秒ごとに留める。いまの列は窓の左端から割り付けている（`waveColumns.ts`）ので、右端が動くたびに組み直すとサンプルが隣の列へ移り、細いピークがフレームごとに明滅する。列の境目を時刻の格子（列の幅の倍数）に固定して組み、その間のフレームは組んだ絵を時刻の差だけ平行移動する。左端に 1 列余分に組んでおく。いちばん新しい列の高さは、組み直す 0.3 秒ごとにしか変わらない。平均の線・P/S 線・目盛りも同じ量で動かす
  - **起きること**: 自作地震計でも、まだ届いていない分が右端に空白として出たり消えたりする。§0 の説明は「0.3 秒ほど」だが、実際には基板からホストを経て端末へ届くまでの遅れと、下の時計のずれの分だけ大きくなりうる（測っていない）
  - **実装の前に測るもの**: サンプルの時刻は、自作地震計では基板の時計（`data-sources-spec.md` §4.5）、公開観測点では miniSEED の UTC で、右端の `serverNow()` とは別の時計。基板の時計が進んでいれば最新の分が右端の外へ落ち、遅れていれば空白が広がる（推測。ずれの大きさは測っていない）。測るのは「サンプルの時刻」と「端末の `serverNow()`」の差。ホストの `/status` の `boardClocks.offsetMs` は基板とホストの時計の差なので、それだけでは足りない（ホストの時計と `serverNow()` の差は含まれない）。端末で、届いたサンプルの最後の時刻と受け取った時点の `serverNow()` の差を測れば、時計のずれと届くまでの遅れを合わせた量が出る。公開観測点も同じ測り方で測る。扱いは §12
  - **変えないもの**: 静かさの測定（`index.tsx` の `QuietLevelMemory`）は今どおり最後のサンプルを基準にする。途絶は §5.3 のとおり受け取ってからの経過で測る。再生中は今どおり下部の波形を出さない（`App.tsx` で `seismoWave` を `'off'` にしている）ので、右端を進める相手が無い
  - **P/S 線**: 右端（いま）より先の時刻は描かない。いまの根拠は「右端＝最後に届いたサンプル」（`liveLanes.ts` の `liveArrivalMarks`）なので、そこを右端の新しい定義に合わせて直す（§5.5・§10）
- 横の幅・観測点が多い（最多 20 点）ときの並べ方は決まっていない（§12）
- 地震を記録していない観測点（§3.4）の平らな線は、「揺れなかった」の証拠にならない。そう読まれない見せ方をするかは §12

### 5.5 P 波・S 波の線

引くなら、自作地震計と同じく緊急地震速報から JMA2001 走時表（`utils/travelTime.ts`）で引く。
自作地震計の下部の波形では、到達予想キーの有無を問わず引いている（`forecast-computation-audit.md` の 11）。公開観測点で引くかは決まっていない（§12）。

## 6. 地震カードの波形

### 6.1 いつ取るか

自作地震計の地震カードは、**描くのは開いたカードだけ**（`EarthquakeCard.tsx` の `isSelected` の中）だが、
**取りに行くのは対象の地震すべてを先に**（`hooks/useSeismoQuakeWaves.ts`。LAN 内のホストへ 1 件 140 ms ほど・7 日で十数件）。

公開観測点を同じく先に取ると、「7 日ぶんのカードの数 × 1 地震あたりの観測点の数」を、端末ごとに起動のたびに保存庫へ投げることになる。
カードの数は数えていない（地震情報の電文が届いた地震だけなので、§4.1 の震源カタログの 427 件よりずっと少ない）。
1 地震あたりの観測点は、震源カタログの中央値で約 2.4 点（1,012 組 ÷ 427 件）、多くて 19 点。
**取りに行く時機を自作地震計と同じにするかは、カードの数を数えてから決める**（§11・§12）。
範囲は自作地震計と同じ発生の 30 秒前〜4 分後（`services/seismoWaveHistory.ts` の `WAVE_HISTORY_LEAD_MS`・`WAVE_HISTORY_TAIL_MS`。次の地震の発生で切る）。
遠い観測点では、S 波が 4 分の内に届かないことがある。範囲を観測点ごとに走時で伸ばすかは §12。

### 6.2 まだ入りきっていない分

保存庫には 8〜19 秒遅れで入る（§3.5）。発生から 4 分と少し経つまでは、範囲の後ろが入っていない。

- **範囲の終わりが「いま」より十分前のものだけを、取り終えたものとして控える。** それより新しいものは仮の控えにして、後で取り直す（回数と間隔に上限を置く）
- 保存庫の「データが無い」（204・404）も、範囲が十分古いときだけ確かなものとして扱う
- **保存庫を繰り返し問い合わせて伸ばすのは利用条件に触れる**（§2）。揺れている最中のカードを伸ばすなら、SeedLink で受けている分から継ぎ足す。どうするかは §12

### 6.3 枠

自作地震計の枠（`QuakeSeismoWave.tsx`）を流用し、見出しに番号と観測点名を出す（§0）。
自作地震計の波形と同じカードに並べる順番は決まっていない（§12）。

## 7. 地図の印

- **波形を出している公開観測点の位置に印を置き、番号だけのラベルを付ける**（§0）
- **波形を押すと、地図がその観測点へ寄って強調する**（§0）。寄せる仕組みは、一覧の行を押したときに使っている `FocusTargetGL`（`components/Map/CameraFollowsGL.tsx`）と `App.tsx` の `focusMapTarget` を通す
- 印は少数（多くて 20 点）なので、津波の到達確認の印（`components/Map/TsunamiArrivalMarkersGL.tsx`）と同じ HTML マーカーの方式で足りるとみている（推測）。レイヤーにするなら `MAP_LAYER_ORDER`（`components/Map/gl/layerOrder.ts`）へ登録する
- 印を出す場面・見た目・強調の仕方・共有カードの画像に写すかは決まっていない（§12）
- 自作地震計の観測点には印を出さない（§0）。自宅の位置が地図にも共有カードの画像にも出ないようにするため

## 8. 失敗の扱い

自作地震計の押し出し（`services/seismoStream.ts`）の作法に揃え、§5.2 の守ることを足す。

- 何か届けば見張りを張り直し、黙ったら自分から切って繋ぎ直す。黙りの長さは届く間隔に合わせて自作地震計（45 秒）より長くする（§5.3 と一緒に決める）
- 読めないレコードは捨てて数え、記録へ残す（間引く）
- 保存庫の取得は `fetchWithTimeout`（`utils/fetchWithTimeout.ts`）を通す（[`data-sources-spec.md`](spec/data-sources-spec.md) §1「応答が返らない取得には上限を置く」）。止めた取得は失敗に数えない
- 保存庫の取り直しは、失敗が続くほど間隔を空け、回数に上限を置く。1 件ずつ直列に、間を空けて取る
- 「データが無い」と「取れなかった」を分けて持つ。前者の扱いは §6.2

## 9. 通信量の見積もり

| 経路 | 量 | 頻度 |
|---|---|---|
| SeedLink（下部の波形） | 接続 1 本。静かなとき 20 点で 1 分あたり約 90 KB（揺れている間は増える）＋ `TIME` で遡った分 | 繋いでいる間（いつ繋ぐかは §12） |
| 保存庫（地震カード） | 1 地震で中央値約 2.4 件・多くて 20 件（1 件数十 KB）＋ §6.2 の取り直し | 取りに行く時機による（§12）。7 日ぶんのカードの数は数えていない（§11） |
| 観測点情報 | 20 点の座標・名前をアプリに持たせるなら 0 件（案。§12） | — |

複数のタブ・複数の端末が同じ IP から繋ぐと、上の量がその数だけ増える（§2）。

## 11. 確かめ方

- 受け方: **ブラウザから SeedLink の WebSocket に繋がるか**（`Origin` を付けた接続を断られないか）を最初に確かめる。断られるなら中継が要る（§12）。
  あわせて、20 点を 1 本で受けて全成分が届くこと・揺れている間の届く間隔・存在しない観測点を指定したときの応え・`END` の後に観測点を足せるかを測る。測る道具は `scripts/` に置く
- カードの数: 7 日ぶんの地震カード（地震情報の電文が届いた地震）の数を、両方の版で数える。§6.1 の時機を決める材料にする
- しきい値: §3.4 の手順を `scripts/` の道具で再現できるようにする（抜き出しの種・判定の式は §3.4 のとおり）
- 選び方: 長期震源カタログの地震で、選ばれる観測点の数を数える（§4.1 の数え方）。M3 未満の切り上げをどう扱うかでも数が変わる
- 画面: 地震カードは、保存庫から取った過去の地震で確かめる。下部の波形は、ライブで揺れ検知を待つか、§12 の再生中の扱いが決まればそちらで確かめる

## 12. 決まっていないこと

「案」は書き手の提案で、決まったものではない。

| 項目 | 案 |
|---|---|
| `predictMeasuredIntensity` が M3 未満を M3 に切り上げている件 | 別に諮る。直すと自作地震計の地震カードの選び方も変わる |
| 震源の要素が欠けるとき（仮定震源要素・深さ不明・規模不明）の選び方（§4.1） | 原則に合わせて出す側へ倒す。揺れ検知があれば §4.2 の仮の選び方へ落とし、それも無ければ震央の近くから選ぶ |
| 緊急地震速報の初報で、しきい値 −1.5 の余裕が足りるか（§3.4） | 続報のたびに選び直し、増えた観測点は足し、減った観測点は出し続ける（§5.2） |
| 揺れ検知だけのときの仮の選び方（§4.2） | 確定した検知点のいちばん強い点を仮の震央にし、その点の震度と同じ予測になる規模を逆算して §4.1 を当てる。または検知点から一定の距離。逆算を採るなら、自前の予測計算として予報業務の読みと `forecast-computation-audit.md` の対象に含める |
| 下部の波形の位置づけ | いちばん新しいサンプルが最大約 26 秒遅れる（§3.2）ので、主要動が届くより後に出ることが普通にある。速報ではなく「いま届いた揺れの確かめ」として扱う |
| 番号の振り方（§4.3） | 震央に近い順。選び直しで番号が変わらないよう、一度振った番号は保つ |
| 観測点の日本語名 | 20 点の表をアプリに持ち、英字の地名から日本語へ直す（例: 「Kochi Monobe」→ 高知県の物部）。直した根拠をどこに置くかも諮る |
| 下部の波形を出す設定（§5.1） | 自作地震計と同じ `seismoWave` に乗せ、`auto` で揺れ検知・緊急地震速報のとき出す。`always` でも公開観測点は常時繋がず、`auto` と同じに扱う（常時繋ぐと 1 日に約 130 MB） |
| SeedLink をいつ繋ぎ、どこまで遡るか（§5.2） | 出すと決まったときだけ繋ぎ、揺れ始めの 1 分前まで遡る。出さなくなったら切る |
| 選び直しで観測点が変わるとき（§5.2） | 繋ぐときは最初から 20 点全部を載せ、どれを描くかは画面の側で選ぶ。載せ直しの繋ぎ直しが要らず、20 点でも静かなとき 1 分約 90 KB で済む |
| 選び直しで有感範囲から外れた観測点 | 原則に合わせ、その揺れが終わるまで出し続ける。§0 の「有感範囲の中だけ」と食い違わないか、諮って決める |

| 右端の時計とサンプルの時計のずれ（§5.4） | §5.4 の測り方で、時計のずれと届くまでの遅れを合わせた量を測る。0.3 秒を大きく超えるなら、空白や最新の分の欠けが §0 で選んだ前提（0.3 秒ほどの空白）と違ってくるので、測った値を添えて右端の時刻を諮り直す。最新の分が右端より先に来たときに、端へ寄せて描くか・外へ落とすかもそこで決める |
