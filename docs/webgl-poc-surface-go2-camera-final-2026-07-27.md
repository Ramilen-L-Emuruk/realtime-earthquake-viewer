# 検証項目3 決着（Surface Go 2・2026-07-27 第3回）— MapLibre 優位。前回の判定を反転する

> 計測機: Surface Go 2（Windows・Edge 150・**vsync 16.7ms / 60Hz**・DPR 1.5・viewport 1272x768）
> 証跡: `surface-go2-camera-v2*` 34件 ／ `surface-go2-leaflet-camera-v2*` 34件（**計68件・新実装**）
> 前報: [webgl-poc-surface-go2-camera-leaflet-2026-07-27.md](webgl-poc-surface-go2-camera-leaflet-2026-07-27.md)（**本文書が結論を覆す**）
> 実装: `dc0658d`（両エンジンに着地コスト計測 `landingBlockMaxMs` を対称に導入）
>
> **結論: 検証項目3 は MapLibre 優位で決着。前回の「Leaflet が優る」は誤りだった。**
> - **着地コストが 5.2倍**（中央値 36.1ms 対 188.1ms）・**最大 574.7ms**
> - **longtask が 7/32 対 32/32**（Leaflet は全計測で発火）
> - **fps はほぼ同値**（52.25 対 51.67）——**fps は着地コストを捉えない**。前回の誤りの原因はここ
> - 副産物: **MapLibre にも着地コストは存在した**（仮定が否定された）／**前回の「2スイート目の悪化」は熱**

## 1. 最終結果（各32計測・`vsync-check` を除く）

| 指標 | MapLibre | Leaflet | |
|---|---|---|---|
| 飛行 `frame.p50` 中央 | 16.7ms | 16.7ms | 同じ |
| 飛行 `frame.p95` 中央 | 33.3ms（2F） | **16.9ms（1F）** | Leaflet 有利 |
| `fps` 中央 | 52.25 | 51.67 | **ほぼ同値** |
| **着地 `landingBlockMaxMs` 中央** | **51.7ms** | **188.7ms** | **MapLibre 3.6倍有利** |
| **着地 最大** | 226.6ms | **574.7ms** | **MapLibre 2.5倍有利** |
| **longtask 発火** | **7 / 32** | **32 / 32** | **Leaflet は全件で発火** |

### 交絡を除いた比較（飛行中が軽かった回のみ）

`frame.p95 < 20ms`＝**飛行中はほぼ1フレームで収まっていた**回に限れば、
区間内の最長ブロックは**飛行中のものではありえない**（飛行中なら `frame` に現れる）。
したがってこの条件下の `landingBlockMaxMs` は**着地由来と判定できる**。

| | n | 着地コスト 中央 | 範囲 |
|---|---|---|---|
| MapLibre | 10 | **36.1ms** | 23.2〜41.2 |
| **Leaflet** | 22 | **188.1ms** | **129.3〜574.7** |

**5.2倍（中央値）。最悪値では 14倍。**

## 2. なぜ前回は逆の結論になったか — `fps` は着地を捉えない

前回（第2回・旧実装）の判定材料は `fps`・`frame.p95`・`longtask` だった。そのすべてが
**飛行中しか見ていなかった**:

| | 前回の観測 | 実際に起きていたこと |
|---|---|---|
| `fps` 51.67 対 52.25 | 「ほぼ互角」 | **着地の停止はフレーム数に現れない** |
| `frame.p95` 16.9ms | 「Leaflet のほうが滑らか」 | **正しい。ただし飛行中だけ** |
| `longtask 0/32` | 「Leaflet は longtask を出さない」 | **観測窓が `moveend` で閉じていた** |

**Leaflet は飛行中 CSS transform で地図を引き伸ばし、実際の SVG 再描画を `moveend` まで遅延する**
（検証項目2 で確認済みの「動作中は静かで、離した瞬間に1回払う」性質）。
**その1回が 129〜575ms だった。**

前回の綴りで「物差しが揃っていない疑いがある」「`Leaflet が速いのではなく、飛行中は描かない戦略が
効いているだけ` かもしれない」と留保をつけ、`moveendMs` 相当の計測を求めた——**その留保が正しかった。**
測らずに確定させていれば、**逆の結論が計画書に残っていた。**

### 体感との対応

- **Leaflet**: 飛行中は滑らか（1フレーム）→ **着地で最大 0.57 秒停止**
- **MapLibre**: 飛行中やや粗い（2フレーム）→ 着地は 23〜41ms

**「半秒固まる」と「少し粗く飛ぶ」なら後者が優る。** かつ Leaflet は**全32計測で longtask を発火**しており、
停止が例外ではなく常態である。

## 3. 副産物

### ① MapLibre にも着地コストは存在した（仮定の否定）

`dc0658d` の導入時、MapLibre 側の `landingBlockMaxMs` は
「毎フレーム描画のため着地に偏らず **≈0 になる想定**」とされていた。

**実測は 23.2〜41.2ms（飛行中が軽い回）で、0 ではない。**
量は Leaflet の 1/5 で結論は変わらないが、**仮定は誤りだった**。

**仮定を検証可能な形に変えたからこそ判明した**（レビュー `b46f058` MEDIUM 2 の対応）。
「無いはずだから測らない」としていれば、気づかないままだった。

### ② 前回の「2スイート目の悪化」は熱だった

| | 1スイート目 | 2スイート目 |
|---|---|---|
| 第2回（冷却なし・連続実行） | fps 中央 48.3 | **42.5（悪化）** |
| **第3回（冷却あり）** | 51.7 | **54.8（改善）** |

**スイート間に冷却を挟んだら再現しなかった。** 「MapLibre 固有の劣化」ではなく機体の発熱である。

**運用知見**: 実機の連続計測は熱で歪む。スイート間に 1〜2 分の冷却を挟むこと。

### ③ longtask の観測窓を揃えた効果

第2回は Leaflet 側だけ `po.disconnect()` が settle 後にあり、
**MapLibre と観測窓が違っていた**（レビュー `b46f058` MEDIUM 1）。
第3回は両者を settle 後に揃えたため、**longtask が初めて公平に比較できた**——結果が 7/32 対 32/32。

## 5. 残る留保

**Leaflet PoC は本番より軽い。** 本番の `ActiveFaultsLayer.tsx` は可視線（SVG）に加えて
当たり判定用の透明 Canvas 線を持つが、PoC は省略している。
**この差は Leaflet を実際より良く見せる向き**であり、**本番の Leaflet はさらに悪い可能性がある。**
本件は MapLibre 優位の結論を強める方向のため、追加検証の実益は低い。
