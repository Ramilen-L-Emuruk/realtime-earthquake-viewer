# 地図描画仕様書

> 本書は**現在の実装が地図をどう描画するか**をまとめた仕様書。実コードと食い違う場合は実コードを正とする。
> 関連: [`architecture-spec.md`](architecture-spec.md) の全体構成、各情報の描画詳細は
> [`eew-spec.md`](eew-spec.md) / [`tsunami-spec.md`](tsunami-spec.md) / [`quake-spec.md`](quake-spec.md)。

## 1. 概要

MapLibre GL JS v6（WebGL 描画）で地図を表示する。全レイヤーが WebGL / DOM Marker のいずれかで実装され、
ラスタタイル画像は最小限（背景の海底地形のみ、オプショナル）。地図モードは 3 種類:

- `quake` — 地震情報タブで表示（観測点ドット・区域塗り・震源）
- `tsunami` — 津波情報タブで表示（海岸線・観測バー）
- `kyoshin` — リアルタイム震度タブで表示（強震モニタドット・EEW 予想塗り・予報円）

## 2. モード決定

`App.tsx` で `mapTab` から派生:

```ts
const mapMode = mapTab === 'tsunami' ? 'tsunami'
              : mapTab === 'realtime' ? 'kyoshin'
              : 'quake'
```

`JapanMapGL` は `mode` prop を受け取り、各レイヤーコンポーネントに visible prop を配る。

**EEW 予想レイヤーの kyoshin モード限定**: `eew-region-fill` / `eew-lpgm-region-fill` は kyoshin モードでのみ
描画される。担保は `JapanMapGL` の JSX の `visible={mode === 'kyoshin' && ...}` で行う（フック側は
モード非依存で計算する設計）。地震情報タブでの実測と予想が同じ配色で見分けにくくなる問題を避けるため。

**EEW 震源×印は全モード表示**: 発報中の震源位置だけは常に地図に載る（kyoshin 以外では半透明 0.4 で薄く）。

## 3. レイヤー順（描画順の単一情報源）

`src/components/Map/gl/layerOrder.ts` の `MAP_LAYER_ORDER` 配列が単一情報源。背面 → 前面の順。

各レイヤーコンポーネントは `addOrderedLayer(map, layer)` で追加する。この関数は `MAP_LAYER_ORDER` で
自分より前面に来るべき id の直前に挿入するため、データ到着タイミングに依存せず順序が保証される。

配列に無い id は最上段に積まれる（警告なし）。新レイヤーを足すときは配列への登録を忘れないこと。

**カスタムレイヤーの注意**: MapLibre の `type: 'custom'` レイヤー（現状 `kyoshin-subthreshold`・`pswave`）は
`getStyle().layers` に現れない。順序確認は `map.style._order` を見る。

## 4. ベースマップ

`BaseMapGL` が担当。以下を描画:

- 陸地塗り
- 都道府県境界（`prefectures.json`）
- 一次細分区域境界（`subregions.json`）
- 海底地形（GEBCO ラスタタイル・任意・下記の 2 層構成）

陸地・境界はタイル取得が不要で、全て事前生成された GeoJSON から自前描画する。海底地形タイルは唯一の
外部ラスタで、設定で ON/OFF 切替可能（切替は 2 層に同時に効く）。

陸地塗り・県境・区域境界線と、区域名ポップアップの当たり判定（透明な塗り）は**同じ GeoJSON ソースを
共有**し、レイヤー側は `kind` の filter で自分の分だけを描く（理由は §9「静的な形はソースを共有する」。
取得に失敗したときの振る舞いは下記）。

**海底地形の 2 層構成**: 遠距離の自動フィット（カメラが自動で視野を移す処理・§6）の直後は、飛行先の
タイルがまだ手元に無く海底地形が描けない。ラスタが 1 層だけだとその間は素の背景色が露出して暗転して
見えるため、低ズーム固定の下地を常時敷いて必ず何かが描かれている状態を作る。

| 層 | レイヤー id | ソースの最大タイル z | 描画開始ズーム（レイヤーの `minzoom`） | 役割 |
|---|---|---|---|---|
| 下（下地・オーバービュー層） | `gebco-overview-raster` | `GEBCO_OVERVIEW_MAX_ZOOM` | なし（全ズーム） | 粗いが必ず存在する下地 |
| 上（高解像度） | `gebco-raster` | `GEBCO_SOURCE_MAX_ZOOM` | `GEBCO_HIRES_MIN_ZOOM` | 現在ズーム相当の精細な地形 |

MapLibre はソースの最大タイル z を超えるズームではそのタイルを拡大して描き続けるため、下層はどのズーム・
どの位置でも下地として残る。上層のタイルが届くとその上に載って差し替わる（上層は既定の 300ms
クロスフェードを維持。下層は常在の下地なのでフェードは不要＝`raster-fade-duration: 0`）。下層が使う
タイルは先読みの低ズーム側に含まれるため、起動後まもなく揃う。

上層の `minzoom`（`GEBCO_HIRES_MIN_ZOOM`。**マップズーム基準**の値で、同じ表の「最大タイル z」とは別の
座標系）未満のズームでは、2 層が同じタイルを要求するだけで見た目は変わらない。そこでは上層を描画対象から
外して二重取得を避ける（非表示のレイヤーはソースの更新対象にならないため、タイル取得ごと止まる）。

**対処できる範囲**: 距離・タイミングに起因する一時的なタイル未到達まで。GEBCO の配信元自体へ到達できない
場合は両層とも新しいタイルを描けないが、低ズームのタイルを一度でも取得済みなら MapLibre がそれを拡大して
穴を埋める（タイル取得を全て失敗させても素の背景は露出しないことを実測で確認）。起動直後から到達不能な
場合はその下地も無いため暗転する。

**ズームアウト時の非表示化**: 都道府県境界・一次細分区域境界（`BaseMapGL`）と活断層（`ActiveFaultsGL`）は、
**視野が広すぎるときは描画しない**（線を簡略化するのではなくレイヤーごと消す）。遠地地震のフィットの
ように世界規模まで引くと、これらの線が潰れて列島が塗り潰された塊になるため。陸地塗りとプレート境界は
対象外で、引いた画でも列島の位置は分かる。

判定は `gl/zoomLevels.ts` の `DETAIL_MAX_SPAN_KM`（4400km）で、**視野の短辺が何 km か**で決める
（日本全体の短辺 1443km の約 3 倍まで引いたら消す、という水準）。ズーム値ではなく視野の実距離を使う
理由は §6「寄り上限と閾値の単位」。日本全体表示は画面の短辺に関わらず視野 1600〜1850km に収まる
（`gl/zoomConstants.test.ts` の代表ペインでの実測範囲）ため、従来どおり描画される。

**生成データの取得に失敗したとき**: 該当するレイヤーを作らずに描画を続ける（`prefectures.json` なら
陸地塗りと県境、`subregions.json` なら区域境界線と区域名ポップアップの当たり判定）。`console` には
何が出なくなるかを含む警告を出す。**両方とも取得できなかったときは、共有ソース自体を作らない**
（レイヤーが 1 枚も乗らないため。この読み込みは地図の生成時に 1 度きりで、後から埋まることもない）。
震度表示側は区域データが無いと別のフォールバックを行う（[`quake-spec.md`](quake-spec.md) §7.2）。

応答もエラーも返らずハングした場合も、取得は時間切れで打ち切って上記と同じ失敗として扱う
（警告の文言に「timed out」が入る。タイムアウト値は [`data-sources-spec.md`](data-sources-spec.md) §6 参照）。
利用者に向けては、取得に失敗した件数を地図左上に出す（同 §6「取得状況の表示」）。

**地形先読み**: `src/utils/gebcoPrefetch.ts` が沖縄〜択捉相当の低ズームタイルをアイドル時に
バックグラウンド fetch する。GEBCO は 256px タイルのソースなので MapLibre が要求するタイル z は
マップズーム +1 になる（§6 のズーム基準とは別の座標系）。先読み範囲もタイル座標系で決めるため、
マップズーム基準の値をそのままタイル z として使わないこと（`desiredTileZoom` を通す）。同ファイルは
`GEBCO_HIRES_MIN_ZOOM`（マップズーム基準）も持つため、定数を触るときはどちらの座標系の値かを必ず
確認する。

先読みが基準にするのは**基準ペインでの寄り上限**（`REFERENCE_FIT_MAX_ZOOM`）で、実際の端末の寄り上限
ではない。寄り上限は画面が大きいほど深くなるため、大画面ではこの範囲より 1 段深いタイルを使う局面が
ある。そこを追って上限を上げると先読みのタイル数が 4 倍に増える一方、寄った画のタイルは飛行後に通常
取得され、その間も上記の下地層が暗転を防ぐ。費用に対して得るものが小さいため追わない。

## 5. ラベル描画（`LabelsGL`）

- 地方名・県名・区域名を symbol + icon-image で描画
- ズーム帯で表示粒度を切替（低ズームは地方名、高ズームは区域名）。**切替の境目はズーム値**（文字が
  何 px 間隔で並ぶかの問題なので。§6「寄り上限と閾値の単位」）
- 地方名を出し始める下限だけは**視野の実距離**で決める（`LABEL_MAX_SPAN_KM`。日本全体が画に収まって
  いるかどうかの問題なので）。ズーム値で固定していた間は、狭いペインの日本全体表示が閾値に届かず
  地名が一切出ない状態だった
- 文字サイズは「地図アイコン倍率」（[`settings-pwa-spec.md`](settings-pwa-spec.md) §2「主な項目の補足」）で震度バッジと揃えて拡縮する。
  下記の退避量も `text-offset` の em 指定（文字サイズに対する比）なので、文字とバッジの双方に
  同じ倍率が掛かる限り、倍率を変えても両者の間隔の比率は崩れない
  - この倍率が変えるのは見た目の大きさだけで、クリック・タップの当たり判定（`QuakeHeatmapGL` の
    `HIT_RADIUS_PX` など）には連動しない。押しやすさのための値であり、倍率に連れて広げると
    密集した地域で隣の対象を拾いやすくなるため
- 事前生成 **SDF グリフ**（M PLUS Rounded 1c ExtraBold・`public/fonts/`）を使用
  - **適用されるのは本節のラベルのみ**。震度バッジ等の数字は Canvas2D でラスタライズしたアイコン画像（`gl/intensityIcons.ts`・`gl/lpgmIcons.ts`・`gl/kyoshinDetectedIcons.ts`）で描いており、そちらは端末のシステムフォント（`sans-serif`）を使う
  - 暗い地図の上に小さく置く地名（倍率 100% で 13〜17px）を読ませるため、丸ゴシック（角を丸めた字形のゴシック体）の太いウェイトを採用している
  - **SDF**（Signed Distance Field / 符号付き距離場）: 文字の輪郭を「各ピクセルから輪郭までの符号付き距離」として保存する画像形式。拡大縮小してもエッジが滲まないため MapLibre GL の文字描画に採用されている
- グリフ生成スクリプト: `scripts/build-glyphs.mjs`（`@mapbox/tiny-sdf` で焼く）
  - 収録するのは地方名・県名・区域名・震度ラベル・ASCII に実際に現れる文字だけ。**地名を増減したら再生成が必要**
  - 再生成を忘れると、その文字が生成済みブロック（256 文字単位）内にあれば警告なしで空白になり、ブロックごと未生成なら警告付きで実行時生成にフォールバックして事前生成の目的（初回描画時のメインスレッド停止の回避）が失われる
  - この取りこぼしは目視でしか気づけないため、`npm run build` は前段で `node scripts/build-glyphs.mjs --check` を実行する。配信される `.pbf` を実際に読み、必要な文字が揃っていなければビルドを中断する
  - 検査するのは次の 3 点
    - **文字が収録されていること**
    - **その字形が空でないこと**（収録されていても中身が空なら画面上で空白になる。字形を持たない半角スペースだけは対象外）
    - **焼いたときの条件が今の設定と一致すること**（フォント実体のハッシュ・ファミリ・ウェイト・SDF パラメータを生成時に `build-info.json` へ記録して照合する。フォントを差し替えて焼き直しを忘れると、収録も字形も揃ったまま形だけ古くなるため）
  - `build-info.json` は生成物と一緒にコミットすること（`npm run build` は検証しか行わず、グリフを焼き直さない）。ビルド時の照合にのみ使うファイルで、PWA の precache 対象ではない
  - 生成した `.pbf` は PWA のオフラインキャッシュ対象（[`settings-pwa-spec.md`](settings-pwa-spec.md) §5）
- ズーム帯の切替や衝突による**出入りは即時**（フェードしない）。symbol の配置フェードを地図全体で
  切っているため（§8「symbol の配置フェード」）

### バッジとの重なりを避ける

震度バッジ・観測点ドット等のマーカーは、ラベルを避けて配置されない（震度系アイコンは
`icon-allow-overlap` / `icon-ignore-placement` で MapLibre の衝突判定に参加しないため）。そこで実際の
描画結果を `queryRenderedFeatures` で問い合わせ、**3 段で処理する**（`src/components/Map/gl/labelOverlap.ts`）。

1. **そのまま置けるならそのまま。** 平常時（マーカーが出ていないとき）はここで確定し、ラベルは代表点の真上にある
2. **重なったら上下へ逃がす。** 逃がせるのは領域（県・区域）の内側に収まる範囲まで。上下とも逃がせるなら余地の広い側を選ぶ
3. **逃がしても避けられなければ薄くする**（不透明度 0.35）。消しはしない——地理の手がかりを完全には失わせないため

**退避は重なったときだけ行う。** 以前は退避方向を生成データに焼いて常時ずらしていたが、退避が要るのは
マーカーが出ている間だけなので動的な判定へ寄せた（そのままでは文字が区域の端まで寄る問題があった。
実測値は §16 改訂履歴 2026-08-23）。

ラベルを置く代表点は、境界データが持つ `label`（**面積最大のリングの面積重心**。`scripts/lib/labelAnchor.mjs`）。
湾を抱えた形では重心が水面に落ちるが、そのままにしている——領域として見れば湾の上こそ中心で、無理に
陸地へ寄せると「その地域を指している」ようには見えなくなる。

逃がせる上限は生成データの `room`（代表点から北・南へ、領域の外に出るまでの距離）が決める。代表点が
領域の外に落ちる場合（上記の湾。区域 1 件・県 2 件）は `[0, 0]` で、退避せず薄くなる側へ倒れる。
地方名は境界データを持たないため同じく退避しない。

判定で 2 つ、間違えると静かに壊れる点がある。

- **代表点の判定では「自区域のバッジ」を除外しない。** 区域名ラベルと自区域の震度バッジは同じ代表点に
  置かれるので、ここで除外すると避けたい当の相手が判定から消え、退避そのものが発火しなくなる。除外を
  効かせるのは**退避したあとの位置の判定だけ**（逃がした先で縁が触れる分は許容する。ただし判定は名前の
  一致だけを見ており、重なりの大小は区別しない）
- **`room` は非負であることまで確かめる。** 負値が来ると符号が吸収され、余地が無いはずの方向を「余地が
  ある」と読む。座標（`lngLat`）は負を取りうるので、非負の要求は `room` 側にだけ置く。どちらも壊れた値を
  そのまま投影すると例外になり、**ラベル 1 件の破損が全ラベルの判定をセッション中ずっと止める**

判定結果は feature の `properties`（`shift` / `dimmed`）に書いて `setData` する。`feature-state` を
使わないのは、**layout プロパティである `text-offset` が `feature-state` 式を受け付けない**ため。

県名・区域名は境界データ（`prefectures.json` / `subregions.json`）に依存する。取得に失敗した場合は
そのラベルだけが出ず、他のズーム帯のラベルは影響を受けない。`console` の警告には対象のズーム帯を
含めている（「取得に失敗して出ない」のか「そのズーム帯では元々出さない設計」なのかを区別するため）。

## 6. カメラ制御（`CameraFollowsGL`）

以下のシチュエーションでカメラを自動フィットする:

- 地震カード選択時 → 該当地震の震源＋主要観測点を含む範囲
  - **遠地地震**（[`quake-spec.md`](quake-spec.md) §3）は国内で震度を観測せず対象が震源 1 点だけになるため、
    離島を含む日本全体の枠（`gl/bounds.ts` の `JAPAN_WIDE_BOUNDS`）を合成してフィットする
- 揺れ検知時（confirmed） → **地図に描かれている検知点**を含む範囲
  - 追うのは「いま描かれている点」だけ。検知イベントのメンバーは現在の震度で絞られていないため
    （[`kyoshin-detection-spec.md`](kyoshin-detection-spec.md) §8）、それを追うと大地震のあと画が
    全国に張り付いたまま戻らない。詳細は下記「揺れ検知追従の目標範囲」
  - 検知が終わると日本全体へ戻すが、候補クラスタ（確定検知に育っていない検知点群。下記「解除時」参照）が
    残っている場合は戻さず、候補側が寄り直す。候補が失効したときに日本全体へ戻す判断は
    `FitToCandidateGL` 側が持つ
- EEW 発報中 → 予報円・震源・揺れ検知点・予想の区域塗りを含む範囲（**kyoshin モード時のみ**。
  下記「既知の限界」参照）。目標範囲の決め方は次項
- 津波情報表示時 → 観測点の更新があればその観測点、無ければ対象海域（海岸線）を含む範囲。
  目標範囲と俯瞰への帰り方は下記「津波追従の目標範囲」

**着地ズームは 0.5 段階へ切り下げる**（`gl/camera.ts` の `snapZoomDown`）。上記すべての点群フィットに
共通で、目標にぴったり合わせず**わずかに引いて余白を残す**（日本全体への帰還は固定の枠なので対象外）。

- 収まりを見張る側（下記「成長フォロー」）と対になっている。ぴったり寄せると目標の縁が判定の余白の
  ちょうど上に着地するため、着地直後に「はみ出している」と読まれて 1 段引き直される。ユーザーには
  「寄りすぎた後にちょっと引く」二段の動きに見える（2026-08-21 に EEW 解除後の帰還で報告。実測では
  5°×4° の点群で余裕が 0px・判定は「はみ出している」、切り下げると 104px の余裕が残る）
- 寄り直しの発火判定（下記「収め直しフォロー」）が使う「寄り直して得られる段数」も同じ式を通す。
  片方だけ変えると、得られると計算した段数と実際の着地がずれる
- 旧 Leaflet 版の `zoomSnap=0.5` 相当のヒステリシスでもある。EEW 予報円のように毎秒育つ目標では、
  段階に乗せておかないと少しの成長で毎回はみ出して引き直しが頻発する

**揺れ検知追従の目標範囲**（実装は `FitToDetectionGL`）:

- 目標は「**いま地図に描かれている検知点**」の外接範囲（`JapanMapGL` の `detectedFitPoints`）。
  検知イベントのメンバー観測点は、値が下がりきってからも猶予のあいだ残る
  （[`kyoshin-detection-spec.md`](kyoshin-detection-spec.md) §8）。一方マーカーは現在の震度で絞られる
  （震度0未満・欠測を描かない／孤立した震度0を落とす）。この差をカメラが引き継ぐと、揺れが収まって
  地図上の点が減っても目標だけが全国に居座る
- 画からはみ出したら引く（**成長フォロー**）。ここでの「はみ出した」は、画面の縁から
  **フィットと同じ余白（60px）の内側**に入っていないこと。検知点はバッジで描くため、縁のちょうど上に
  ある点は丸が半分切れて読めない（`gl/camera.ts` の `mapContainsBounds` の余白引数）
  - 地図ペインが狭い端末では、この余白は**短辺の 2 割**まで切り詰める（短辺 300px 未満でこの上限が
    効き始める）。切り詰めずに 60px を取ると、短辺が 120px を割る状態では上下（または左右）の余白が
    ペインを食い尽くして判定用の範囲が反転し、常に「はみ出している」になって毎秒フィットが走る
- 収まっている場合でも、寄り直しに次のどちらかの価値があり、その状態が **8 秒**続いたら寄り直す
  （以下「ペイン」は地図自身の描画領域＝`map.getContainer()` を指す。アプリのレイアウトのパネル
  （[`architecture-spec.md`](architecture-spec.md) §4）とは別物）
  （**収め直しフォロー**。値は `CameraFollowsGL.tsx` の `REFIT_*`）
  - **1 段以上**ズームが深くなる（範囲が狭まった場合）
  - 中心が**ペイン短辺の 2 割以上**動く（範囲が別の場所へ移った場合）
  - **2 つ必要な理由**: ズームの利得だけでは、寄り上限（`fitMaxZoom`）の近くにいる間じゅう発火しない。
    現在ズームと着地ズームの双方がクランプに当たって利得が 1 段に届かないため（着地ズームは 0.5 刻みなので
    ズーム 6.5 以上では構造的に届かない）、揺れの位置が動いても画が固まる。2026-07-17 大隅半島東方沖
    M5.2 の再生で実測: ズーム 7 のままカメラが約 2 分動かず、目標中心のずれが 42px → 247px
    （ペイン短辺の 31%）まで育った。逆に中心のずれだけでは、目標がその場で縮んだ場合を拾えない
  - 判定に「画が目標の何倍ゆるいか」という**矩形の広さの比は使わない**。比で測ると padding（px 固定）と
    ビューポートのアスペクト比が効き、地図ペインが小さい端末では着地後も閾値を超えたままになって
    無駄な寄り直しを繰り返す。**ズームの利得と中心の移動量は、
    寄り直したあとは定義上どちらも 0 になる**ため、その往復が構造的に起きない
    （`gl/camera.ts` の `refitDeltaForBounds`）
  - 8 秒という保持時間は、余震・表面波の再来・欠測の出入りで範囲が数秒単位で上下するため。
    一瞬変わっただけで寄せるとカメラが落ち着かない。EEW 発報中・ユーザー操作中・自動フィットの
    飛行中はこの待ちを数え直す（持ち越すと、抑制が明けた瞬間に待ち時間ゼロでスナップする）
  - この待ちは観測点の値の更新（毎秒）で進む。取得が途絶えると待ちも止まり、寄り直しは起きない。
    その状況では観測点も検知カードも同じく凍結しているため、カメラだけ動かす意味がないと判断している。
    待ちに入ったことはログに残す（「待機中」と「更新が来ていない」を事後に区別するため）
  - 寄り直し先そのものを算出できない場合（地図のコンテナ寸法が取れない・座標が壊れている）は
    寄り直さない。このとき成長フォローも「収まっている」と判断して通り過ぎているため、どちらの
    フォローも動かなくなる。その状態に入ったこともログに残す（黙って止まると原因を追えないため）
  - 収め直しフォローを持つのは揺れ検知の追従だけ。EEW 発報中は下記の EEW 側が目標を持つ
    - **限界**: EEW の目標は基本的に広がる一方（S 波円は時間で育つ）だが、続報でマグニチュードが
      下方修正されたり予想区域が減れば縮みうる。その場合に画を狭め直す経路は無い（件数が減ったときの
      再フィットだけが例外的に収め直す）。発表が続く数十秒〜数分の話なので、解除後は揺れ検知側の
      追従が引き取る
- 「検知が続いているか」は描画フィルタを通さないメンバーの集合で判定する。描ける点が一時的に
  ゼロになっても検知終了とは扱わず、カメラを動かさない（日本全体へ戻すと、点が戻った瞬間に
  寄り直す往復になる）。**EEW 解除時の帰還も同じ扱い**——検知が続いていて描ける点だけが無い場面では
  帰還を見送り、EEW の画に留める（候補クラスタや日本全体へ落とすと、生きている検知を差し置いて画が飛ぶ）

**揺れフォーカス（強まった点へ一時的に寄る）**（実装は `FitToDetectionGL` の `shakeFocus`）:

揺れの強まり（レベルアップ・再エスカレーション）と別地点の検知で、その音が指している 1 点へ短く寄る。
**確定検知の開始は対象外**（同じ検知音が鳴るが、そこは検知点全体へのフィットが画を作る）。要求を出すのは `useKyoshinAlerts`
（[`kyoshin-detection-spec.md`](kyoshin-detection-spec.md) §8「発報ロジック」）で、**音を鳴らすのと同じ
判定で出す**——判定を別に組むと「音は鳴るのに画は動かない」経路が黙って生まれる。

- 寄り先は 1 点で、寄り上限（`fitMaxZoom`）まで寄る。その点が画の中心に来る
  - 揺れの強まり（レベルアップ・再エスカレーション）では、**そのレベルを担った観測点**
    （最大震度を記録した点。`ConfirmedShock.peak`）
  - 別地点の検知では、**その地域で最大震度を記録した観測点**（通知の「推定最大震度」と同じ点）
  - **確定イベントのメンバー重心（代表点）へ寄せてはならない。** 重心は地域単位の発報の照合に使う
    位置で、広域に広がったイベントでは最も強く揺れている点から大きく離れる。2024-01-01 16:08 能登の
    再生で実測: 石川〜千葉に 151 点が反応したイベントの重心は新潟県境付近で、震度4を記録した能登の
    観測点から約 140km 離れていた——画の中心には何も無く、音が指した点は隅に写る
- **担当は EEW の有無で入れ替わる。** EEW が出ていない間は `FitToDetectionGL`、発報中は
  `FitToEEWGL` が寄せる。発報中はカメラの持ち主があちらへ移る（検知追従が `hasEew` で止まる）ため、
  こちらが寄せても EEW の成長フォロー——予報円の再計算（100ms ごと）で評価される——が即座に
  引き戻してしまう。**消費済みの連番は共有し、担当しない側は消費もしない**（消費すると、その要求は
  どちらにも寄られないまま消える）
- 寄せた直後の **3 秒間**（`SHAKE_FOCUS_SUPPRESS_MS`）は上記の成長・収め直しフォローを止める。
  EEW 発報中は下記「発報中」の引き直しと件数減少の再フィットを同じ 3 秒だけ止める。
  - **「引き直しを止める期限」と「第一報に譲る期限」は別に持つ。** 揺れフォーカスが譲るかどうかを
    見るのは後者だけ——ひとつにまとめると、自分が直前に張った抑制を自分で読んで、3 秒以内に続く
    上昇（震度7へ達する瞬間はまさにここ）を落としてしまう。ログにも「第一報の直後」と出て原因を
    誤らせる
  止めないと、次の観測点の更新（毎秒）で「検知点全体が収まっていない」と判定され、寄せた画が 1 秒で
  引き戻される。下記 EEW 第一報の抑制（`GROWTH_FOLLOW_SUPPRESS_MS`）と同じ仕掛けだが、止める相手が
  違う（あちらは EEW 追従・こちらは検知追従）ため別の値として持つ
- **全体像へ戻す経路は別に持たない。** 抑制が明けたあと、観測点の更新で成長フォローが検知点全体へ
  引き直す
- **強まりが続く間は寄った画が続く。** レベルが上がるたびに要求が出るので抑制がそのつど延びる
  （同じ点なら画は動かず、より強い点へ移ったならそちらへ寄り直す）。最後の上昇から 3 秒で戻る
- 寄せない場面が 5 つある。**担当している側は、寄せなくても要求を消費する**——「その瞬間を見せたい」
  要求なので、遅れて寄る価値が無い。**消費し忘れると害が出る**: 要求が残ったまま次の検知が始まると、
  終わった揺れの点へカメラが飛ぶ（下記の鮮度 5 秒では、その間の再開を弾けない）。ただし
  **担当していない側は消費しない**（上記「担当は EEW の有無で入れ替わる」）
  - **新規 EEW の発報から 10 秒**（`SHAKE_FOCUS_YIELD_AFTER_EEW_MS`）。EEW は「これから来る」の報せで、まず
    震源と予報円を見せる意味がある。揺れの強まりは猶予明けの次の上昇で拾える。**猶予を過ぎれば
    発報中でも寄せる**（2024-01-01 能登本震の再生で確認: 16:10:16 の発報直後の上昇は譲り、
    16:10:30 の震度7へ達する上昇では寄った）
    - **下記「第一報」の抑制（3 秒）とは別の値。** あちらは「第一報の画を保たせる」ためにカメラの
      引き直しを止めるもので、こちらは「発報直後は EEW の画を優先する」という取り決め。同じ値を
      共有していた頃は、引き直しの都合を変えると猶予まで一緒に動いた
    - 猶予は**どの EEW の発報でも**張る。直前に別の EEW が発報していたなら、その分も譲る
  - **ユーザーが地図を操作している間**。震度の上昇は警報の第一報ではないので、EEW のように操作の
    保持を解除してまで画を奪わない
  - **要求が古いとき**（5 秒。`SHAKE_FOCUS_WINDOW_MS`）。揺れ検知はタブ移動も同時に要求するが、
    EEW・津波の保持で realtime へ移れないことがある。その要求が残ったまま後から手動で入室すると、
    もう収まった揺れの点へ寄ってしまう
  - **検知が終わっているとき**（要求と検知終了が同じコミットで届いた場合）。日本全体へ帰る側が勝つ
  - **描ける点が無いとき**（検知は続いている状態。上記「揺れ検知追従の目標範囲」の末尾）。寄り先は
    代表点なので描画に依らず飛べるが、何も無い場所へ寄っても見せるものが無い
- **タブ入室（`FitToDetectionGL` の初回マウント）時点で、鮮度の窓（上記「要求が古いとき」）内の
  未消費の要求が残っていたら、検知点全体へのフィットを経由せず直接その点へ寄る。** 別タブにいる間に
  震度が上がると（`useKyoshinAlerts` のレベルアップ処理はタブ切替要求と揺れフォーカス要求を同時に
  出す）、タブが realtime へ切り替わる時点で既に要求が立っていることがある。要求が無い、または
  鮮度の窓を過ぎていれば、これまで通り検知点全体へのフィットになる——見送りはその場で記録し、次の
  観測点更新まで持ち越さない
- 通知音の設定（オフ）に関わらず寄る。自動タブ切替と同じ扱いで、音の有無とは独立させている
- 同じフレームで「揺れの強まり」と「別地点の検知」が重なったら**別地点が勝つ**（要求を出す側の
  取り決め。[`kyoshin-detection-spec.md`](kyoshin-detection-spec.md) §8「発報ロジック」）
- 同じフレームで新規 EEW と重なったら**第一報が勝つ**（受け取る側の取り決め。`FitToEEWGL` の中で
  第一報の effect を先に置き、こちらはその抑制を見て譲る）
- 要求は単調増加の連番で運ぶ（座標の等値では「同じ場所でさらに強まった」を表せない）。消費済みの
  連番を覚えるのは `JapanMapGL`——この追従はリアルタイム震度モードのときだけマウントされるため、
  内部で覚えるとタブを離れるたびに記録が消え、直前に見せた要求を未消費と読んで同じ点へ寄り直す
  （EEW の初出時刻・地震カードの選択回数を親が控えているのと同じ理由）

**EEW 追従の目標範囲**（他より複雑なため独立して記す。実装は `FitToEEWGL`）:

- **第一報**（その EEW を**震源の位置が判る形で**初めて見てから 10 秒以内に追従が始まったとき。
  `NEW_EEW_FOCUS_WINDOW_MS`）
  → その EEW 自身の S 波円（円が無ければ震源 1 点）へ寄る。予想の区域塗りは含めない——
  警報級では予想区域が広く、含めると第一報から引きの画になって震源近傍が見えなくなる
  - この寄りを見せた直後の **3 秒間**（`CameraFollowsGL.tsx` の `GROWTH_FOLLOW_SUPPRESS_MS`）は、
    下記「発報中」の**引き直しだけ**を止める。揺れフォーカスが譲る猶予はこれとは別に持つ
    （`SHAKE_FOCUS_YIELD_AFTER_EEW_MS` = 10 秒。上記「揺れフォーカス」）。すでに揺れ検知が広範囲に出ている状況では、寄った直後に
    検知点が更新されて即座に引き直され、「一瞬寄って即ズームアウト」というちらつきになるため。
    **この間は予想の区域塗りが画面外にあっても引かない。** 抑制が明けると、予報円の再計算（100ms ごと）
    をきっかけに次の判定が走って追いつく（解除を待つタイマーは無い）
- **発報中の EEW のところへ入室した**（タブを往復した・発報から間を置いてリアルタイム震度タブを
  開いた）→ 下記「発報中」と同じ範囲へ 1 回だけ寄せる。第一報のような震源近傍の寄りは見せない——
  そのころには予想の区域塗りや揺れ検知が育っており、いま起きていること全体が入る画のほうが役に立つ
  - 第一報かどうかは**その EEW を初めて見てからの経過時間**で判断する。数え始めるのは震源の位置が
    判ってから——位置不明のまま届いた報（標準版では起こりうる）から数えると、寄れるようになった
    時点で既に 10 秒を過ぎていて、第一報の寄りを見せられなくなる
  - 追従が始まったかどうか（マウントされたかどうか）では判別できない。この追従はリアルタイム
    震度モードのときだけ動くため、タブを往復するたびに「初めて見る EEW」に見えてしまう。初めて
    見た時刻は、全モードで生きている `JapanMapGL` が控える
  - 目標が「発報中」と同一なので、寄せた直後に引き直されることはない。第一報の 3 秒の抑制も掛けない
  - 発報が終わった EEW の記録は落とす。同じ EEW が再び現れたら（テスト時刻設定で同じ日時を
    再生し直した場合など）、あらためて第一報として扱う
  - **限界**: 10 秒は、自動タブ切替が読み上げの待ち合わせで数秒ずれることを見込んだ値。それを超えて
    タブ移動が遅れた新規 EEW は入室として扱われ、震源近傍の寄りを見せずに合成範囲から始まる
  - ユーザーが地図を操作している間は寄せない（操作の保持が明けたら寄せ直す）
- **発報中** → 「S 波円 ∪ 震源 ∪ 揺れ検知点 ∪ 予想の区域塗り」を 1 つに束ねた範囲。表示に収まらなく
  なったときだけ引く（**第一報の直後 3 秒間は上記のとおり引かない**）。以下、この引き直しを
  **成長フォロー**と呼ぶ。EEW の件数が減ったときの再フィットも同じ範囲を使う（目標が食い違うと、
  再フィットの直後に引き直しが起きて二段のカメラ移動になる）
  - 件数減少時の再フィットは、**表示に収まっているかどうかを見ない**。複数の EEW が同時に出ている
    場面で、片方が取り消されたときなどに、残りを画へ収め直すための経路。ただし第一報直後の抑制は
    こちらにも効くため、抑制中に減少が起きた回は寄り直しを見送る（残りが画面外にはみ出していれば、
    抑制が明けた直後に成長フォローが引き直す）
  - 追従の基準は揺れの前線＝S 波円で、速い P 波円は追わない。円の半径は有感半径
    （[`eew-spec.md`](eew-spec.md) §7）と**引き上限**（`EEW_FOLLOW_MAX_RADIUS_KM` = 800km・箱は
    1600km 四方になる）で頭打ちにするが、検知点と区域塗りには上限をかけない（実際に反応した観測点と
    気象庁が塗った区域は「そこにある事実」なので切らない）
  - **上限は円の半径にかける。矩形の辺を枠で切り詰めてはならない。** 辺を別々に動かすと箱の中心が
    震源から外れ、枠の外に震源がある地震（南西諸島・小笠原・千島・大陸寄り）では震源を含まない箱に
    なりうる。半径で持てば箱は常に震源中心の正方形になる（この方式に至った経緯と 800km の選定根拠は
    `gl/bounds.ts` の `EEW_FOLLOW_MAX_RADIUS_KM`）
    - 上限の値を上げるときは地方名ラベルの閾値（`LABEL_MAX_SPAN_KM` = 2200km・§5）との関係を見ること。
      視野は余白のぶん箱より広くなるので、上げすぎると大地震の引きの画で地名が消える（基準ペインでは
      半径 930km あたりが境目。`gl/zoomConstants.test.ts` が地名の出る側・落ちる側の両方を固定している）
    - 合成後の箱は震源中心にならないことがある（検知点・区域塗り・複数 EEW を含めた結果）。
      これは画に入れるべきものを入れた結果で、円側の上限が中心を保つのとは別の話
  - 塗ってある区域が画面外にあると読めないため区域も含める。予想長周期地震動を表示中はそちらの区域へ
    切り替わる（どちらを塗るかの判定と同じ分岐を使う）
  - ここで束ねる「揺れ検知点」も**地図に描かれている点**（上記「揺れ検知追従の目標範囲」と同じ集合）。
    別の集合を渡すと、EEW が解除された瞬間に目標が入れ替わってカメラが飛ぶ
  - **震源の位置が判らない EEW は寄り先に含めない**。位置の欠け方は情報源で 2 通りある（`-200` の
    センチネルと、座標の欠測）。判定は `hasKnownEpicenter`（`utils/geo.ts`）に寄せる——「位置不明で
    ないこと」を否定形で書くと欠測がすり抜け、地図に不正な座標が渡って画面ごと落ちる。位置が判る
    までは残りの材料（検知点・予想の区域塗り・他の EEW）だけで範囲を作る
- **解除時** → 揺れ検知点、無ければ候補クラスタ（確定検知（`confirmed`）に育っていない `likely` 状態の
  検知点群。判定は [`kyoshin-detection-spec.md`](kyoshin-detection-spec.md) §4）、どちらも無ければ
  日本全体へ帰る
  - 発報中は他のカメラ追従（`FitToDetectionGL` / `FitToCandidateGL`）が停止して EEW 側へ追従を一任する
    ため、帰還先も `FitToEEWGL` が決める。委譲された側に帰還経路が無いと、EEW 中に立った候補クラスタが
    一度も画面に入らないまま終わる（`FitToCandidateGL` は候補 1 つにつき一度しか発火せず、自力では
    取り戻せない）
  - **限界**: 解除の瞬間にユーザーが地図を操作していた場合、この帰還は行われず、操作が終わっても
    再評価されない。確定検知は成長フォローが安全網になるが、候補クラスタにはそれが無い
  - 検知が続いていて描ける点だけが無いときは帰還を見送る（上記「揺れ検知追従の目標範囲」の末尾）

**津波追従の目標範囲**（実装は `TsunamiFitGL`。優先順位の判定は `gl/tsunamiFit.ts` の `decideTsunamiFit`）:

下記は「どこへ寄るか」の選択で、実装の分岐と同じ順に評価し、最初に当たったものだけを実行する
（そもそも動かすかどうかは津波モードかとユーザー操作中かで決まる。下記「ユーザー操作の尊重」）。
ここでいう signature は「区域名:等級」を連結した文字列で、発表内容が変わらなければ同じ値になる。

- **観測点の波高が更新された** → 更新された観測点へ寄る。速報性のある変化を俯瞰より先に見せる
  - このとき対象海域の signature を消費する（同じ範囲を海岸線と観測点で二重に決めると、寄った直後に
    引き直しが起きて二段のカメラ移動になる）。区域・等級が変わらない限り海岸線フィットは再発火しない
  - 手動操作中や津波モード以外のときは寄らずに持ち越す。持ち越すのは**最後に届いた電文のぶんだけ**で、
    複数の電文を束ねはしない（離れた観測点の和では引きの画になり、どこで新しく観測されたのかが
    読めなくなる）
- **区域・等級が変わった**（新規発表・格上げ・区域追加） → 対象海域全体
- **発表が終わった**（解除表示の後の消去・有効期間の満了） → 日本全体へ帰る
  - **限界**: 帰るのは津波モードの間だけ。消えるより先に他のタブへ移っていた場合はその場では帰らない
    （モードを越えた調停に踏み込まないのは下記 MAP-5 と同じ理由）。ただし `TsunamiFitGL` は
    モード切替をまたいで常時マウントされているため、次に津波タブへ戻った時点で下記「入室時」または
    この分岐が評価され、カメラは補正される
- **津波モードへ入室した、またはアイドル復帰の期限が来た** → 対象海域全体へ帰る（海岸線が引けない
  ときは日本全体）
  - アイドル復帰の期限は、観測点へ寄ってから、または地図を手動操作してから `INTERACTION_HOLD_SEC`
    （下記「ユーザー操作の尊重」と同じ固定時間）だけ何も起きないこと
  - これが無いと観測点に寄ったまま残り、発表中の対象海域全体が二度と画面に入らない（上記の
    signature 消費のため）
  - 設定タブの「自動復帰までの時間」は見ない。**「無効」を選んでも帰る。** 設定に従わせると、
    無効時に猶予タイマーが張られず、上記の「取り残される」経路がそのまま復活してしまう
    （帰還を足した動機そのものを打ち消すため）

**観測情報の行クリック**（実装は `FocusObsGL`）→ その観測点へ寄る。あわせて上記アイドル復帰の期限を
クリック時点から数え直す（パネルのクリックは地図の操作ガードを通らないため、数え直さないと
ユーザーが選んだ表示が猶予の残り時間だけで巻き戻される）。地図に観測棒が無い観測点（座標未収録・
[`tsunami-spec.md`](tsunami-spec.md) §8）はカメラを動かさないので、猶予にも触らない。

**寄り上限と閾値の単位**: MapLibre のズーム値が表すのは 1px あたりの実距離（m/px）だけで、
**見える地理的範囲は m/px × 地図ペインの寸法**で決まる。同じズーム 7 でも、スマホの短辺 375px では
視野 181km、2K の 1200px では 578km になる。そのため閾値の単位は「何を測りたいか」で使い分ける。

| 測りたいもの | 単位 | 該当する閾値 |
|---|---|---|
| 対象がどれだけ画に収まるか | **視野の短辺の実距離（km）** | 自動フィットの寄り上限・細線を消す下限・地方名ラベルを出す下限 |
| 文字や点が何 px 間隔で並ぶか（読みやすさ・混み具合）・タイルの縮尺との対応 | **ズーム値（m/px）** | ラベル粒度の切替帯（§5）・ヒートマップの収束ズーム・海底地形の高解像度層の下限（§4 の `GEBCO_HIRES_MIN_ZOOM`。要求するタイル z から逆算した値なのでズーム基準） |
| タイルの座標系 | **タイル z** | 地形先読みの最大タイル z（§4） |

密度で決まる閾値をズーム値のまま置くのは、密度が m/px だけで決まりペインの大きさに依らないため。
視野基準へ移すと逆に狭いペインで文字が潰し合う。換算の実装は `gl/viewSpan.ts`。

**視野基準の閾値**（いずれも「視野の短辺が何 km を超えたら／下回ったら」で持ち、実行時にその端末での
等価ズームへ換算する）:

| 閾値 | 定数 | 値 | 基準ペイン（短辺 800px）での等価ズーム |
|---|---|---|---|
| 自動フィットの寄り上限 | `FIT_MIN_SPAN_KM`（`gl/camera.ts`） | 400km | 7.0 |
| 細線を消す下限（§4） | `DETAIL_MAX_SPAN_KM`（`gl/zoomLevels.ts`） | 4400km | 3.5 |
| 地方名ラベルを出す下限（§5） | `LABEL_MAX_SPAN_KM`（同） | 2200km | 4.5 |

いずれも移行前のズーム値（7・3.5・4.5）と基準ペインで同じ画になる値を選んである。寄り上限だけは
**0.5 刻みへ丸めてから返す**（`fitMaxZoom`）——上限が刻みから外れていると、上限にクランプされた着地を
着地ズームの切り下げ（`snapZoomDown`）がさらに 1 段引き下げてしまう。

**寄り上限には絶対上限がある**（`ABSOLUTE_MAX_ZOOM` = 8）。視野基準の値は画面が大きいほど深くなるため、
上限を設けないと大画面で際限なく寄る。短辺 1600px（4K の上下分割相当）まではクランプが効かない水準に
置いてあり、それを超える画面では「視野の実距離を一定に保つ」という原則を意図的に破る。

**上限が固定の帯では、可変の下限が追い越さないよう止める**（`clampMinZoom`）。地方名ラベルの帯
（可変の下限 〜 固定の 6.5）は、ペインの短辺が 3228px を超えると下限が上限を追い越す。MapLibre は
`minzoom > maxzoom` を検証せずそのまま受け取り、可視判定は下限と上限を独立に見るため、**どのズームでも
描かれないレイヤーが黙って出来上がる**（例外もログも出ない）。

**Leaflet からの値の移植**: MapLibre GL JS のズームは 512px タイル基準で数えるため、Leaflet
（256px 基準）の同じ数値より 1 段深い（MapLibre の z は Leaflet の z+1 相当）。コードに書くズーム値は
常に MapLibre 基準に統一し、Leaflet 版から値を移す場合は 1 段引く。

**閾値を触るときに併せて見直すもの**:

- 震度の区域集約の閾値（[quake-spec.md](quake-spec.md) §7）。寄り上限と同値でなければならない
- 海底地形の高解像度層の下限ズーム（§4 の `GEBCO_HIRES_MIN_ZOOM`。マップズーム基準。自動フィットの
  寄り上限で必ず高解像度が出るよう、どの画面幅でも寄り上限より小さく保つ）
- 地形先読みの最大タイル z（§4。タイル座標系。基準ペインでの寄り上限から導く）

これらの相互関係は `src/components/Map/gl/zoomConstants.test.ts` が機械的に固定している。閾値が可変に
なったため、定数どうしの比較ではなく**代表的なペイン寸法**（スマホ縦・スマホ横・デスクトップ・2K・
超大画面）のすべてで関係が成り立つことを検証する形になっている。

**ユーザー操作の尊重**: `gl/camera.ts` の `subscribeUserInteraction`（各追従コンポーネントが呼ぶ入口。
`zoomstart`・`dragstart` の購読は内部で map ごとに 1 組だけ張る）を通じて、ユーザーが地図を操作している
間は自動フィットを抑制する。抑制は一定時間（`gl/camera.ts` の `INTERACTION_HOLD_SEC`。現在 30 秒）で
**必ず解ける**。

この時間は設定タブの「自動復帰までの時間」とは**切り離している**（あちらはタブの自動復帰専用）。
以前は同じ設定値を使っており、設定次第で抑制が永久に解けなくなっていた（経緯は §16 の 2026-08-19）。
切り離したことで、どの追従も下記のバイパスの有無に関わらず必ず復帰する。

MapLibre はプログラムによる
`flyTo`/`fitBounds` でも同じイベントを発火するため、自動フィット側は**アプリ起点であることを示す印**を
イベントに載せ（MapLibre の `eventData`）、印のあるイベントだけを判定から除外する。印はイベント自身が
運ぶので、下記「カメラの重複制御」の進行中判定（`isProgrammaticFlight`）には依存しない。逆に、自動
フィットの最中にユーザーがホイールやドラッグで割り込んだ操作は印を持たないため、取りこぼさずに
抑制がかかる。

**明示選択によるバイパス**: 上記の抑制は「電文更新起点の自動追従」を対象とした挙動であり、
ユーザー自身が明示的に選択した操作（地震カードのクリック・津波タブから地震情報へのリンク）は
抑制の対象外として扱う。App 側の `quakeSelectionTick` が明示クリック時のみ +1 され、
`QuakeFitGL` はこの tick が進んだフレームでは `isUserInteracting` を無視して強制フィットする。
EEW も同様に「新規 EEW 受信時は `resetUserInteraction()` してからフィットする」（`FitToEEWGL`）
という同種のバイパスを持つ。

**カメラの重複制御**: `beginProgrammaticFlight` / `isProgrammaticFlight` が自動アニメーションの進行中
判定を持つ。EEW と揺れ検知それぞれの成長フォロー（`FitToEEWGL` / `FitToDetectionGL`）が「進行中の飛行が
終わるまで次のフィットを待つ」ために使う。飛行ごとに通し番号を振り、**その番号を持つ `moveend` だけ**を
完了とみなす。後続のフィットが先行の飛行を中断したときにも `moveend` は発火するため、区別しないと
飛行中に「終わった」と判定されてしまう。`moveend` が来ないまま終わる場合（タブ非表示でアニメーションが
進まない等）に備え、所要時間に余裕を足した時刻を過ぎたら完了とみなす期限も併せ持つ。

なぜ印と通し番号が要るか。以前は飛行を数え上げるカウンタだけで「自分の操作か」を判定していた。EEW の
直前には候補クラスタ→揺れ検知のフィットが連続する（実地震では必ず起きる）が、重なった飛行の完了待ちが
1 回の `moveend` で一斉に解けてカウンタが 0 まで落ち、直後に自分のフィットが起こす `zoomstart` を
ユーザー操作と誤認していた。結果、誰も地図に触れていないのに EEW のカメラ追従が抑制の保持時間ぶん
止まり、予想の区域塗りが画面外に取り残されていた（当時はこの保持時間に設定「自動復帰までの時間」を
そのまま使っていた）。

**既知の限界（MAP-5）**: EEW 追従の `FitToEEWGL` は `mode === 'kyoshin'` のときのみマウントされる。
kyoshin モードから tsunami/quake モードへ切り替えるとアンマウントされ、以降その EEW を追従できない。
初回の敵対的レビューで「常時マウント化」を試みたが、`QuakeFitGL`/`TsunamiFitGL` との flyTo 争い・
EEW 解除後の他モード帰還が未実装等の副作用が広範に発生することが判明し revert した。正しい修正には
mode を全 Fit*GL に配って優先度で調停する大規模リファクタが必要で、スコープ外とした。

**地図の投影**: 地球は**球**として描く（`JapanMapGL` のスタイルに `projection: { type: 'globe' }`）。
傾けて見るのが常態になると、平面のままでは引いたときに端が伸びて見えるため。**寄ると MapLibre が
自動で Mercator へ切り替える**ので、日本を細かく見る場面での描画は従来と変わらない。切り替わる
境目は実測で **zoom 11 と 12 のあいだ**（`shaderData.variantName` が `globe` → `mercator`）。

投影が変わると、カスタムレイヤー（`gl/depthPointLayer.ts` / `gl/subThresholdLayer.ts` /
`PsWaveGL.tsx`）に渡される座標変換の仕組みも丸ごと入れ替わる。**`u_projection_matrix` に行列を
入れるだけの実装では、どちらか片方でしか正しく描けない。** MapLibre はこれを見越して、
`render()` の引数で**投影ごとの GLSL 断片**（`shaderData.vertexShaderPrelude`）を配る。これを
頂点シェーダーの先頭へ貼ると `projectTile()` / `projectTileFor3D()` が使えるようになり、投影の
違いは MapLibre 側が吸収する。**プログラムは投影ごとに作って持つ**（`gl/projectionProgram.ts` が
`variantName` をキーに抱える）。

- **属性の番号はリンク前に固定する**（`bindAttribLocation`）。投影が切り替わるとプログラムは別物に
  なるが、番号が揃っていれば VAO は作り直さずに済む
- **リンクに失敗したプログラムを返してはならない。** WebGL は未リンクのプログラムへの `useProgram`
  で例外を投げず、直前の別レイヤーのシェーダーが残ったまま描画が走る（§9 も参照）。
  失敗は `null` として**覚える**——覚えないと毎フレーム作り直しに行き、ログで埋まる
- **`projectTileFor3D` の elevation は投影で単位が違う。** 球ではメートル（負で地球中心へ向かう）、
  平面では Mercator 座標系の z（緯度で縮む）。バッファはメートルで持ち、シェーダーの
  `elevationForProjection` が `#ifdef GLOBE` で吸収する
- **`projectTileFor3D` は水平線のクリッピングを掛けない。** `projectTile` /
  `projectTileWithElevation` は `globeComputeClippingZ` が z を書き、裏側の点を `z/w > 1` にして
  捨てるが、3D 用の経路にはそれが無い。深さを持つ点が球の裏へ回っても透けて見えるのはこのため
  （そのままにする判断と理由は §16「球の裏側にある点は透けたまま残す」）
- **`map.project()` は地球の裏側の点にも画面内の座標を返す。** zoom 2・中心 138E36N で南大西洋
  (-40, -20) が画面中央付近の (500, 411) に落ちる。画面座標だけで「見えているか」を判定する箇所
  （§6「地図の傾きと回転」の「収まり判定」の項）は、投影して戻す往復で裏側を弾く
  （`isBehindGlobe`）。手前の点は誤差 0 で戻り、裏側の点は大きくずれる（上の例では 176 度。
  **判定の閾値 1 度は、別に測った最も小さいずれ 20 度から十分な余裕を取った値**）。
  **平面投影では常に誤差 0 で戻る**ので、この判定は何も弾かない

描画コストは球のほうが重い。zoom 6・pitch 50 で 1 フレームあたり 1.5 度ずつ回し続けたときの
フレーム間隔は、中央値が球 20.4ms / 平面 17.2ms（p90 は 29.7 / 29.5 でほぼ同じ）。dev ビルドを
1178×965 のペインで測った**目安**で、端末と表示している点の数で変わる。

**地図の傾きと回転**: 傾き（pitch）と回転（bearing）はどちらも**ユーザー操作から使える**。地下の
震源分布を立体で見せるため、傾いた状態を常態として扱う。実装は `JapanMapGL` の Map 生成オプション
（`maxPitch: 60`）のみで、MapLibre の標準ジェスチャがそのまま傾きと回転を担う。マウスは右ドラッグで
両方、タッチは**2 本指を上下へ動かすと傾き・ひねると回転**（別々のハンドラ。`TwoFingersTouchPitchHandler`
と `TwoFingersTouchRotateHandler`）、キーボードは Shift + 矢印。

**`maxPitch` の 60 は MapLibre の既定値であり、その先は霧を前提とした領域。** MapLibre は
`style/sky.ts` の `calculateFogBlendOpacity` で「pitch 60 未満は霧を無効、60〜70 でフェードイン、
70 以上は完全」と定め、水平線が視界へ入ることによる破綻を霧で隠す設計にしている（同ファイルの
コメント: "gets out of view, which is at about pitch 70"）。このアプリは sky / fog を設定して
いないため、その手前で止める。公式ドキュメントも 60 度超を experimental と明記している
（`ui/map.ts` の `setMaxPitch`）。

**水平線の位置は単純な fov の引き算では求まらない。** 実体は `geo/projection/mercator_utils.ts` の
`getMercatorHorizon` で、`cameraToCenterDistance × min(tan(90 − pitch) × 0.85, tan(89.25 − pitch))`。
0.85 の減衰と 89.25 度の上限が入る。60 を超えて使いたくなったら、この式と sky / fog の設定を
併せて見直すこと。

傾きを入れると視野は大きく広がる。日向灘（132, 32）を中心に zoom 6・ペイン 929×454 で実測した値
（`maxPitch: 60` では 68・70 へは到達しないが、**なぜそこで止めるか**の根拠として残す）:

| pitch | 画面左上の緯度 | `getBounds()` の北 | 緯度幅 | 経度幅 |
|---|---|---|---|---|
| 0 | 34.09 | 34.09 | 4.23 | 10.21 |
| 30 | 34.97 | 34.97 | 5.04 | 12.64 |
| 45 | 36.37 | 36.37 | 6.64 | 15.31 |
| 55 | 38.76 | 38.76 | 9.29 | 19.48 |
| 62 | 43.24 | 43.24 | 14.05 | 27.36 |
| 68 | 58.15 | 58.15 | 29.29 | 58.33 |
| 70 | **76.06** | 61.69 | 32.97 | 68.04 |

70 度の行だけ「画面左上の緯度」と「`getBounds()` の北」が食い違う。そこでは既に MapLibre 本体の
水平線クランプが効いている。**`getBounds()` はクランプするが、生の `unproject()` はしない**——
画面左上を素直に地理座標へ戻すと北極圏（緯度 76 度）が返る。傾きを扱うコードが `unproject()` を
直に使う場合はここに落ちる。

**上限の 60 度ではこの食い違いは起きない**（実測: 画面左上の緯度 63.46 ＝ `getBounds()` の北 63.46）。
クランプの領域へ踏み込まないことが、60 を選ぶもう一つの裏付けになっている。なお `pitch` に 85 を
指定しても MapLibre 側が `maxPitch` へ丸めるため、コード経由で上限を超えることもない。

傾きと回転を常態にするにあたって直したのは次の 6 点。

- **予報円**（`PsWaveGL`）— **円を地面に貼る方式へ変えた。** 単位円のグリッド（角度 × 正規化半径）を
  静的な頂点バッファに持ち、頂点シェーダーでその方位へ r×半径 km 進んだ地点の Mercator 座標を求めてから
  MapLibre の行列を掛ける。半径は uniform で毎フレーム渡すだけなのでバッファは作り直さない。
  旧実装は「震央から東へ 1 点ずらして `project()` した画面座標の x 座標差」を半径として真円を描いており、
  回転すると `cos(bearing)` 倍に縮み（実測: 0 度 45.51px → 45 度 32.18px → 60 度 22.76px → **90 度 0px**）、
  傾ければ地面の円と画面の円が一致しなかった
- **カメラ自動フィット**（`gl/camera.ts`）— `fitBounds` / `cameraForBounds` の呼び出し 5 箇所すべてに
  `bearing: map.getBearing()` を渡す。MapLibre は bearing を渡されない限り 0 として扱うため、渡さないと
  `fitJapan`（タブ切替で走る）が**ユーザーの回転を無断でリセットする**
- **収まり判定**（`gl/camera.ts` の `mapContainsBounds`）— **目標の四隅を `map.project()` で画面座標へ
  投影し、余白の内側に入っているかを見る**（`getBounds()` も `unproject()` も使わない）。地理座標の
  矩形どうしで比べてはならない——回転した視野を軸並行の矩形で包むと実際の視野より必ず大きくなり
  （45 度で約 1.41 倍）、**画面からはみ出しているものを「収まっている」と誤判定する**。EEW の成長フォロー
  （`CameraFollowsGL`）は「収まっていれば何もしない」だけで収め直しの経路を持たないため、ここが甘いと
  回転した地図で追従が黙って止まる。画面座標で見れば回転にも傾きにも自動的に追従する
- **ユーザー操作の検知**（`gl/camera.ts` の `subscribeUserInteraction`）— `zoomstart` / `dragstart` に
  加えて `rotatestart` / `pitchstart` も監視する。漏らすと傾けている最中に自動フィットが割り込む
- **地名ラベルの退避**（`gl/labelOverlap.ts` の `shiftCandidates`）— 余地の判定を符号込みにする（下記）
- **点の遠近**（`circle` レイヤー全般）— `circle-pitch-scale` を `viewport` にする。既定は `map` で、
  カメラからの距離に応じて半径が縮む。縮み率は透視除算の `w` に比例するので、**奥行き方向の圧縮率が
  そのまま効く**——傾き 60 度・zoom 4.6 の日本全体の画で、緯度 0.1 度あたりの画面上の距離は手前
  （九州）4px に対し最奥（北海道）1px だった（実測）。同じ比で半径も縮む。この地図の点・バッジ・ラベル・
  DOM マーカーはすべて画面に正対して一定の大きさで描く方針なので、そちらへ揃える。とくに震度0以下を
  描く `gl/subThresholdLayer.ts` は自前シェーダーの固定サイズ（`gl_PointSize`）なので、`circle` 側を
  既定のまま残すと**同じ観測点なのに震度1以上だけ奥で縮む**。対象は `KyoshinPointsGL`（観測点）・
  `KyoshinMaxEffectGL`（波紋）・`QuakeHeatmapGL`（当たり判定）の 3 つ。**新しく `circle` レイヤーを
  足すときも同じ指定を入れること**

**地名ラベルの退避**（`gl/labelOverlap.ts`）は符号で判定する。ラベルを逃がすのは画面座標の上下だが、
`room` が持つのは地理的な真北・真南への余地（`scripts/lib/labelAnchor.mjs` の `shiftRoom` が経度線に
沿って測って焼いた生成データ）。回転すると両者は一致しないため、投影してから**どちらが画面上方向に
伸びるか**を符号で決める。絶対値を取ると北が画面下へ来たときに読み違える。
限界として、画面の真上は地理的には北とは限らず（回転 45 度なら北東）、その方位の余地はデータが
持っていない。北・南の余地を画面 y 成分へ射影して代用するため、退避先が区域の外へわずかにはみ出す
ことがある。回転が 90 度に近づくと候補が消え、退避せず薄くする側（安全側）へ倒れる。

傾き（pitch）については**符号は崩れない**（実測: zoom 4.6 の日本全体の画で、pitch 0〜60 のどの角度でも
北は画面上・南は画面下に投影される）。ただし透視で遠方が圧縮されるため、**奥ほど余地が小さく見積もられる**。
緯度 0.1 度ぶんの画面 y 差は、手前（九州）が 4px のままなのに対し最奥（北海道）は 5px → 1px まで縮む。
退避の候補が立たなくなる方向なので安全側だが、奥のラベルほど退避しにくくなる。

**視野の実距離（`gl/viewSpan.ts`）に傾きの補正は入れていない。** 傾けても描画されるフィーチャは
増えないため（zoom 5.0 で実測: 地方名ラベルは 0〜62 度で 8 件のまま、県境フィーチャは 389 → 363 と
むしろ微減）。これらの閾値が代理指標にしているのは画面中心の縮尺であり、そこは傾けても変わらない。

**未解決: 傾けると自動フィットの寄りが甘くなる。** `cameraForBounds` は pitch を計算に入れないため、
傾きに関わらず同じズームを返す。対象は**見切れない**（実測で四隅は常に画面内）が、画面の中で小さくなる。
矩形 `[138.0, 35.0]`〜`[141.5, 39.5]`（東北）を padding 48 でフィットしたときの実測（ペイン 929×454）:

| pitch | 算出 zoom | 四隅が画面内 | 対象の縦 px | 対象の横 px |
|---|---|---|---|---|
| 0 | 5.476 | ○ | 358 | 222 |
| 30 | 5.476 | ○ | 315 | 255 |
| 45 | 5.476 | ○ | 262 | 272 |
| 55 | 5.476 | ○ | 215 | 282 |
| 62 | 5.476 | ○ | 178 | 288 |

縦の縮み方は `cos(pitch)` にほぼ一致する（実測 0.88 / 0.73 / 0.60 / 0.50 に対し cos は 0.87 / 0.71 /
0.57 / 0.47）。**ただし zoom だけを `-log2(cos(pitch))` で補正すると、かえってはみ出す**——
`cameraForBounds` は center も pitch を見ておらず、傾けると対象は画面の上寄りに来るため、そのズレごと
拡大されるからである（南北に長い `[139.5, 35.0]`〜`[141.5, 41.5]`／東西に長い `[131.0, 33.5]`〜`[141.5, 37.5]`／
正方に近い `[138.5, 34.8]`〜`[140.9, 37.2]` の 3 形すべてで、45 度以上ではみ出すことを実測）。
正しく直すには zoom と center を同時に解く必要があり、`cameraForBounds` を自前で書き直すことになる。
見切れない以上は機能として壊れていないため、常用する傾き角が定まってから着手する。

一方、**円マーカー・ラベル・DOM マーカーは画面に正対して一定の大きさで描かれる**。symbol のラベルは
画面空間の固定値で、`maplibregl.Marker`（`EpicenterGL` / `EewEpicentersGL` / `TsunamiObsBarsGL`）も
`rotationAlignment` の既定（viewport）により画面に正対したままだからである。**ただし circle レイヤーの
半径だけは、上記「点の遠近」の指定に依存する**——`circle-pitch-scale` を既定の `map` に戻すと、
この段落の前提はその場で崩れる。

`gl/labelOverlap.ts` の重なり**判定**（`overlapsAt`）も画面座標どうしの比較なので崩れない
（退避方向の決め方は上記のとおり別扱い）。

**津波の観測点の波高バー**（`TsunamiObsBarsGL`・DOM マーカー）は傾けても高さが変わらない。バーの高さは
波高に比例する設計で、大津波警報の「10m 以上」では 403px に達する（ペイン 929×454 での実測。傾き 0 度・
30 度・55 度のいずれでも同じ）。**傾きで壊れたのではなく元からの長さ**だが、背景に遠近が付く分、正対した
棒が地面から浮いて見える度合いは増す。地面から起立させるには DOM マーカーをやめる必要があり、傾きの
対応とは別の議題。

## 8. 毎秒更新レイヤー（強震モニタ 1Hz）

Yahoo リアルタイム震度は 1 秒毎に更新される。以下のレイヤーが毎秒 setData / setFeatureState する:

- `KyoshinPointsGL` — 各観測点の feature-state を更新
- `KyoshinSubThresholdGL` — カスタムレイヤーで indices バッファを更新して triggerRepaint
- `KyoshinMaxEffectGL` — 波紋 rAF アニメ
- `KyoshinDetectedPointsGL` — 検知点の GeoJSON を setData

**トランジション対策**: MapLibre GL v6 は全 paint プロパティに既定 300ms トランジションが付く。
毎秒更新するレイヤーで painter の値が動く場合、`-transition: { duration: 0 }` を明示的に設定して
アニメーション残像・点滅を防ぐ。過去に津波点滅（v4.1.1）と強震モニタ（v4.2.2）で 2 回踏んだ実績あり。

**symbol の配置フェード**: 上記の paint トランジションとは**別系統**で、symbol レイヤーには出入りの
フェードがある（MapLibre の `fadeDuration`。既定 300ms——直前の paint トランジションと同じ数字だが、
偶然一致しているだけの別設定）。paint プロパティではなく配置処理が持つ仕組みなので、各レイヤーで
`-transition: { duration: 0 }` を書いても効かず、**地図全体（`new Map()` のオプション）でしか
設定できない**。本アプリは `JapanMapGL` で **0 に設定して切っている**。理由は 2 つ:

- **不透明度が既に意味を持っている**。欠測ホールド中の点を 0.35 倍で描いて「そこに点はあるが今は
  値が無い」と伝えているため（下記「欠測中の点は薄く描く」）、出現時に 0→1 を通すと、その途中が
  「欠測中の点」と見分けられなくなる
- **同じ出来事が 2 通りの見え方に割れる**。MapLibre は前回の配置にあったシンボルの不透明度を引き継ぎ、
  引き継げないシンボル（＝その位置に前は無かったもの）だけ 0 から立ち上げる。加えてタイル再読み込み
  直後の配置ではフェードを免除する。免除に当たるかは秒単位のタイミング次第なので、「新しい検知点が
  出る」という同一の出来事がフェードと即時に割れる（実測値は §16 の 2026-08-21 の項目）

**効果はアイコン画像・文字を描く層（symbol）すべてに及ぶ**。設定を絞れないため、検知点だけを対象に
することはできない。現時点の対象は `KyoshinDetectedPointsGL`（揺れ検知点ハイライト）・
`QuakeIntensityPointsGL`（観測点ドット）・`QuakeRegionFillGL`（区域中心震度バッジ）・`LpgmPointsGL` /
`LpgmRegionFillGL`（長周期）・`LabelsGL`（地名ラベル）の 6 つ。円（`circle`）とカスタムレイヤーは
対象外なので、`KyoshinPointsGL` や `KyoshinSubThresholdGL` は元から即時。

これで出入りは一律に即時となり、不透明度が動くのは欠測ホールドの 0.35 とラベルの重なり回避（§5）
だけになる——**不透明度の変化＝意味のある変化**に揃う。

**欠測中の点は薄く描く**: 強震モニタの秒データは 1〜2 秒の欠測（瞬断）を頻繁に含む。表示に使う値は
欠測点を直前値で短時間保持しており（[`kyoshin-detection-spec.md`](kyoshin-detection-spec.md) §8）、
保持中の点は `KyoshinDetectedPointsGL`（`icon-opacity` のデータ駆動式）と `KyoshinPointsGL`
（feature-state の不透明度）で 0.35 倍に落として描く。どちらもトランジションを 0 にする——
既定の 300ms を残すと、抑えたい明滅が「薄くなりかけて戻る」形で残ってしまう。

## 9. パフォーマンス上の要点

### setData churn 対策
- 同じデータでの setData は避ける（React で参照同一性を保つよう useMemo で囲む）
- 過去に `App.tsx` の `Array.from(activeEEWs.values())` を毎レンダー生成していて fps 17→55 の劣化を起こした事故あり

### rAF の停止
- `KyoshinMaxEffectGL`・`TsunamiLinesGL`（点滅）・`PsWaveGL` は `requestAnimationFrame` を使う
- 停止条件（`activeEEWs.length === 0` 等）で `cancelAnimationFrame` を呼ぶ
- コンポーネント unmount 時にも cleanup が必要

### カスタムレイヤーの GL リソース
- `KyoshinSubThresholdGL` は **FBO 二層合成**で「同レベルドットの重畳を非加算合成」を実現
  - **FBO**（Framebuffer Object）: 画面ではなくオフスクリーンのテクスチャに描画するための WebGL の仕組み。1 層目に「その点が塗られているかどうか」を書き込み、2 層目でその結果を通常の paint に合成することで、同じ震度階級のドットが何個重なっても濃くならないブレンドを実現している
- `PsWaveGL` は `type: 'custom'` のカスタムレイヤーで、内部でオフスクリーンの 2D canvas に円を描画してから `gl.texImage2D` で WebGL テクスチャに転送する構造（旧実装は `getCanvasContainer` 上の DOM Canvas オーバーレイだったが、カスタムレイヤー方式に置換済み）

### 大量マーカーの実装方針
- 座標に強く紐づく DOM 要素（震源×印・観測バー）は `maplibregl.Marker` を使う
- それ以外は GL レイヤー（circle / fill / line / symbol）で描画

### 静的な形はソースを共有する

MapLibre は**ソース単位**で次の 2 つを毎フレーム回す。どちらもレイヤーの枚数ではなく
**ソースの数**に比例する。

| 処理 | 何をするか | 走る条件 |
|---|---|---|
| タイル被覆の再計算 | いま見えている範囲を覆うタイルを**四分木**（タイルを 4 分割しながら、必要な細かさに届くまで絞り込む探索）で探す | ソースごとに毎フレーム |
| タイルのクリッピングマスク描画 | fill / line を描く前に、タイル境界を**ステンシルバッファ**（画素ごとに描いてよい範囲を保持する補助バッファ）へ描く | **直前のレイヤーとソースが変わったときだけ**（境界あり／なしの 2 パス × タイル枚数） |

つまり同じ画に一緒に出る fill / line は、**ソースを共有するほど軽くなる**。共有していればマスクは
1 回で済み、タイル被覆の計算も 1 回で済む。そこで「読み込んだら変わらない形」は種別ごとにソースを
分けず、`kind` の filter で描き分ける形で相乗りさせている。

**共有ソースは 2 つある。**

| 共有ソース | 相乗りしているレイヤー | 共有の仕組みを持つファイル |
|---|---|---|
| `basemap-shapes` | `land-fill`（陸地塗り）／ `pref-borders`（県境）／ `sub-borders`（区域境界線）／ `subregion-hit`（区域名ポップアップの当たり判定） | `gl/basemapFeatures.ts` |
| `overlay-lines` | `plate-boundaries`（プレート境界線）／ `active-faults`（活断層線） | `gl/overlayLineSource.ts` |

上の 2 ファイルが持つのは feature の組み立てと共有の調停だけで、**レイヤーそのもの（描画順・色・線幅・
ズーム帯）は各コンポーネント側**にある（`BaseMapGL` / `PlateBoundariesGL` / `ActiveFaultsGL`）。

**この 2 つを 1 つにまとめないのは、レイヤーの並び順が理由。** 線の 2 枚は震度の区域塗りより前面に
置くため、あいだに別ソースのレイヤーが挟まる。1 つにまとめてもマスクは 2 回描かれる。

**`kind` は型（`BasemapKind` / `OverlayLineKind`）を通して埋め込むこと。** GeoJSON の属性はどんな値も
受けるので、素で書くと綴りを間違えても型検査を通る。埋め込む側と filter 側は別ファイルの文字列
どうしなので、食い違えば**エラーも警告も出さないまま、そのレイヤーだけが何も描かなくなる**。

`overlay-lines` は提供元が 2 つあり、データの到着も離脱も独立している（それぞれ別の遅延読込）。
「先に届いた方が作り、後から届いた方が追記し、最後の 1 つが降りるまで消さない」調停が要るため、
受け皿を `gl/overlayLineSource.ts` に置いている。**提供元は自分のレイヤーを外してから降りること**
——参照が残っていると MapLibre はソースを削除しないが、**その失敗は例外ではなくエラーイベントの形**
でしか現れない（気づかず登録簿を畳むと、次の提供元が書き込んだ時点で残ったレイヤーが無言で空になる）。

**新しく静的な形のレイヤーを足すときは、既存の共有ソースへ相乗りできないか先に検討する。**

実測（CPU を 4 倍遅くした状態・傾き 45 度・自動移動中の 1 フレーム平均）: ソースを 24 個から 20 個へ
減らして、フレーム 73.4ms → 53.0ms、ドローコール 397 本 → 209 本、うちマスク描画 15.2ms → 5.4ms。

## 10. maplibregl.Marker の注意点

`maplibregl.Marker` の不透明度は **`element.style.opacity` ではなく Marker のオプション**
（`opacity` / `opacityWhenCovered`）で渡す。Marker は「地形に隠れたとき薄くする」機能があり、
これが element の style.opacity を自前で上書きするため、cssText 経由の設定は無視される。

`opacityWhenCovered` を省くと地形有効時に既定 0.2 が効くため、隠蔽時も同じ濃さにしたいなら同値を渡す。

**Marker の不透明度と、中の要素の CSS アニメーションの opacity は乗算される。** 点滅する描画物で
Marker 側の不透明度も下げると、実際の濃さは両者の積になる。谷が深いアニメーション（例: 1 ↔ 0.1）に
低い不透明度を掛けると、谷では事実上見えない。EEW の震源×印（`EewEpicentersGL`）がこれを踏み、
仮定震源要素を「薄く」する意図が実効 0.02 まで落ちていた。**弱めたいときは不透明度だけでなく
アニメーションの振幅も併せて決める**（[`eew-spec.md`](eew-spec.md) §5）。

**点滅する Marker は「作り直さない」ことが要る。** CSS アニメーションは要素ごとに時間を持つので、
DOM を作り直すと 1 周期がゼロから始まる。更新のたびに作り直していると、更新の間隔が周期より短い
場合に周期の前半へ留まり続け、点滅が止まって見える。開いていたポップアップも閉じる。避けるには
2 つ要る。**差分更新のキーに更新ごとに変わる値を使わない**ことと、**内容が変わらないなら
`innerHTML` を触らない**こと。片方だけでは作り直しの経路が残る。

> EEW の震源×印（`EewEpicentersGL`）がこれを踏んでいた。キーが報番号込みだったため続報ごとに
> マーカーを作り直し、続報の間隔（1 秒前後）が点滅周期（1.2 秒）より短いので点滅が止まって
> 見えていた。キーの取り方は [`eew-spec.md`](eew-spec.md) §10、作り直しを避ける判定は
> `updateCrossEl` の早期 return（`EewEpicentersGL.test.ts` が固定している）。

## 12. WebGL コンテキストロスト

MapLibre v6 は WebGL コンテキストロスト時、内蔵レイヤーは `_contextRestored` の
`setStyle(style, {diff:false})` 経由で復元するが、custom レイヤーは復元しない
（公式コードが `console.warn("Custom layer ... cannot be restored")` で明示）。

本アプリでは `map.on('webglcontextrestored', ...)` を各 custom レイヤーコンポーネントで購読し、
restore 時に手動で `addOrderedLayer` 経由で再追加する:

- `pswave`（`PsWaveGL.tsx`）: 同一の `customLayer` オブジェクトを再追加。onAdd が新しい gl から
  program/buffer/texture 参照を作り直す。
- `kyoshin-subthreshold`（`KyoshinSubThresholdGL.tsx`）: `makeSubThresholdLayer` で
  レイヤーオブジェクトごと作り直し、成功後に `layerRef` を差し替えて setLevels/setIconScale/setVisible の
  窓口を維持する。restore 直後にマウント時点の値ではなく現在の props/直近 levels を再適用する
  （`iconScaleRef` / `visibleRef` / `levelsRef` で保持）。

### タイミング設計上の注意

MapLibre v6 の `_contextRestored` は `setStyle(..., {diff:false})` を呼んだ直後、**同じ同期実行内**で
`webglcontextrestored` を発火する。この時点で新しい `Style` は `_load()` が次フレームまで遅延され
`_loaded=false` のため、直接 `addLayer` を呼ぶと `_checkLoaded` が `Error: Style is not done loading.`
を投げる。さらに MapLibre の `Evented.fire` はリスナー単位で try/catch しないため、1 つの例外が
後続の custom layer のハンドラを止めうる。

対策:
- `map.isStyleLoaded()` を確認し、false のときは `map.once('style.load', ...)` で待ってから追加
- 各コンポーネントで try/catch し、失敗は `log.error` で記録（他 custom layer のハンドラは巻き添えにしない）

モバイル常駐 PWA で GPU リソース回収時（バックグラウンド長時間放置後の復帰・端末リソース逼迫）に
発生しうる。

## 14. 地震活動ヒートマップの見せ方

`QuakeHeatmapGL` が直近 1 ヶ月の震源を密度として描く。パラメータの決め方には前提が 2 つある。

**前提 1: 濃さは場所によって桁で違う。** 実データ（2026-08-18・696 点）では 0.1 度メッシュあたりの
重み合計が中央値 0.15 に対し最大 16.6 と 100 倍以上開く。色の折れ点を等間隔に置くと、濃い側は
上限に張り付いて一様な赤（境界のはっきりした塊）になり、薄い側は透明に潰れて、どちらの濃淡も
読めなくなる。**折れ点は対数的に配置し、密度強度も低く抑える。**

**前提 2: 取得できる震源の座標は 0.1 度（約 11km）刻み**（両バリアント共通。気象庁の決定精度では
なく公表時の丸めで、精密な値が別電文にあることを含め [data-sources-spec.md](data-sources-spec.md) §2）。
半径を px 固定のまま寄ると、格子の間隔が半径を超えて 11km 格子の点描になり、配信された座標より
細かい位置が分かっているように見えてしまう。そこで
**`HEAT_MAX_ZOOM` から `HEAT_GEO_ZOOM` までは半径を「ズーム 1 段で 2 倍」＝地理的な距離が一定に
なるよう伸ばす**（`interpolate` の `exponential` base 2。この基数だとストップ間が正確に 2 倍ずつに
なる）。引きの画では見やすさを優先して px で決め打つため、境目が `HEAT_MAX_ZOOM` になる。

半径を伸ばすと高ズームで画面全体が塗り潰されて地図が読めなくなるので、**不透明度を寄るほど下げて**
下地に沈ませる。引きの画は従来の濃さのまま、寄ったら「背景の情報」として残る。

`HEAT_GEO_ZOOM` より寄ると半径・不透明度とも値が固定される（`interpolate` はストップ範囲外を
クランプするため）。地図自体に寄り上限は無いのでそこまで寄ることはできるが、その領域では
「地理的な距離を保つ」性質は失われ、再び格子が見え始める。

値そのものは `QuakeHeatmapGL.tsx` の定数と paint 式を正とする。

## 15. バッジの文字色とサイズ

### 文字色は塗り色から決める

対象は震度・長周期地震動階級を色で示すバッジ全般。地図の Canvas アイコン（`gl/intensityIcons.ts`・
`gl/lpgmIcons.ts`・`gl/kyoshinDetectedIcons.ts`）、ポップアップのバッジ（`gl/popupHtml.ts` の
`badgeHtml`・`HypocenterDepthGL.tsx` の県別震度）、UI 側のバッジ（`SettingsTab`・`RealtimeTab` の震度分布）。

ポップアップのバッジ（`badgeHtml`）は**ラベルを折り返さない**（`white-space:nowrap`）。幅は中身に
合わせて伸びるが、狭い親の中では折り返して「4以」「上」と縦に割れる。EEW の上限を定めない予想震度
（→ [`eew-spec.md`](eew-spec.md) §4）で 2 文字を超えるラベルが入るようになったため必要になった。
同じ理由で EEW 震源のポップアップは幅の上限を 280px に取る（既定の 240px では 1 行に収まらない）。

気象庁の震度配色・長周期地震動階級の配色は仕様として定まっているため**色そのものは変えられない**。
一方このパレットは明度の幅が広く（震度4 の黄 〜 震度7 の紫）、文字色を白か黒の一方に固定すると
必ず片側が WCAG AA（通常サイズ 4.5:1）を割る。

そこで `src/utils/contrast.ts` の `readableTextColor(塗り色)` が、白・黒それぞれとのコントラスト比を
実際に比べて高い方を返す。これで配色を変えずに全階級が AA を満たす。
**明度のしきい値で切り替える実装にしないこと**（僅差で選択を誤る色がある）。判断の根拠になる
具体的な比率は `contrast.ts` 冒頭のコメントを正とする。

この関数は `#rgb` / `#rrggbb` 以外を受け取ると白へフォールバックする。想定外の値に対する最後の
備えであって許容する入力ではない。**新しい呼び出し元を足すときは、渡す色が必ず 16 進表記である
ことを確認すること**（フォールバックが発動しても例外は出ず、明るい塗りの上で静かに AA を割る）。

配色を触ったときに気づけるよう、`src/utils/contrast.test.ts` が震度・長周期の全配色について
AA を満たすことを検査する。

**同じ系統の色で文字色が切り替わって見えるのは想定どおり**（不具合ではない）。長周期は階級1〜3 が
黒文字で階級4 だけ白文字になる。階級3 と階級4 はどちらも赤系だが輝度が境界をまたぐためで、
統一しようと全て黒にすると階級4 が AA を割る（観測点バッジは文字が小さく Large Text 緩和にも
載らない）。区域と観測点は同じアイコン画像を共有しているので、片方だけ別の文字色にもできない。
2026-08-19 に検討したうえで自動選択のままとした。

### 同じ階級なら画面の手前から

傾けると奥行きが生まれ、同じ震度のバッジが重なったときに**どちらが手前か**が意味を持つ。
並びは「階級が第一・手前らしさが第二」の二段（`gl/screenDepth.ts`）。

MapLibre の並べ替えは 2 通りあるが、**どちらか一方しか使えない**。

| 仕組み | 何で並ぶか |
|---|---|
| `symbol-sort-key` | 値が大きいものが手前（実測で確認） |
| `symbol-z-order: 'viewport-y'` | 画面の下にあるものが手前 |

`symbol-sort-key` を指定すると `viewport-y` は使われない。したがって二段の並びは、
**両方を 1 つの値へ畳んだ合成キー**でしか作れない。

```
並び順の値 = 階級 + 手前らしさ(0〜1) × 0.9
```

手前らしさに割り当てる幅を 1 未満にしておけば、階級の刻み（震度は 10・長周期は 1）を
またがない——**手前らしさが隣の階級を追い越さない**。

**手前らしさは方位と座標だけで決まる。** 方位 θ に対して `−x·sinθ + y·cosθ`（x・y は Mercator
座標）。中心・ズーム・傾きには依存しないので、**作り直しが要るのは方位が変わったときだけ**。
点の側には Mercator 座標を持たせておき（`mercatorProps`）、方位が変わったら
`setLayoutProperty` で式だけ差し替える（`setData` は呼ばない）。

- **値の取りうる範囲は ±√2。** ±1 で収まると誤ると、斜めの方位で 0〜1 をはみ出して階級を
  追い越す。√2 で割ってから 0〜1 へ写す
- **作り直しは方位 5 度刻みに間引く**（`BEARING_STEP_DEG`）。シンボルの配置計算が走るため、
  回している間ずっと呼ぶのは重い。端数は回し終わりで合わせる
- **`styledata` を購読して再適用するときは、中身が変わらないなら書かないこと。**
  `setLayoutProperty` は `styledata` を発火させるので、書く→通知→書くの無限ループになる
- 対象のレイヤーは `FRONT_SORTED_LAYERS`。**ここへ足したレイヤーの点には `mercatorProps` を
  必ず持たせること**（持たせ忘れると合成キーが null になり、そのレイヤーの並びが階級ごと壊れる）

実測（中心 138E36N・zoom 5 で 289 点）では、画面 y との順序の食い違いは方位 0/90 度と傾き 0 で
0%、斜めの方位でも 0.2〜1.2%。Mercator の縮尺が緯度で変わるぶんの誤差で、バッジの前後を
決めるには足りる。

### 地図バッジのサイズは階級に連動させる

こちらの対象は**地図の Canvas アイコンのみ**（ポップアップ・UI 側のバッジは CSS で寸法が決まり、
階級では変わらない）。重大なほど大きく見えるよう、半径を階級から決める。

| バッジ | 半径（正方形は一辺の半分） | 表示サイズ（倍率 100%） |
|---|---|---|
| 震度・観測点（`QuakeIntensityPointsGL`） | `getScaleRadius(scale) + 3` | 直径 14〜38px |
| 震度・区域（`QuakeRegionFillGL`） | `getScaleRadius(scale) + 4` | 直径 16〜40px |
| 揺れ検知点（`KyoshinDetectedPointsGL`） | `getScaleRadius(scale) + 6`（confirmed）／`+ 2`（candidate）。震度0相当は固定小半径 | 直径 9〜44px（confirmed）／5〜36px（candidate） |
| 長周期・観測点（`LpgmPointsGL`） | `getLpgmClassRadius(cls)` | 一辺 16〜28px |
| 長周期・区域（`LpgmRegionFillGL`） | `getLpgmClassRadius(cls) + 8` | 一辺 32〜44px |

`getScaleRadius()` は `src/utils/intensity.ts`、`getLpgmClassRadius()` は `src/utils/lpgm.ts`。

#### ベース半径とぼやけ

アイコン画像は `*_ICON_BASE_RADIUS`（いずれも 32）で焼いたものを `icon-size` で縮小して表示する。
`icon-size` が 1 を超えると焼いた画像の拡大になり、文字がぼやける。上表の半径には
「地図アイコン倍率」（`mapIconScale`・**0.5〜3.0 の可変**）が掛かるため、**高倍率ではどのバッジも
いずれ 1 を超える**。倍率がいくつを超えるとぼやけ始めるかはバッジごとに異なる。

| バッジ | ぼやけ始める倍率 |
|---|---|
| 長周期・観測点 | ×2.29 |
| 震度・観測点 | ×1.68 |
| 震度・区域 | ×1.60 |
| 揺れ検知点 (confirmed) ／ 長周期・区域 | ×1.45 |

つまり**ベース半径 32 が保証しているのは等倍付近まで**であり、倍率を上げれば必ず破れる。
上限まで滲ませないためにはベース半径を 3 倍側に合わせて焼き直す必要があるが、画像が 9 倍の面積に
なるため現状は採っていない。ベース半径を変えるときはこのトレードオフを踏まえること。

#### フチ・余白の比例（`lpgmIcons.ts` のみ）

ベース半径を変えると、余白・フチの線幅・角丸・影のにじみを固定 px で持っている限り、縮小表示した
ときのフチや影の太さが変わってしまう。`gl/lpgmIcons.ts` はベース半径を 16→32 に上げた際、この 4 つ
（`PADDING`・`STROKE_WIDTH`・`CORNER_RADIUS`・`SHADOW_BLUR`）をベース半径への比率で持つようにした。
表示時の太さは「画像上の px × `icon-size`」で決まるので、ベース半径と同じ倍率で増やせば相殺されて
見た目が変わらない。

**`gl/intensityIcons.ts`・`gl/kyoshinDetectedIcons.ts` は 4 つとも固定 px のまま**（`PADDING = 8`・
`lineWidth = 2`・`CONFIRMED_RING_WIDTH = 4`・`shadowBlur = 3`）。これらのベース半径を変えるときは、
先に同じ比例化を入れないと見た目が変わる。


## 16. 深さを持つ点（地下の描画）

震源のように**深さを持つもの**は `gl/depthPointLayer.ts`（カスタムレイヤー）で描く。DOM マーカー
（`maplibregl.Marker`）は地表にしか置けないため、地下を扱う描画物はすべてここへ乗せる。長期震源
カタログの点群も同じ仕組みを使う想定で、**点の数に依存しない作り**にしてある（頂点バッファ 1 本と
`drawArrays` 1 回。判定も後述のカラーピッキングで点数に依らない）。

**深さ方向の誇張率は設定で変えられる**（設定タブ「震源の深さの強調」＝ `hypocenterDepthScale`、
1〜20 倍）。水平方向は常に実スケールで、誇張は z にだけ掛ける。

### 地下の点が消える 2 つの理由 — クリップ空間の z を自前で決める

**平面（Mercator）: MapLibre の far が地下を含まない。** `mercator_transform.ts` の計算は
`farZ = (cos(π/2 − pitch) × topHalfMinDistance + lowestPlane) × 1.01` で、**傾き 0 では第 1 項が
消える**（`cos(π/2) = 0`）。残るのは地表までの距離の 1.01 倍だけになる。zoom 7・緯度 37.5 での実測:

| pitch | far の余裕 | 地下を描ける深さ |
|---|---|---|
| 0 | 1.010 倍 | 3.3 km |
| 10 | 1.073 | 24.1 km |
| 30 | 1.251 | 82.8 km |
| 45 | 1.515 | 170.1 km |
| 60 | 2.390 | 459.1 km |

**球（globe）: 地表のタイルが深度を書き込む**（裏側の半球を隠すため）。素直に描くと、地下の点は
手前に見えている地面に隠されて 1 ピクセルも出ない。**far で切られることはない。** 中心 137.3E37.5N・
pitch 45 で両投影の `args.farZ`（MapLibre が渡す視点空間の距離。尺度は画面 px と同じ）を測ると:

| zoom | 球の far | 平面の far |
|---|---|---|
| 4 | 4734 | 2193 |
| 6 | 14595 | 2193 |
| 8 | 54036 | 2193 |
| 10 | 211803 | 2193 |
| 12 | （平面へ切り替わる） | 2193 |

**平面の far はズームに依らず一定**（傾きと画面の高さだけで決まる。上の表の pitch 依存はこのため）。
一方**球の far はズームに比例して広がる**（球全体を収める必要があるため）。球が使われる帯では
つねに平面より広く、深さ 700km 相当（zoom 6・緯度 37.5 で 721 px）に対しても余る。

どちらも「クリップ空間の z を自前で決める」ことで解ける。**手前の薄い帯へ写し、帯の中の位置は
カメラからの距離で決める**（`float slabZ(float w)` と `depthSlabRange`）。点どうしの前後関係は
保ったまま、地図の描画物より必ず手前になる。透視投影では `w_clip = −z_view` なので距離は `w` から
取れ、これは球の射影行列でも成り立つ（どちらも最後は透視変換のため）。

- 帯の厚み（`DEPTH_SLAB` = 0.02）は薄いほど隠されにくく、厚いほど前後関係を細かく表せる。0.02 なら
  24bit の深度バッファで 33 万段階が残り、長期震源カタログの 101 万点でも実用上ぶつからない
- 距離の範囲は near から far までで、**そのレイヤーが描く最深点までのぶんだけ far を広げる**
  （`FAR_MARGIN`）。広げないと、深い点がすべて帯の奥端に貼り付いて前後関係が潰れる
- **帯の中の位置は下限を丸めない。** near より手前の点は帯の外（z < −1）へ出て GPU に破棄される。
  0 で丸めると、破棄される代わりに近クリップ面へ貼り付いて描かれてしまう

### 球では地球の中心を越えさせない

MapLibre は球面上の点を `spherePos × (1 + elevation ÷ GLOBE_RADIUS)` で置く（`GLOBE_RADIUS` は
6371008.8）。**elevation が −GLOBE_RADIUS を下回ると係数が負になり、点は地球の反対側へ写る。**
地表の震央だけ正しい位置に残り、震源だけがあり得ない場所へ飛ぶ形になる。

これは机上の話ではない。**深さ 700km 級の深発地震に「震源の深さの強調」10 倍を掛けるだけで届く**
（700 × 10 = 7000 > 6371）。設定の上限は 20 倍なので、余裕をもって越える。`elevationForProjection`
が地球半径の 0.95 倍で止める（`clampElevationForGlobe` が同じ計算の JS 側の双子で、境界を
単体テストで固定している）。

平面（Mercator）側には同じ構造が無い。深さは Mercator 座標系の z へ換算され（分母が赤道全周＝
4000 万 m）、深くすればどこまでも下へ伸びるだけで符号は反転しない。

**`transform.overrideNearFarZ()` で地図全体の far を伸ばしてはならない。** これは公開 API だが
（`ITransform` に載っている）、**地図全体の深度精度が落ちて他のレイヤーが z-fighting を起こす**。
シェーダー側で決めれば影響はこのレイヤーに閉じる。

**表示用と判定用の両方に同じ計算を入れること。** 片方だけだと、見えている点をクリックできない
（あるいはその逆）という食い違いが出る。柄（縦線）も同じ。補助の点を隠す条件（後述）も両方へ入れる——
見えていないものがクリックできると、点ごとに内容を出し分けたときに誤った結果を返す。実装では
頂点シェーダーの共通部分（`SHARED_VERT`）に置いて、3 つのプログラムが必ず同じ式を使うようにしている。

### 球の裏側にある点は透けたまま残す

**深さを持つ点だけは、地球の裏側へ回っても消えない。これは残す。**

MapLibre の球シェーダーには投影関数が 2 系統ある。水平線のクリッピングを掛けるのは
`projectTile` / `projectTileWithElevation` で、`globeComputeClippingZ` が z を書き、裏側の点は
`z/w > 1` になって捨てられる。深さを持つ点が使う `projectTileFor3D` はこれを掛けない。加えて
このレイヤー自身が z を帯へ書き換えるため、仮に掛かっていても打ち消す。

**ほかのレイヤーは裏へ回れば見えなくなるが、消え方は 2 通りある。** 県境・一次細分区域・予報円
（fill / line / circle）は上の z がそのまま効き、GPU がプリミティブごと捨てる。震度バッジ・検知点・
地名ラベル（symbol）は**配置計算の側**で消える——`isLocationOccluded` が同じクリッピング平面で
裏側を判定し、フェード不透明度を 0 にする。**symbol の頂点シェーダーに `globeComputeClippingZ` は
出てこない**ので、機構を追うなら配置側を見ること。

**残す理由**: 遠地地震の震源は日本と同じ視野に入らない。南米で起きた地震を地図に出しても、日本を
画面に収めたままでは、その震源はまず球の裏側になる（日本の対蹠点が南米沖にあたる）。透けて見える
ほうが、震源がどこにあるかを掴める。

**低ズームのときだけの話ではない。** 対蹠点はカメラの視軸上に乗るため、傾き 0 なら**ズームに
よらず画面の中央へ投影される**。引けば見える・寄れば見えない、という性質のものではない。

前後関係とクリック判定はこれで壊れない。帯の中の位置はカメラからの距離（`w`）で決めるので、手前の
点は裏側の点より前に描かれる。判定は表示と同じ頂点計算を通すため、見えているものは掴めるし、掴める
ものは見えている。**帯の奥端で飽和して前後関係が潰れることも無い。** `slabZ` は `min(…, 1.0)` で
頭打ちにするが、MapLibre は球の far を `cameraToCenterDistance + globeRadiusPixels × 2` と置いており
（そうしないと球自身が far で切られる）、これは**対蹠点までの距離そのもの**。球の上と内側の点は
すべてこれ以下に収まり、こちらはさらに `FAR_MARGIN` ぶん広げている。

**裏を消す方へ転じるなら、可視面の判定は震央（地表）の位置で行うこと。** 地下の点は球の内側にある
ため、地表向けの判定を点そのものの座標へ当てると、**手前にある深い震源まで消える**。

### クリック判定 — カラーピッキング

MapLibre はカスタムレイヤーが何を描いたかを知らないため、`queryRenderedFeatures` に**一切ヒット
しない**。そこで各点に通し番号を振り、その番号を色として画面外のバッファへ描き、クリック位置の
1 ピクセルを読んで番号へ戻す。**表示と同じ頂点計算を使う**ので、傾き・回転・誇張率が自動的に一致する。

- **判定は描画ループの中で解く。** MapLibre と WebGL の状態を共有しているため、ループの外から
  フレームバッファを触ると内部のキャッシュと食い違う。`pick()` は直近の結果を返し、座標が変われば
  次のフレームぶんを予約する
- **未解決は `'pending'` として返す。`null`（何も無い）と区別すること。** マウスは `mousemove` が
  先に来るので解決済みになるが、**タッチは指が触れた瞬間が最初の入力**で、そこで `null` を返すと
  1 回目が必ず空振りする。`popupRegistry` は**クリックもホバーも**数フレームだけ聞き直す
  （`CLICK_PICK_RETRY_FRAMES`）。**ホバーを「次の `mousemove` で解ける」に任せてはいけない**——
  目的の点でマウスを止めると次のイベントが来ず、解決済みの値を読む機会が永久に来ない。ただし
  未解決の間はカーソルも吹き出しも触らないこと。消すと 1 フレームの遅れが明滅として見える
- **予約の枠は 1 つしかない。クリックの予約はホバーに上書きさせない**（`forClick`）。トラックパッドの
  微動などでホバーが割り込むと、クリックが指した座標が一度も解かれずリトライを使い切る。
  ホバーには次の機会があるが、クリックは一度きり
- **判定のキャッシュはカメラが動いたら捨てる**（`cameraSignature`）。画面座標が同じでもカメラが動けば
  別の点が来る。このアプリは EEW 追従・揺れフォーカス・津波追従など**マウスを伴わずカメラが動く**経路を
  多く持つ（§6）ので、座標一致だけで使い回すと移動直後の最初のクリックが古い結果を返す
- 判定用の描画では**アンチエイリアスを掛けない**（色は番号そのもので、混ざると別の点に化ける）。
  小さい点を狙いやすいよう、判定用だけ `HIT_PAD_PX` ぶん太らせる

### 未解決: 点が近くになくても 1 フレーム待たせている

カラーピッキングは**座標が変わるたびに必ず 1 フレーム遅れる**。そして上位が未解決の間は下位優先度を
見ない（前述）ため、**震源が 1 つでも出ていると、そこから遠く離れた場所のホバーまで 1 フレーム遅れる**。
区域名・活断層線・ヒートマップのカーソル反応が、その分だけ鈍くなる。

手当ては「点の近くでなければ CPU 側で即座に `null` を返す」粗い足切り（点群のスクリーン空間 bbox や
格子索引）だが、**これは長期震源カタログの点群を載せるときに必ず要る仕組みと同じもの**。
震源 1 点のために先に作るより、点群の設計と一緒に決める方が形が整う。

同じ理由で、**現状の「点数に依存しない」は描画についてのみ成り立つ**。判定はマウスが動くたびに
全頂点を処理するので、101 万点では素通しにできない。

### EEW の震源も同じ仕組みで置く

地震情報の震源と EEW の震源は、どちらも `gl/depthPointLayer.ts` で描く（レイヤーは別々）。
かつて EEW だけが DOM マーカーで地表に貼り付いており、**同じ種類のものが片方だけ深さを持つ**
非対称があった。

- **仮定震源要素（単独観測点処理）は深さを採らない。** M・深さを画面から隠すのと同じ扱いで、
  地表に置く。採ると、確定していない数値を立体で断定して見せることになる
  （連動して隠す箇所の一覧は [`eew-spec.md`](eew-spec.md) §5）
- 点滅と不透明度はシェーダーで作る。CSS アニメーションから移した（下記）

### 点滅は「明・暗の 2 値」と「全点共通の位相」で作る

EEW の震源は点滅する。値は 2 組（確定は 1 ↔ 0.1、仮定は 0.9 ↔ 0.45）で、点ごとの不透明度と
**掛け合わさる**。片方だけ動かすと点滅の谷で消えるため、掛け算は 1 箇所に閉じている
（`alphaPair`。積の関係は `EewEpicentersGL.test.ts` が固定）。

- **位相は全点で共通の時計から決める**（`blinkPhaseAt`）。点ごとに持たせるとばらばらに明滅して
  騒がしい。また、**電文の到着で位相を作り直さないこと**——続報は 1 秒前後で届き周期（1.2 秒）より
  短いため、濃い側に留まったまま＝点滅が止まって見える
- **判定（クリック）は明滅を見ない。** 暗い側の位相でも掴めないと、狙って押せない
- **再描画は位相が変わる瞬間にだけ予約する。** MapLibre は変化が無ければ描き直さないので何もしないと
  点滅が止まるが、毎フレーム要求すると 1 秒に 2 回しか変わらない値のために 60fps で回し続けることに
  なる（CSS アニメーションは無償だったので、そのまま置き換えると劣化する）
- 柄は点と同じ明滅に乗せる。別々に動かすと繋がって見えない

### 補助の点と柄

震源には震央（地表）の印と、その間を結ぶ縦線（柄）を添える。**柄が短くなって主役と重なる状況では、
震央の印ごと隠す**（`auxiliary` と `MIN_STEM_PX`）。判定は柄の画面上の長さで行う。

```
柄の長さ = 深さ × 誇張率 ÷ (m/px) × sin(pitch)
```

この 1 つの式で「真上に近い」「震源が浅い」「誇張率が低い」の 3 通りが同じ条件に落ちる。**傾きだけで
判定してはならない**——深さ 2km の地震は傾き 60 度でも柄が 13px しかなく、丸と × が重なったまま残る。

柄は点より**先に**描く（後だと線が × 印の上を横切る）。
