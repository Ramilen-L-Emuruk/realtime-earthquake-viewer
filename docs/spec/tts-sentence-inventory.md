# 読み上げ文の棚卸し

読み上げ文を触る開発者向け。**この文書は、アプリが組み立てている読み上げ文を 1 つずつ並べ、
文型（助詞・述語・語順）が揃っていない箇所を挙げたもの。** 揃え方は決めていない ——
「どこが揃っていないか」を先に見えるようにするための一覧。

読み上げの規則そのもの（何を読むか・どの語で読むか・いつ読むか）は
[`audio-tts-spec.md`](audio-tts-spec.md) §4 が単一情報源。実装と食い違う場合は実コードを正とする。

下表で言う**断片列**は、読み上げ文に「どの語がどの区域・観測点・事実を指すか」の印を付けたまま
分割して持つ形（`SpeechSegment[]`）。文字列版は断片列を連結しただけで、文面は変わらない
（用途は [`audio-tts-spec.md`](audio-tts-spec.md) §4「主要関数」）。

## 1. 出どころの型

読み上げ文の材料は 4 通りに分かれる。**型によって直せる範囲が違う** ——
電文の文をそのまま読んでいる箇所は、アプリ側で言い回しを揃えられない。

| 型 | 意味 | 例 |
|---|---|---|
| **アプリ** | 文言がすべてコード側にある。震源名・波高などの**値**を差し込むものも含む | 「地震情報。15時4分頃、」 |
| **電文** | 電文の**文**をそのまま声にする。加工は句点の補いなど最小限 | 取消の理由（`Body/Text`） |
| **混在** | 1 つの関数の中で、アプリの定型句と電文の文を接続する | 「地震情報は取り消されました。」＋電文の理由 |
| **フォールバック** | 原則は定型文。既知の表に無い値だけ電文を軽く整えて読む | 規模の説明（`magnitudeCondition`） |

**値の差し込みは「アプリ」に数える。** 震源名・区域名・波高・号数は文ではなく値で、
どう並べるかはアプリが決めているため。**見出し文・付加文・取消の理由は「電文」**
—— 気象庁が書いた文をそのまま流している。

## 2. 調べた範囲と手順

### 範囲

読み上げへ渡る文字列の出どころは 3 つ。

1. `src/utils/ttsText.ts`（定義 105 件。うち `function` / `const` が 99、`type` / `interface` が 6）
2. `src/hooks/useLiveEventHandler.ts` の `plain('津波観測情報。')` **1 箇所** ——
   波高の文が無い津波観測情報（到達確認・欠測・警報相当だけの報）で名乗りを足すもの
3. `src/components/SettingsTab/index.tsx` の VOICEVOX 試聴ボタン **1 箇所** ——
   設定を確かめるための固定文で、電文を受け取って読む文ではない。**一覧には載せるが、
   実運用の文型と食い違っている**（→ §4-9）

### 手順

**「見つからなかった」と「見ていない」を分けるため、機械的に数え上げてから目視で補正した。**

1. 読み上げの入口をすべて列挙する。**入口は 2 段ある。**
   - 読み上げの待ち合わせを通る経路 —— `speakNonEEW` / `speakNonEEWDelayed` / `chainEEWSpeech` /
     `scheduleSpeech` への呼び出しを全文検索し、渡している引数を 1 件ずつ確かめた（10 + 3 箇所）。
     いずれも `ttsText.ts` の関数の戻り値か、それを `joinSegments` で連結したもの
   - **待ち合わせを通らず直接合成する経路** —— `speakWithVoicevox` の呼び出しを全文検索した。
     設定タブの試聴ボタン 1 件だけが、`ttsText.ts` を経由せず文字列リテラルを直接渡している
2. `ttsText.ts` の外に組み立てが無いかを確かめる。`plain(...)` に日本語を渡している箇所を
   `src` 全体（テストを除く）で検索 → `useLiveEventHandler.ts` の 1 箇所のみ。
   **この検索式だけでは足りない** —— `plain()` を経由しない生の文字列は捕まらないので、
   手順 1 の 2 段目が要る
3. `ttsText.ts` の全 2236 行を通読する
4. 3 の結果を機械判定と突き合わせる。コメントを除いたうえで**文字列リテラルの中に日本語を
   含む定義**を数えると 52 件、含まないものが 47 件
5. 一覧に載せた名前と、実装に存在する定義を突き合わせる。**一覧 56 件＋下記「一覧に載せて
   いないもの」35 件＋文字列版 8 件 = 99 件**で、`ttsText.ts` の `function` / `const` の総数と
   一致する（どちらにも現れない定義 0 件・実装に無い名前 0 件）

### 機械判定だけでは足りない点

**判定の取りこぼしを 2 種類確認した。数字をそのまま信じないこと。**

- **読点・中黒（U+3000〜303F）を日本語に数えるかで結果が変わる。** 数えないと 50 件、数えると
  52 件。増える 2 件（`areaNameSegments`・`observationDetailSegments`）は、区域名・観測点名を
  読点だけで連結する関数で、**文の組み立てそのもの**を担っている
- **日本語リテラルを持たないのに文を組む定義がある。** 他のモジュールの語（`tsunamiGradeLabel`
  → `TSUNAMI_GRADE_SHORT_LABEL`・`intensityText` → `getIntensityLabel`）を引くもの、
  断片列を作る関数をラップするもの（`maxScaleOnlySegments`・`domesticTsunamiSegment`）、
  断片列を連結するだけの文字列版（`earthquakeToText` ほか 8 件）がこれに当たる

**逆向きの取りこぼし（日本語リテラルはあるが文ではない）もある。** ログの文言
（`magnitudeConditionSentence`・`heightPhrase`・`earthquakeCountToText`）、電文の語との
照合値（`CANCEL_DECLARATION_SUBJECTS`・`domesticTsunamiText` の `case` ラベル・
`earthquakeCountToText` の `'累積'`）。これらは一覧の判断には使っていない。

## 3. 一覧

「揃っていない点」の欄は 4 通りに読む。

| 書き方 | 意味 |
|---|---|
| 空欄 | 他と食い違わない |
| **（意図的）** | 実装のコメントか仕様書に理由が書かれている。**揃える対象から外す** |
| **→ §4-N** | 他の経路と並べて §4 で扱う |
| 上記のいずれでもない | **理由を探したが、実装にも仕様書にも見つからなかった**（一部の行はその旨を明記している） |

## 4. 揃っていない点

**重いものから並べた。** 直し方は決めていない。

**解消した項は見出しに「（解消済み）」と付けて残す。番号は詰めない** —— 他の文書やコードの
コメントがこの番号で参照しているため。**上の「重い順」には数えない。**

### 4-1. ごく浅いのときだけ、震源要素更新の深さの語形が 2 通りになる

> **文が壊れていた件は 2026-09-12 に直した。**

語形が 2 通りに分かれる理由は [`audio-tts-spec.md`](audio-tts-spec.md) §4「特殊な扱い」の震源深さが
単一情報源。ここに置くのは棚卸しで実測した結果だけ。

| 深さ | 規模 | 出力 |
|---|---|---|
| 0 | なし | 「…について、震源の深さはごく浅い場所に更新されました。」 |
| 0 | 7.1 | 「…について、震源の深さはごく浅く、マグニチュード7.1に更新されました。」 |
| 120 | なし | 「…について、震源の深さ120キロメートルに更新されました。」 |
| 120 | 7.1 | 「…について、震源の深さ120キロメートル、マグニチュード7.1に更新されました。」 |

**直す前は 1 行目が「震源の深さはごく浅くに更新されました。」だった。**

**この組み合わせは実配信では観測できていない。** DM-D.S.S のアーカイブに 2024-01-01〜2026-09-12 を
指定し、返ってきた **975 日**（この範囲の暦日は 986 日。地震の電文が 1 通も無い日はアーカイブ自体が
無く、11 日ぶん欠ける）を全部読むと震源要素更新は 51 通あり、**深さがごく浅いものは 0 通、規模が
数値にならないものも 0 通**だった（最も浅いもので 1km）。直したのは、起こりうる形に対して語形が
足りていなかったため。

### 4-2. 規模を語る形が 4 通りある

| 経路 | 形 |
|---|---|
| 初報の句（`magnitudePhrase`） | 「マグニチュード7.1の」（助詞なし・連体修飾） |
| 数値にならないとき（`magnitudeConditionSentence`） | 「マグニチュードは8を超える巨大地震とみられます。」（「は」・独立した文） |
| 続報の言い直し（`changedFactSegments`） | 「マグニチュードは7.1に更新されました。」（「は」） |
| 震源要素更新（`earthquakeToSegments`） | 「マグニチュード7.1に更新されました。」（助詞なし） |

後ろ 2 つは**同じ「更新された」を伝えるのに助詞が違う**。ただし**揃えられない** ——
震源要素更新は「震源の深さ120キロメートル、マグニチュード7.1に更新されました。」という
**列挙**で、途中の項目に「は」を付けると列挙が壊れる。続報の言い直しは 1 事実ずつの独立した文で、
主題を示す「は」が要る。同じ構文の中で分かれているわけではない。

2 つ目（`magnitudeConditionSentence`）には**続報用の形が増えた**（2026-09-13。→ §4-5）。
「マグニチュードが更新されました。8を超える巨大地震とみられます。」で、**主題部だけが
差し替わる** —— 値を「〜に更新されました」の枠へ入れると、マグニチュード（数値）を
地震（出来事）へ更新することになり破綻するため。

### 4-3. 深さを語る形が 3 通りある

| 関数 | 形 |
|---|---|
| `depthSourcePhrase` | 「深さ120キロメートル」（「〜を震源とする」の前） |
| `depthUpdateValue` | 「120キロメートル」（「震源の深さは〜に更新されました」の中） |
| `depthAmendPhrase` | 「震源の深さ120キロメートル」（「〜に更新されました」の前。ごく浅いは → §4-1） |

「震源の深さ」という語を、付ける／付けないが経路で分かれている。

### 4-4. 時刻の導入句が 4 通りある

| 経路 | 形 |
|---|---|
| 地震情報・震源情報 | 「15時4分頃、」 |
| 遠地地震 | 「10日15時4分頃、」（**日から読む**） |
| 震源要素更新 | 「15時4分頃発生した〈震源名〉の地震について、」 |
| 長周期地震動 | 「15時4分頃発生した地震で、」 |
| 推計震度分布図 | 「15時4分頃発生した地震について、」 |

後ろ 3 つのうち、震源要素更新と長周期地震動は震源名の有無だけが違うのに助詞も「について」「で」で
分かれている。推計震度分布図は 2026-09-13 に足したもので、名詞句は長周期地震動と同じ・助詞は
震源要素更新と同じ —— **助詞は述語で決まる**（「〜で観測しました」は地震が観測の場、
「〜について受信しました」は地震が話題）ので、この 2 つは揃えられない。
遠地地震が日から読むのは、発表が発生から数十分後になり日をまたぎうるため（意図的）。

### 4-5. 規模が数値にならない続報では「更新」が語られなかった（解消済み）

`changedFactSegments` は、規模が数値なら「マグニチュードは7.1に更新されました。」と言うが、
数値にならない場合は初報と同じ「マグニチュードは8を超える巨大地震とみられます。」へ落ちていた。
**値が変わったことが声にならず、しかも最大級の地震でだけそうなる。** 震源名・深さ・津波区分には
同じ逃げ道が無い。

**2026-09-13 に直した。** 値を「〜に更新されました」の枠へ入れるのではなく、**主題部だけを
差し替える**。

| | 文 |
|---|---|
| 初報 | 「マグニチュードは8を超える巨大地震とみられます。」 |
| 続報（値が変わった） | 「マグニチュードが更新されました。8を超える巨大地震とみられます。」 |

「マグニチュードは8を超える巨大地震に更新されました。」は採らない —— マグニチュード（数値）を
地震（出来事）へ更新することになる。述部を主題抜きで持つことで、「Ｍ不明」も未知の表記も
同じ形で通る（「マグニチュードが更新されました。不明です。」）。

**震源要素更新（VXSE61）は初報の形のまま。** 名乗りと直前の文が既に「更新」を言っているので、
続報の形を持ち込むと 1 回の発話で「更新」が 3 度重なる。

### 4-6. 取消の述語が「キャンセル」と「取り消し」で割れていた（解消済み）

**同じ「取消」を伝えるのに 2 通りの述語があった。**

| 種別 | 述語（〜2026-09-12） |
|---|---|
| 緊急地震速報・地震情報・長周期地震動 | 「キャンセルされました」 |
| 津波（`retracted`）・南海トラフ臨時情報・地震回数に関する情報 | 「取り消されました」 |

気象庁が使う語は「取消」。[CLAUDE.md](../../CLAUDE.md)「利用者へ出す語を気象庁の表現と揃える」に
照らすと、前者が外れていた。**外している理由はどこにも書かれていなかった。**

**2026-09-13 に「取り消されました」へそろえた。** 決め手は**画面が既にそう書いていた**こと ——
取消のオーバーレイは大きな見出しこそ「キャンセル」だが、その下の文は「この地震情報は
取り消されました」「この緊急地震速報は取り消されました」。読み上げだけが取り残されていた
（→ [audio-tts-spec.md](audio-tts-spec.md) §4）。

> 見出しの「キャンセル」はスタンプにあたる 1 語で、文ではない。ここでは触っていない。

**津波はさらに 2 つの終わり方を持つ。** こちらは取消とは別の事象なので、述語が違うこと自体は
正しい。**終わり方 3 つを 1 つの関数（`tsunamiCancelToText`）が返す**ため、上の表だけを見て
一括で書き換えると巻き込む（そうしていないことをテストで固定してある）。

| 終わり方 | 述語 |
|---|---|
| 解除（既定） | 「津波警報等は全て解除されました。」 |
| 失効（`expired`） | 「津波予報の有効期間が終了しました。」 |

### 4-7. 津波の等級を伝える述語が 2 通りある

「発表されました」（新規発表・前回が `Unknown` の区域変化）と「発表されています」
（引き下げ・上位等級より下の等級）。**新しく出たものは「されました」、既に出ているものは
「されています」という使い分けに見えるが、その規則は書かれていない。**

### 4-8. 電文の文を読む 4 箇所で、前後の区切りが揃っていない

| 箇所 | 電文の文をどう置くか |
|---|---|
| 取消の理由 | 定型文の直後に置き、句点が無ければ足す |
| 遠地地震の付加文 | 震源の句の直後にそのまま置く |
| 津波観測情報の見出し文 | 名乗り「津波観測情報。」の直後にそのまま置く（区切りの語なし） |
| 後発地震注意情報の見出し文 | 名乗りの直後に置き、句点を足す |

**句点を足すのは 2 箇所だけ**で、他の 2 箇所は電文が句点で終わっている前提になっている。

### 4-9. 設定タブの試聴文が、実運用の緊急地震速報と別の文型になっていた（解消済み）

VOICEVOX 試聴ボタンが読ませていたのは次の一文で、文字列を直接書いていた。

> 緊急地震速報。三陸沖を震源とするマグニチュード7.2の地震が発生しました。予想最大震度6強。

震源の言い方は**地震情報の文型**（`quakeOccurrenceSegments`）で、緊急地震速報はこの形を持たない。
実運用は「緊急地震速報、三陸沖で地震。」「予想最大震度6強。」を別々に鳴らす。

現在は実運用と同じ関数から組んでいる。**要点は「文字列を直接書かないこと」** ——
書けば、文型を変えたときに試聴だけ古い形で残る。詳細は
[`audio-tts-spec.md`](audio-tts-spec.md) §3「試聴で読ませる文」。

### 4-10. 波高が付いていない津波の発表で等級名を 2 回言う（意図的として確定）

`tsunamiToSegments` の波高なし経路は「大津波警報。〈区域〉に大津波警報が発表されました。」と、
名乗りと本文で同じ等級名を読む。波高がある経路は「大津波警報が発表されました。」の一文が
名乗りを兼ねるので重複しない。

**この重複は、等級を先頭で伝えるための代償として受け入れる**（2026-09-13 に確定）。日本語では
「〈区域〉に発表されました」と区域が述語の前に来るため、頭の名乗りを外すと**等級が判るまで
区域名を全部聞くことになる**（予報区が多いほど遅れる）。等級と行動を先に言い切るのは波高あり
経路の設計でもあり、そちらへ揃えるほうが正しい。理由は実装（`tsunamiToSegments` の波高なし
経路のコメント）にも置いてある。

### 4-11. 名乗りの継ぎ方が読点と句点で割れている

**名乗りの後ろに短い語（震源名・段階名・号数）を足す種別は読点で継ぎ、それ以外は句点で切る。**
どちらを使うかは種別ごとに決まっているが、**同じ関数の中で分かれるものが 2 つある。**

| 継ぎ方 | 種別 |
|---|---|
| 読点 | 緊急地震速報（「緊急地震速報、〈震源名〉で地震。」）／南海トラフ臨時情報の 4 段階（「南海トラフ地震臨時情報、調査中。」）／南海トラフ関連解説情報の**臨時解説**（「南海トラフ地震関連解説情報、第1号。」） |
| 句点 | 地震情報・震度速報・震源要素更新・遠地地震・長周期地震動・津波観測情報・地震回数に関する情報・後発地震注意情報／南海トラフ臨時情報の**フォールバック**／南海トラフ関連解説情報の**定例解説** |
| 名乗りを文の中に入れる | 推計震度分布図（意図的）／**取消・解除の文はすべてこの形**（「〈情報名〉は取り消されました。」「津波警報等は全て解除されました。」） |

`nankaiToText` と `nankaiCommentaryToText` は、**同じ種別なのに報の内容で継ぎ方が変わる**
（段階や号数を持つ報は読点、持たない報は句点）。継ぐ語がある／無いで分かれているとも読めるが、
**その規則は書かれていない。**

## 5. 意図的に揃えていないもの

**下記は揃える対象から外すこと。** 実装のコメントか仕様書に理由が書かれている。
**§3 の表で「（意図的）」と注記した箇所も同じ扱い** —— こちらへ重ねて並べていないだけで、
外す対象に含む。

| 箇所 | 理由の置き場所 |
|---|---|
| 場所の助詞「で」を文末（述語の直前）にだけ置く | `buildRegionSegments` の `toSentence` |
| 未入電を「では、」で主題化し、述語を「観測しました」から分ける | `unreceivedRegionSegments` |
| 欠測を「は」、観測できた分を「で」で言い分ける | `tsunamiMissingToSegments` |
| 読み上げから外した地点数の助詞を述語で切り替える | `omittedPointsSentence` |
| 話題の変わり目を「また、」で継ぐ | `joinWithAlso`、[`audio-tts-spec.md`](audio-tts-spec.md) §4 |
| EEW の切り出しを 3 通りに固定し、句読点で終わらせる（起動時に合成して持っておく単位に合わせる） | `EEW_LEAD_PHRASE`、[`audio-tts-spec.md`](audio-tts-spec.md) §6 |
