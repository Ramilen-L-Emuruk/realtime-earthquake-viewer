# 強震モニタ揺れ検知 V3 設計書（近傍一致・PLUM 型）

V2（`kyoshinDetector.ts`：波面フィット＋リーキー積分＋逆投影系）を置き換える、**震源非依存の近傍一致検知**の設計。
JMA EEW（PLUM 法・着未着法）と Scratch 前身「リアルタイム地震ビューアー」の検知方式の調査から収束した結論に基づく。

> 関連: V2 設計書 `kyoshin-detection-design.md`。本書は検知コアの全面刷新であり、V2 コアを置換する。
> UI・音・自動タブ切替・自動フィット・地図オーバーレイ（`useKyoshinAlerts` / `deriveKyoshinView` /
> `RealtimeTab` / `KyoshinV2Overlay`）は V2 移行時（commit 3e02a27）のものを**流用**する。

## 1. 背景：なぜ作り替えるか

V2 は「波面フィットで震源を決め、その品質を時間積分して確信度を出す」設計だった。これが次の壁を生んだ:

- **Kanto の壁**: 弱い震度1の実地震（埼玉）と北関東の間欠ノイズが per-cluster 特徴（規模・振幅・連続性）で分離できない。
- **確定レイテンシ**: リーキー積分が S_ON まで登るのに 5〜6 秒。V1 の「2 連続フレーム確定」より遅い。
- **明滅**: クラスタ急成長中に波面フィットが一時破綻（fitOk=false）→ confirmed→weak へ転落→再確定（解除→再検知）。
- **分裂**: 1 地震が震央ジッタ・フィット失敗で複数イベント ID に割れる。
- **warmup**: LTA ベースラインが 60 秒間落ち着かず、コールドスタート直後は confirmed を出せない。

これらに band-aid（fast-confirm・片側拡張・連続性免除・確定ラッチ）を重ねたが、緩めるほど北関東の誤検知が出る堂々巡りになった。

## 2. 調査からの収束（JMA / Scratch 前身）

| | JMA（実物） | Scratch（前身） | V2（旧） |
|---|---|---|---|
| 検知の芯 | **PLUM**＝近傍観測点の実測震度で判定・震源不要 | **最短7点の近傍同時性**・震源不要 | 波面フィット＋積分＋逆投影 |
| ノイズ対策 | 着未着＋振幅分類 | **点別の静的しきい値**（1748点） | オンライン連続性ゲート |
| 震源 | IPF で別立て | EEW から（DM-D.S.S）別立て | 検知と一体化して破綻 |

**結論**: 検知から震源推定を切り離し、「**点別のノイズ床 ＋ 近傍同時性（PLUM 型の面）＋ 地域別の慢性活性ガード**」で検知する。
1 秒・計測震度という入力に最も噛み合い、Kanto の壁（**点別床＋地域活性の二軸**）・分裂（**近傍グラフ連結＋格子 ID**）・warmup（床は静的/長時定数＝LTA 追随不要）を原理から解消する。

## 3. 設計原則

1. **震源非依存**（source-free）: 検知の可否は「面として揺れが在り、近傍が同時に立ち上がったか」で決める。震源・波面フィットは検知に使わない（表示用の任意補助に降格）。
2. **点別の静的しきい値**: 観測点ごとに事前計算したノイズ床を持つ。ノイズの多い点（北関東・都市・火山）は自動的に鈍くなる。オンライン LTA を廃し **warmup を撤廃**。
3. **近傍同時性**: 点の検知は「その点の K 近傍のうち一定数が短時間窓で一緒に立ち上がった」ことを要件にする（PLUM／着未着の思想）。
4. **グループ化は近傍グラフ・格子は ID 専用**: イベントは K 近傍グラフの連結成分で束ねる（セル境界での分裂を避ける）。固定格子は安定 ID の錨としてのみ使う（同一地震が常に同一 ID）。
5. **速い・単純**: 強い per-frame 判別なので長い時間積分は不要。V1 相当（数秒）で確定。可動部を V2 より減らす。
6. **特異度は二軸で守る（単一防御にしない）**: (a) 点別のノイズ床（慢性的に騒がしい点を鈍く）＋ (b) セル別の慢性活性ガード（慢性活性な地域＝北関東等の確定バーを上げる）。北関東ノイズはコヒーレントに多点同時発火し得て近傍同時性(L2)を通過するため、床だけでは守れない。地域軸を独立に持つ（JMA の着未着＋振幅分類に相当する我々版の第2軸）。

## 4. 入力と制約

- 入力: Yahoo リアルタイム震度。約 1725 点・1 Hz・計測震度（`value = -3.0 + index*0.5`。震度0≈0.0）。
- サブ秒精度の到達時刻・P 波は無い。→ 波面フィット／到達時刻総当たりは原理的に不利（V2 で確認済み）。
- 観測点集合は `siteConfigId` で版が変わる。静的メタは**座標キー**（`siteKey(lat,lng)`）で引く。未知点は既定しきいで扱う。
- 純粋関数コア `step(state, frame, meta)` を維持。`meta` は静的（近傍・格子・任意の初期床 JSON）。点別床とセル慢性活性はオンライン学習で `state` 側（永続化対象）。

## 5. アーキテクチャ（層構成）

### L0 静的観測点メタ（オフライン事前計算・`meta`）

`public/data/` に JSON で持ち、初回に一度 fetch（生成データの遅延読込と同方式）。

- **点別しきい値 `siteThreshold[key]`**（計測震度 units）: 各点のノイズ床（ロバストな高分位点。例: 各点 `value` の 99 パーセンタイル）。Scratch の `ten:しきい` に相当。**取得は過剰リクエストを避ける**:
  - Yahoo の 1 リクエスト＝全 ~1725 点の 1 秒ぶん。床推定は点あたり数百〜2千サンプルで足りるので **~1〜2k フレーム（=~1〜2k リクエスト）を疎にサンプルした平常窓**で十分。**密な多日 1Hz 取得（10 万件超）は不要・不可**。この平常窓は検証（§10）で叩く窓と共用できる。
  - **本番はオンライン学習＋永続化が本命**（追加リクエスト 0）: ライブ受信 stream（既に 1 req/s 受信）から**長時定数（時間オーダー）の EWMA**で点別床を推定し localStorage に保存。V2 の LTA（45 秒）は追随が速すぎて慢性ノイズを捉えられなかったが、時間オーダーの時定数なら「その点が慢性的に騒がしい」を捉える。実イベント・群発で床が汚れ鈍化しないよう、床更新は **(i) 検知中の点・(ii) 近傍が同時活性の点で凍結**し、床に上限 `FLOOR_CAP` を設ける（改良4）。
  - コールドスタートは既定床 or 上記の小さな初期 JSON で開始し、稼働中に精緻化（→ warmup とは別。検知自体は初手から可能）。
  - 生成（初期 JSON・任意）: `scripts/build-station-thresholds.mjs`（疎サンプルのみ・スロットル付き）。
- **K 近傍 `neighbors[key]`**: 各点の最近傍 K 点（`R_km` 以内）。Scratch の「最短7点」に相当。
  - **生成は実行時**: `buildStationMeta(sites)` が受信中の実座標（Yahoo `sitelist.json`＝フレーム座標）から
    純粋な幾何計算で組む。近傍はメモリ上の座標から出せるため**追加リクエスト 0**。事前計算 JSON を出荷
    しないことで、`siteConfigId` 版差での `siteKey` ドリフト（JMA `station-coords` と Yahoo sitelist の
    不一致）を構造的に防ぐ。O(点数²) だが観測点集合ごとに一度だけ計算しキャッシュする（フレーム毎ではない）。
- **格子割当 `cellOf[key]`**: 各点が属する固定格子セル（緯度経度の等間隔ビン）。同じく `buildStationMeta` が実行時に算出。
- **セル別慢性活性 `cellActivity[cell]`**（オンライン学習・永続化・追加リクエスト 0）: 各固定格子セルが平常時にどれだけ「確定揺れ点」を出すかの長時定数の率。慢性活性セル（北関東等）で L4 の確定バーを上げる**第2の特異度軸**（§3-6・改良1）。

### L1 点トリガー（per-point, per-frame）

各点 `i` について:
- `level_i = value_i`
- `rate_i` = 直近 `RATE_DT`(2〜3s) での `value` 上昇量（1 フレーム差でなく**窓**で評価し、fetch ジッタ・欠測フレームを吸収。改良6）。
- **トリガー成立**: `level_i ≥ siteThreshold[i] + LEVEL_MARGIN` **かつ** `rate_i ≥ RATE_MIN`
  - level は「その点の床を超えたか」、rate は「今まさに立ち上がったか（オンセット）」。両者で持続ノイズと一過性を分ける。
- 欠測（`missing`）点はトリガー評価から除外し、`value` 履歴は最後の有効値で保持する。
- state: `triggeredAtMs[i]`（最終トリガー時刻）。`now − triggeredAtMs[i] ≤ TRIG_ACTIVE_MS` の間「トリガー継続」とみなす。

### L2 近傍同時性（core discriminator ＝ PLUM／着未着）

各トリガー継続点 `i` について:
- `agree_i` = K 近傍 `neighbors[i]` のうち `now − triggeredAtMs[neighbor] ≤ COINCIDENCE_MS` を満たす数。`avail_i` = `R_km` 以内に実在する近傍数。
- **「確定揺れ点（confirmed-shaking）」**: `agree_i ≥ MIN_NEIGHBORS` **または** `agree_i / max(avail_i,1) ≥ MIN_NEIGHBOR_FRAC`。
  - 実地震は点＋近傍が同時に立ち上がる。孤立・散在ノイズは近傍が揃わず脱落。
  - 疎地域（近傍が R_km 外・少数）は**割合条件**で救済し、離島・過疎網の小地震を取りこぼさない（改良5・§5-A 相当）。
- （Phase 2 任意・着未着精緻化）近傍のうち中心寄りが先に、外側が後にトリガーしている「外向き伝播」の整合を加点。1 秒量子化なので緩い判定に留める。Phase 1 では一致数のみ。

### L3 格子集約とイベント

- **グループ化＝K 近傍グラフの連結成分**（境界の無い方式。セル境界での分裂を避ける・改良3）。確定揺れ点どうしを近傍グラフで連結し、連結成分＝1 イベント。
- **ID 安定化＝固定格子（錨としてのみ）**。各成分に占有格子セル集合／重心セルで**安定 ID** を与え、前フレームとメンバー・セルが重なる成分は ID を継承。→ 分裂・明滅を構造的に防ぐ。
- **セル別慢性活性の更新**: 平常時に各セルが出す確定揺れ点率を長時定数で `cellActivity` に学習（実イベント中の該当セルは凍結）。
- イベント属性: メンバー確定揺れ点、占有セル、`maxIntensity`（メンバー現在 `value` 最大＝PLUM 出力）、初活性時刻、最終活性時刻。

### L4 確信度と発報

- **likely（可能性）**: 確定揺れ点 ≥ `MIN_LIKELY_POINTS`（例 3）**かつ** `maxIntensity ≥ MIN_LIKELY_INTENSITY`（例 震度1）。早期反応（候補音＋タブ）。
- **confirmed（検知）**: 確定揺れ点 ≥ `CONFIRM_POINTS`（例 5〜8・密度正規化＝改良5）**かつ** `maxIntensity ≥ MIN_CONFIRM_INTENSITY`（例 震度1、慢性活性セルは震度2）**かつ** `CONFIRM_FRAMES`（例 2）連続。→ V1 相当の速さで確定（積分待ちなし）。検知音＋タブ＋通知＋観測点フットプリントへ自動フィット。
- **震度ゲート（改良2）**: 低震度（震度0）の同時多発ノイズが点数だけで確定するのを防ぐ。JMA の発報基準（予報=震度3/警報=5弱）に倣った震度しきい。
- **地域活性バー（改良1・第2軸）**: `cellActivity` が高い（慢性活性）セルでは `CONFIRM_POINTS`・`MIN_CONFIRM_INTENSITY` を引き上げる。北関東のコヒーレントノイズが点別床をすり抜けても地域軸で受け止める。地域を名指しせず「慢性活性」で自動的に効く。
- **推定最大震度** = `maxIntensity` を震度階級へ。カード・音レベルに使用（`useKyoshinAlerts` のレベルアップ再鳴に供給）。
- **終了・保持**: セルが非活性化して `HOLD_MS`（例 10 秒）経過で解除（V1 相当の保持）。固定 ID なので明滅しない。
- **特異度＝二軸＋段階ゲート**: (a) 点別床（持続ノイズ）＋(b) セル別慢性活性（地域ノイズ）を独立軸に、L2 近傍同時性（散在排除）・点数集約（単点排除）・震度ゲート（低震度排除）を重ねる。単一防御にしない。

### L5 震源（任意・表示専用）

- 必要なら最早トリガー点近傍の重心を「推定震央（不確実）」として出す。**検知にも自動フィットにも使わない**（自動フィットはメンバー点のフットプリント）。深発・沖合は不確実として明示。

## 6. パラメータ初期値（ハーネスで較正）

| 記号 | 意味 | 初期値 |
|---|---|---|
| `LEVEL_MARGIN` | しきい床への上乗せ（value） | **0.0**（震度0 を含む・§13 参照。旧 0.5） |
| `SUSTAIN_MARGIN` | 継続揺れ判定の床上乗せ（継続点数・保持に使用・§13） | 0.4 |
| `RATE_MIN` | オンセット上昇量（value/RATE_DT） | 0.5 |
| `RATE_DT` | 上昇量の評価間隔 | 2〜3 s |
| `K` | 近傍点数 | **12**（密網での連結の穴を塞ぐ・§17 参照。旧 7） |
| `R_km` | 近傍半径 | 40 km |
| `MIN_CLUSTER` | 揺れクラスタに要する同期 onset 連結成分サイズ（§13。旧 MIN_NEIGHBORS） | 3 |
| `COINCIDENCE_MS` | 同期とみなす時間窓 | 4 s |
| `TRIG_ACTIVE_MS` | トリガー継続窓 | 8 s |
| セル寸法 | 固定格子 | 0.2°（≒ 20 km） |
| `MIN_LIKELY_POINTS` | likely 点数 | 3 |
| `CONFIRM_POINTS` | confirmed 点数（密な網の上限） | 5 |
| `CONFIRM_DENSITY_FRAC` | 確定点数の密度正規化（疎地域救済） | 0.6 |
| `CONFIRM_FRAMES` | confirmed 連続フレーム | 2 |
| `HIGH_CONFIRM_INTENSITY` | 高震度 fast path の震度下限（点数ゲート免除・§20） | 震度3（value 2.5） |
| `HIGH_CONFIRM_POINTS` | 高震度 fast path に要する高震度到達点数（§20） | 2 |
| `CONFIRM_INTENSE_POINTS` | confirmed に要する確定震度到達点数（単点強震ノイズ除去の第3軸・§18） | 2 |
| `EEW_CONFIRM_POINTS` | EEW（震源要素確定）発表中に `CONFIRM_POINTS` の代わりに使う確定点数（§19） | 3 |
| `EEW_CONFIRM_FRAMES` | EEW 発表中に `CONFIRM_FRAMES` の代わりに使う確定連続フレーム数（§19） | 1 |
| `MERGE_EVENT_KM` | イベント重心併合距離（分裂統合） | 100 km |
| `HOLD_MS` | 確定保持（confirmed のイベント存続） | 10 s |
| `LIKELY_HOLD_MS` | likely/faint のティア保持（§16） | 10 s |
| `MIN_LIKELY_INTENSITY` | likely の最大震度下限（未満は faint・§13） | 震度1（value 0.5） |
| `MIN_CONFIRM_INTENSITY` | confirmed の最大震度下限 | 震度1（慢性活性セルは震度2） |
| `FLOOR_CAP` | 点別床の上限（鈍化防止） | 要較正 |
| `cellActivity` 時定数 | セル慢性活性の学習 | 時間オーダー |
| 慢性活性セル閾値 | 確定バー引き上げの発動 | 要較正 |

> パラメータは少数に保ち、可能なら物理から決め打つ（`R_km` は観測点間隔から、`COINCIDENCE_MS` は S 波速度 × `R_km` から）。少数の検証イベントへの過学習を避けるため検証は事件数を増やす。

## 7. 状態・純粋性・永続化

- `state`: 点別の `value` 短時間履歴・`triggeredAtMs`、点別床 `siteThreshold`（オンライン学習ぶん）、`cellActivity`（セル慢性活性）、アクティブイベント（ID・セル・メンバー）、ID 採番。
- `meta`（静的・不変）: `neighbors` / `cellOf` / 任意の初期床 JSON。
- **warmup 撤廃**: 床は静的/長時定数なので LTA の落ち着き待ちが無い。コールドスタート直後から検知可（V2 の 60 秒問題が消える）。
- **永続化対象**: 点別床・`cellActivity`・アクティブイベント（localStorage）。これで再読込・5 時リロード後も学習済みの床/地域活性を保つ（追加リクエスト 0）。

## 8. 出力とUI配線（既存流用）

- コアは既存 `DetectionEvent` 互換の配列を返す（`波面フィット系フィールドは削除`、`maxIntensity` を追加）。
  - 保持: `id` / `confidence` / `memberKeys` / `originTimeMs` / `lastOnsetAtMs` / `maxIntensity`(旧 lastPeak) / `lastSize`。
  - 削除: `epicenter`（→ 任意・null 可）/ `bearingDeg` / `oneSided` / `lastFitOk` / `radialFitOk` / `lastContiguity` / `strongStreak` / `score`。
- `deriveKyoshinView` / `useKyoshinAlerts` / `RealtimeTab` / `KyoshinV2Overlay` は概ね流用。
  - `RealtimeTab` の震度ヒストグラムは memberKeys から集計（現行踏襲）。
  - 片側配置の方位表示・score 表示は削除（震源を出さないため）。オーバーレイは「メンバー点の外周（フットプリント）」＋任意の推定震央に変更。

## 9. 計算量

- L1: O(点数) = 1725/フレーム。L2: O(点数 × K) ≈ 12k/フレーム。L3: 連結成分は活性点のみ（平常時ほぼ 0）。
- V2 の `spatialFill`（メンバー毎に全点走査）より大幅に軽い。1 Hz で余裕。

## 10. 検証計画（ハーネス `window.__fold`）

- **特異度**: 平常窓（北関東 12:00 / 03:00 / 14:30 / 18:00 ほか）で confirmed 0。**特に V2 の band-aid を壊した北関東コヒーレントバースト（[36.1,140.3] 型・震度1・9〜12点同時）を専用テストに据える**（点別床＋地域活性の二軸で 0 を確認）。
- **感度・速度**: 埼玉 M2.0 震度1 / 長野 M3.2 / 大隅 M5.2（沖）/ 福島沖 / 深発 / 疎地域（奄美・離島）などで、ネットワーク到達から数秒以内に confirmed・1 イベント・明滅なし。事件数を増やし過学習を避ける。
- **回帰**: 同時多発（離れた 2 地震）が別 ID に分離。**セル境界をまたぐ地震が 1 イベントに保たれる**（近傍グラフ連結・改良3）。
- 較正順: 床分位点/FLOOR_CAP → RATE_MIN → MIN_NEIGHBORS・MIN_NEIGHBOR_FRAC・COINCIDENCE_MS → CONFIRM_POINTS・震度ゲート → cellActivity 閾値。

### 10.1 実データ検証結果（2026-07-24・初回）

- **感度・速度・非分裂・非明滅 ◎**: 福島県沖 2026-07-22 20:11（震度2・沖）を正のコントロールにリプレイ →

## 13. spread 型への改訂（2026-07-24・判別軸を「同期 onset の空間的広がり」へ）

**動機**: §10.3 で 紀伊水道 M3.2 震度2 が非検知だった件を精査すると、単点ではなく **3局が時間差で同時反応**していた
（実質2局同時）。旧 L2 の per-point「K 近傍のうち agree≥3」は時間差 onset・密な網（agree≤2）で取りこぼす。
さらにユーザーの着想「**震度0 の広がりを追えば判定できないか**」＝ Scratch 前身の `grid:上昇中割合計算&トリガ`
（グリッド＋周囲9セルの上昇割合で面判定）と一致。実データ実験で「レベルでなく**同期 onset の連結成分**で見れば
震度0 でも実地震と平常ノイズが分離できる」ことを確認したため、判別の芯を作り替える。

**変更点**:
- **L1 床を震度0 へ**: `LEVEL_MARGIN` 0.5→**0.0**（value ≥ floor で levelActive。強震モニタは 0.5 刻み量子化＝
  震度0 は value 0.0。静穏点は floor≈0 なので震度0 を取り込む。慢性ノイズ点は floor 自体が高く据え置き）。
- **L2 を per-point 近傍一致 → 同期 onset の連結成分に置換**: 直近 `COINCIDENCE_MS` に onset した点を K 近傍
  グラフで連結し、成分サイズ ≥ `MIN_CLUSTER`(=3) を「揺れクラスタ」とする。時間差 onset も成分で束ね、
  紀伊水道（成分3）を捕捉。`MIN_NEIGHBORS`/`MIN_NEIGHBOR_FRAC` は廃止（疎地域救済は成分方式に内包）。
- **faint ティア新設**（spread と intensity の分離）: **spread（成分≥3）＝実在性**、**intensity（≥震度1）＝発報の重み**。
  confirmed/likely は震度1以上（音）、**faint は同期 onset の広がりはあるが震度1未満（震度0級）＝無音で控えめに可視化**。
  Confidence は `confirmed | likely | faint | weak`。faint は `deriveKyoshinView` の confirmed/candidate に含めない
  ＝音・自動タブ・自動フィットを駆動しない。`RealtimeTab`（淡青カード「微弱な揺れの兆候」）・`KyoshinV2Overlay`
  （淡色・非脈動マーカー）で控えめ表示。

**保持（HOLD）の不具合修正（同日・spread 改訂に含む）**: 旧実装は継続点数・保持を「最後の onset」基準
（triggeredAt が TRIG_ACTIVE_MS で失効）にしていたため、**値が頭打ちで onset が止まると、まだ揺れている
のに size が減衰しイベントが早期消滅・地図リセット**した（紀伊水道で 3 局が震度1+ 継続中の 7:46:48 に weak
転落を実測）。継続点数・保持を「**いま揺れているメンバー**＝ sustained（value ≥ floor + `SUSTAIN_MARGIN`＝
床を明確に超えて継続）or 直近 onset」で数えるよう修正。`lastOnsetAtMs` は size>0 の間毎フレーム更新し、
**揺れが収まってから HOLD_MS 経過で解除**する。LEVEL_MARGIN=0 では平常の震度0(value 0.0)も levelActive に
なり保持が切れないため、継続判定は一段高い SUSTAIN_MARGIN で行う（faint＝震度0 は sustained にならず
onset ベースの一過性のまま）。→ 紀伊水道は likely が 7:46:38→7:47:38（揺れ継続の約1分間）維持され、
収束後に解除。平常窓は誤持続なし（0/0/0 維持）。

**検証（ハーネス・2026-07-24）**:
- **紀伊水道 M3.2 震度2** → **likely で検知**（従来完全取りこぼし）・揺れ継続中は維持（上記 HOLD 修正）。
- 正コントロール全件 confirmed 維持・**確定が高速化**（長野 5:46:06→5:45:40 等・低い床が初期微動を早く捕捉）。
  福島県沖 5秒短縮・大隅は 06:49:59（狙い通り）・奄美/根室/千葉/宮城/山梨も退行なし。巨大地震7件も即時確定・震度飽和維持。
- **特異度＝平常5窓（03/10/12/14:30/18:00・各300s・全国）で confirmed 0・likely 0・faint 0**。震度0 床でも
  onset連結成分≥3 が平常で発生しないため faint も氾濫しない。faint は実地震の末尾・震度0 フリンジにのみ出現。
- 型 0・vitest 30 件（faint 昇格・揺れ継続中の早期消滅回帰テストを追加）。

## 14. 地域単位の発報（別地点・余震の再検知）

**動機**: 発報が「confirmed が1件でもあるか」の**グローバル真偽**（false→true で1回）だったため、検知中に
(a) 同一地域の余震・(b) 全く別の場所の地震 が来ても鳴らなかった。Scratch 前身はそもそも**グリッド単位・
上昇駆動**（`震度上昇効果音` が各グリッドの上昇で鳴る）で、この問題を持たない。V3 も発報を地域単位へ寄せる。

**実装（`useKyoshinAlerts` のみ・コア/検知は不変）**:
- コアは変更せず、`deriveKyoshinView` が confirmed 各イベント（地域）の代表点＋最大インデックス
  `confirmedShocks` を出す。
- **初検知**（confirmed false→true）＝検知音＋タブ＋通知（従来どおり）。
- **同一地震の揺れ強まり**＝全体最大レベルの再エスカレーション（従来のグローバル判定を維持・安定）。
- **別地点の地震**（新設）＝検知中に、既存の確定地域から `REGION_MATCH_KM`(300km) より離れた新地域が
  `REGION_PERSIST_TICKS`(3f) 持続したら検知音＋タブ＋通知。分裂フラグメントの誤発報を避けるため持続＋
  クールダウン(`NEW_REGION_COOLDOWN_TICKS`=5f)で抑制。同一地域の余震（時間差）は、揺れが収まって地域が
  解除された後に来れば「新地域」として、収まる前に来れば全体再エスカレーションとして鳴る。
- 全地域解除で EEW が無ければデフォルトタブへ復帰。

**検証（ハーネス・発報回数シミュレーション）**: 単発中規模は別地点0＝**検知音1回**（福島県沖 M4.2・大隅 M5.2）。
巨大地震は有感域が全国 >300km に割れるため **能登 M7.6 で約10回**（連続する広域大動なので許容）。当初試した
per-point 微小再エスカレーションは能登で168回鳴り過剰だったため廃止し、上記（初＋全体再エスカレーション＋
別地点）に整理。`REGION_MATCH_KM` は 250→300 で単発中規模の分裂フラグメント誤発報（別地点1回）が消えることを確認。

## 16. likely/faint のティア保持 LIKELY_HOLD_MS（2026-07-24・弱い検知の早期消滅を解消）

**動機**: confirmed は `everConfirmed` ラッチ＋イベント存続（`HOLD_MS`）で揺れが収まっても維持されるが、
**likely/faint にはラッチが無く、揺れの面（size）が `MIN_LIKELY_POINTS` を割った瞬間に weak（＝非表示）へ

## 19. EEW（震源要素確定）発表中の確定緩和（2026-07-29・Scratch 版との比較から着想）

**動機**: 別実装（Scratch 3.0 版「リアルタイム地震ビューアー」・同じ DM-D.S.S 系データを使用）との比較検証で、
Scratch 版は単点の急峻な立ち上がりや EEW 予想円内の点を優先的に許可する状態機械を持ち、V3 より速く・敏感に
反応することが分かった。ただし Scratch 版の「1点で仮許可」は V3 が意図的に排除してきた誤検知パターン（茨城県
北部の単点強震ノイズ §18・北関東の慢性コヒーレントノイズ §3-6）そのものであり、そのまま輸入すると誤報耐性を
損なう。一方 Scratch 版の「EEW 予想円内の点を優先」は、EEW（気象庁発表）というすでに強いエビデンスがある
局面に限定した緩和であり、震源非依存の面判定という V3 の設計原則を壊さずに速さだけを取り込める。

**変更**: `Frame.eewActive` が true の間、`updateEventMetrics` の確定点数・確定連続フレーム数を
`CONFIRM_POINTS`(5)/`CONFIRM_FRAMES`(2) から `EEW_CONFIRM_POINTS`(3)/`EEW_CONFIRM_FRAMES`(1) に差し替える。
単点ノイズを弾く `MIN_CLUSTER`・`CONFIRM_INTENSE_POINTS`・`MIN_CONFIRM_INTENSITY`・慢性活性の引き上げ幅は
変えない。震源座標・距離は一切見ない（震源非依存を維持）。

**判定条件の試行錯誤（すべてユーザーとの対話で是正）**:
1. 当初案: `hasActiveEEW`（`severity` 不問）→ セルフレビューで「予報級1件だけで全国規模の確定緩和が発動し、
   §18 で塞いだ単点ノイズ誤 confirmed を EEW 経由で再導入しかねない」との指摘を受け、Warning 限定に修正。
2. `severity==='Warning'` 限定（`hasActiveWarningEEW`）→ ユーザー指摘「単独点は低精度だが、通常の予報は
   確度が高いのでは」を受けて `dmdataParser.ts` の `parseEEW` を確認すると、`severity` は DMDATA 電文の
   `isWarning`（推定震度が警報レベルに達したか）で決まる軸であり、震源推定の精度（単独点処理か複数点処理か
   ＝`earthquake.condition==='仮定震源要素'`）とは独立していると判明。複数観測点による確度の高い処理でも
   推定震度が低ければ severity は Forecast のままになりうる。
3. さらにユーザー指摘「予報でも震度3なので結構揺れている」を受け、severity（推定震度の大小）で判定すること
   自体が目的（震源要素の精度が担保された局面でのみ緩和する）とズレていると判明。**最終的に判定軸を
   `severity` から `earthquake.condition !== '仮定震源要素'`（震源要素が確定した EEW か）に変更した
   （`hasActiveNonAssumedEEW`）**。`condition==='仮定震源要素'` は 1 観測点のみのデータで震源を仮決めした
   速報で、震源・マグニチュード・推定震度の誤差が大きい——`eew.ts` の `eewMaxScale`（単独点処理時は
   `forecastMaxScale` を信用せず 0 を返す）・`RealtimeTab`・`ttsText.ts`（単独点処理時はマグニチュード・
   深さ・推定震度を非表示/読み上げない）と同じ判断基準に揃えた。severity=Warning の EEW は通常 areas
   （地域別確定予想）を伴い震源要素も確定していることが多いため、この変更は Warning 級の挙動をほぼ変えず、
   Forecast のまま震源要素が確定した地震（震度3〜4相当を含む）を新たに拾えるようになる。

**検証**: 型チェック0・vitest 40件（`kyoshinDetector.test.ts`。EEW 緩和が効くこと・`MIN_CLUSTER` と
`CONFIRM_INTENSE_POINTS` は EEW 中でも緩まないことの回帰テスト +4）。判定条件の変更（severity→condition）は
`App.tsx` 側の派生値のみの変更で、`kyoshinDetector.ts` 側のテスト・ロジックへの影響はない。

**残る限界（受容）**: `hasActiveNonAssumedEEW` は全国一律のフラグで震源距離を見ないため、震源要素が確定した
EEW の震源から遠い無関係な地域でも同じだけ緩和がかかる。ただし L2（近傍同時性・連結成分）の空間コヒーレンス
要求は変えていないため、無関係な地域でこの緩和だけでノイズが confirmed に通ることはない（点数・フレーム数の
バーを下げるだけ）。

## 20. 高震度 fast path（2026-08-09・震度3級の確定を点数待ちから解放する）

**動機**: **2026-08-07 10:02 の福井の地震（最大震度3）で、震度3が現れてから confirmed まで実測で6秒かかった**。
ユーザーからの「震度3が2点並んでいるならノイズである確率は低いはず」という指摘を受けて Yahoo 実データを取得し、
`kyoshinDetector` にそのまま流して原因を特定した。

**実データによる原因の切り分け（Yahoo 強震モニタ・2026-08-07 10:01:50〜10:03:09 の80フレーム）**:

| 時刻 | 出来事 |
|---|---|
| 10:02:34 | 震源から 21km の2点が立ち上がり開始（最至近の 8km 点ではない） |
| 10:02:36 | その2点が value 2.5（震度3相当）に到達＝生データ上の震度3初出 |
| 10:02:37 | イベント生成（`likely`・size=4）。ここから**点数待ちの足踏みが始まる** |
| 10:02:41 | size=5 に到達し `confirmStreak=1` |
| 10:02:42 | `confirmStreak=2` で `CONFIRM_FRAMES` を満たし confirmed |

つまり遅延の主因は **`CONFIRM_POINTS`(5) が揃うまでの4秒の足踏み**であり、震度の大小は確定条件に一切
反映されていなかった。`CONFIRM_INTENSE_POINTS`（§18）は「確定震度（通常 震度1）以上の点が2点」を要求するが、
これは震度1でも震度3でも同じ扱いで、**高震度であることが確定を早める材料になっていない**。

**特異度の裏取り（実データ）**:
- **平常時2時間・全国1725点で value≥2.5 の出現は 0 点**（2026-08-08 13:00 台の日中・2026-08-09 00:00 台の
  深夜。計7200フレーム）。2点連結どころか単点すら現れない。
- 点別ノイズ床の学習上限は `FLOOR_CAP`=1.5（震度2相当）。慢性的に騒がしい点でも学習床はここで頭打ちになる
  ため、2.5 はノイズ床が到達しうる範囲の外側にある。
- 既存の `CELL_FREEZE_INTENSITY`=2.5 が既に「これ以上は明らかに実地震なので地域軸の学習を凍結する」という
  判断を採用している。**新しい閾値を発明したのではなく、既にある境界を確定条件でも使う**という位置づけ。

**変更**: `updateEventMetrics` の `meetsConfirm` に高震度経路を OR で追加する。
`HIGH_CONFIRM_INTENSITY`(2.5) 以上に達した levelActive メンバーが `HIGH_CONFIRM_POINTS`(2) 点以上あれば、
点数ゲート（`effectiveConfirmReq`・慢性活性セルの `CHRONIC_POINT_BUMP` を含む）を免除する。
構造としては §18 の第3ゲートの高震度版——「単点は信じない」思想（要求点数2）はそのままに、震度のバーを
0.5→2.5 に上げる代わりに点数待ちを外す対称的な拡張になっている。

**意図的に免除しないもの**:
- `CONFIRM_FRAMES`(2) の連続フレーム要求。落雷起因の電磁誘導ノイズのような**単フレームの跳ね値を弾く安全弁**
  として残す。これを1にしても短縮は1秒に留まり、得るものより失うものが大きいと判断した。
- `MIN_CLUSTER`(3) の連結成分要求。fast path が数えるのは `e.memberKeys`＝同一イベントのメンバーだけなので、
  遠く離れた2点が偶然同時に高震度でも別イベントとして扱われ発火しない（空間コヒーレンスは構造的に温存）。

**慢性活性セルでも免除する判断（案A採用）**: 当初は慢性セルでのみ要求点数を +1 する案（案B）も検討したが、
平常時2時間の実測で慢性・非慢性を問わず 2.5 の出現が皆無であり、**分岐が効く場面が一度も観測されなかった**
ため見送った（効く場面が無い分岐は複雑さだけを増やす）。慢性セルが育つには長期学習が要るため、実運用の
localStorage 永続化で活性が高いセルが生じた場合の挙動は今後の観測対象として残る。

**`HIGH_CONFIRM_POINTS`=2 の根拠（3 では機能しない）**: 福井の実データでは全国で value≥2.5 に達した点は
**ピークでも2点**（相互距離 13km）しか無かった。3 にすると「震度3が数点だけ」の地震を一切救えず、
パラメータとして死ぬ。実データが 2 以外の選択肢を許さなかった。

**検証**:
- 型チェック0・vitest 46件（`kyoshinDetector.test.ts`。fast path が効くこと／震度2.0 止まりでは効かないこと／
  1点だけでは効かないこと／単フレームの跳ね値では確定しないこと の回帰テスト +4。既存42件は全て維持）。
- **福井の実データ再生**: 初回 confirmed が **10:02:42 → 10:02:38 に4秒短縮**（size=4＝`CONFIRM_POINTS` 未満
  での確定を確認）。震度3初出（10:02:36）からは2秒。
- **平常時2時間**（上記2窓・7200フレーム）で **confirmed=0**（fast path による誤発火なし）。

**残る限界（受容）**: `MIN_CLUSTER`(3) は据え置いたため、**単独点・2点しかない震度3は依然として検知されない**
（イベントが生成されないので fast path 以前の問題）。ユーザーからは「単独点であっても震度3はノイズでは
出づらい」という指摘もあったが、単独点は機器ノイズ・発破の典型パターンでもあり、`MIN_CLUSTER` の緩和は
§18 で塞いだ誤検知経路を再び開くリスクが大きいため今回のスコープ外とした。福井のケースは onset 連結成分が
4点あったため、この制約下でも実用上の短縮効果が得られている。

## 21. 欠測フレームでの学習資産巻き添え消失を修正（2026-08-13・KYO-1）

**問題**: `step()` の欠測分岐は当初 `if (frame.missing?.[i]) continue` で `sites[key]` に何も入れず、
学習資産（`floorMean`/`floorDev`）ごと消失させていた。次フレームで `initSiteState` から再学習に入り
`floorDev=0` にリセットされるため、慢性ノイズ点ほど直後に誤 onset を招くリスクがあった（KYO-1）。

**初回修正の踏み外し**: `sites[key] = prev` で `SiteState` を丸ごと据え置いたところ、`hist` も凍結されて
しまい、`pushHist` は配列長を 2 未満に絞らない仕様（`while (hist.length > 2 && ...) shift()`）のため
「60秒前の値」が復帰1フレーム目の `windowRate` で「`RATE_DT_MS`(2.5秒) 窓の直近サンプル」として採用される
状態が生じた。敵対的レビュアーの検証で 3 点欠測→復帰の合成シナリオを実行したところ、緩やかなドリフト
（value 0.0→0.5、震度0.5相当）でも 3 点同時 onset → `MIN_CLUSTER`(3) 到達 → likely 相当を誤検知することが
再現された。

**確定修正**: `sites[key] = { ...prev, hist: [] }` として学習資産のみ保持し `hist` は空リセット。
復帰1フレーム目の `windowRate` は基準サンプル無しで `null` を返すため `onset=false`。緩やかなドリフトが
偽オンセットに化ける経路を塞ぐ。`triggeredAtMs` は据え置いても `COINCIDENCE_MS`(4秒) の時刻ベース判定で
自然に減衰するため保持で問題無い。

**検証**:
- 型チェック0・vitest 289件（既存 265 → B6 で +23、本節で +1・KYO-1 の回帰テスト）
- 回帰テスト: 学習済み 3 点が 60 秒欠測を挟んで震度 0.5 相当に緩やか復帰しても confirmed/likely を出さないこと

**関連 KYO 修正（同コミット）**:
- KYO-2: `calcintensityToScale` 未知コードで `log.warn`（空文字/null/undefined は震度未確定として抑制）
- KYO-3: `fetchRealtimeIntensity` で `realTimeData.intensity` の欠落・空文字を明示的な失敗として扱い次エッジへ
- KYO-4: `useKyoshinRealtime.processResult` を try/catch で隔離しローカルバグを fetch 失敗と誤集計しない
  （`processResult` は後に取得経路を供給元・キュー・反映の 3 段へ分離した際、反映側の `applyFrame` へ改称）

## 22. 孤立した震度0の検知点を描かない（2026-08-19・大地震後に各地へ点々と残る残骸を消す）

**症状**: 2024-08-08 日向灘 M7.1 のリプレイで、揺れが収まった後も各地に震度0の検知点バッジが単独〜少数で
点々と残り続ける。

**原因**: イベントのメンバー（`memberKeys`）は和集合で単調増加し、揺れが収まっても縮まない
（現在揺れている数は `lastSize` が別に持つ）。表面波が抜けた後も値が震度0付近をうろつく点はメンバーに
残り続けるため、描画対象（震度0以上）に居座る。

### 計測と条件の決め方

Yahoo 強震モニタの実データを 2024-08-08 16:22〜17:42 の 80 分ぶん取得し、先頭 20 分（平常）で点別ノイズ床を
学習させてから本震以降を流した。孤立した震度0点＝「近傍に震度1以上の検知点が無い震度0点」。
以下「延べ」は秒×点の累積（1点が10秒残れば10と数える）。

**残骸の出どころは confirmed**: 孤立した震度0点の由来は confirmed 96.6%・likely 1.5%・faint 2.0%、連続表示は
中央値13秒・最長121秒。そこで間引きの対象を confirmed のメンバーに限った。likely / faint は
`HOLD_MS` / `LIKELY_HOLD_MS` の範囲で短命なうえ、faint は定義上メンバー全員が震度0なので、対象に含めると
イベントが生きている間に点だけが消え、「微弱な揺れの兆候」カードと地図が食い違う（実測: faint が存在する
52 秒のうち 19 秒で全点が消えた）。

**空間条件だけでは足りない**: 孤立した震度0点のうち「10秒以内に震度1以上へ育つ点」＝到達先端の割合は
時間帯で大きく偏る（本震〜広がり中の 3 分間は 39.3%、ピーク後の減衰期は 0.1%、収束期 0.9%）。空間条件だけで
落とすと広がり中の先端まで消えるため、「直近 `TRIG_ACTIVE_MS`(8秒) に立ち上がっていない」条件を足した
（`step()` の戻り値に `recentOnsetKeys` を追加して表示側へ渡す）。

半径と条件の組み合わせを比べた結果が下表。**間引き量をほぼ保ったまま誤削除が最小になる「30km ＋ 直近の
立ち上がりを除外」を採用した。**

| 条件 | 間引き量（延べ描画比） | 誤って消す「育つ点」（全期間） |
|---|---|---|
| 30km・空間条件のみ | 8.8% | 293点（うち広がり中 245点） |
| **30km ＋ 直近の立ち上がりを除外（採用）** | 7.8% | **54点**（うち広がり中 42点・減衰期と収束期は 0点） |
| 20km ＋ 同上 | 16.3% | 244点 |
| 40km 以上 ＋ 同上 | さらに小 | 29点前後（収束期の残骸がほとんど落ちない） |

20km は間引きが増える代わりに広がり中の先端を大きく削り、40km 以上は本来の目的（収束期の残骸）に効かない。

### カメラ追従との分離（レビュー指摘で判明した退行）

`CameraFollowsGL` の `FitToDetectionGL` は **点列が空になったこと**を「検知終了」の合図として扱い、
日本全体へ戻す（`fitJapan`）。当初は `deriveKyoshinView` が返す全点列に間引きを適用していたため、
confirmed が続いている最中に点列が空になり、カメラが勝手に引く経路が生まれた
（実測: 検知中に点列が空になる区間が **20秒**・空↔非空の往復 2回。間引き前は 0秒）。

対処として点列の役割を分けた:

| 点列 | 間引き | 用途 |
|---|---|---|
| `detectedPoints` | 通さない | カメラフィット・検知の継続判定 |
| `detectedMarkerPoints` | 通す | 検知点マーカーの描画 |
| `candidatePoints` | 通さない | 候補カメラフィット |
| `unconfirmedPoints` | 対象外（confirmed 限定のため） | 検知点マーカーの描画 |

**教訓**: 「表示のフィルタは検知の判定に触れない」という原則を守っただけでは足りなかった。点列の**空判定**が
別の場所で状態のシグナルとして使われていたため、フィルタが間接的に判定を書き換えていた。

### 検証

- 型チェック0・vitest 全通過（本節で `dropIsolatedZeroPoints` と `recentOnsetKeys` のテストを追加）
- 実データ再検証: 退行（カメラ用点列の空・faint の消失）はいずれも 0秒。間引き量 7.7%（上表の 7.8% は
  対象を confirmed に限る前の値。ほぼ変わらない）。収束期 16:52:00 の描画は 10点→3点
  （空間条件だけなら 8点落ちるが、1点は直近の立ち上がりで保護されるため 7点減）、本震ピーク（16:45:30）は
  319点→318点で影響しない
- ブラウザ（standard 版でリプレイ）でも同じ数字を確認（16:48:00=67点／16:49:00=33点／16:50:00=14点）、
  ズームは終始一定でカメラの誤発火なし
- **地図とカードは同一の点列を共有する**（`App` が `detectedMarkerPoints ＋ unconfirmedPoints` を
  `RealtimeTab` へ渡す）。当初は両者が同じ入力から同じ計算を各自で組み立てていたが、それでは片方の実装を
  変えたときに黙って食い違うため、計算を 1 箇所に寄せた

## 23. `recentOnsetKeys` の信頼性を支える 2 つの修正（2026-08-19・§22 と同日）

§22 で `recentOnsetKeys` を表示の判定材料に使い始めたことで、「その値が信頼できるか」が新たに効くように
なった。レビューで挙がった次の 2 点を同時に直した。どちらも**壊れても例外が出ず、静かに劣化する**類。

### 1. 観測点集合の変化を取りこぼす（`siteSignature`）

以前は「点数＋先頭・末尾座標」だけで近傍メタ（`StationMeta`）のキャッシュ有効性を判定していた。配列の
中間だけが差し替わった更新はこれを通り抜けるため、古い `StationMeta.keys`（＝`computeSiteKeys` が座標の
重複点に出現順で付けた `#2`, `#3`）を使い続ける。一方で表示側の `buildSiteIndex` は毎回キーを作り直すため、
両者がずれて `recentOnsetKeys.has(key)` が常に false になり、到達先端の救済が効かなくなる（Yahoo の観測点
リストは全1725点中431点が座標重複に該当する）。

**全点を見るシグネチャに変えた**。走査コストを避けるため二段構えにしている: まず `sites` の**参照**で弾き
（同一 `siteConfigId` なら `fetchSiteList` が同じ配列を返すため通常運用はここで終わる）、参照が変わったときだけ
全点シグネチャを比べる。内容が同じなら近傍メタ（O(点数²)）を再利用し、参照だけ差し替える。

### 2. `step()` 例外時の凍結

例外時は `setResult` を呼ばずに抜けるため、`detections` と `recentOnsetKeys` が前フレームの値で凍結する。
一方で表示側が使う現在震度は生きたまま更新されるので、放置すると「古いメンバーを現在の震度で描き続ける」
状態になる（間引きの判定も古い `recentOnsetKeys` で行われる）。

**`STEP_FAIL_RESET_FRAMES`(5) フレーム連続で失敗したら検知結果を空にする**。数フレームの一過性なら保持した
方が明滅しないため、閾値を設けている。学習資産（点別床・セル慢性活性）は `stateRef` に残すので、復帰時に
学び直しにはならない。

## 24. 別地点発報の連発を止める（2026-08-20・能登半島地震リプレイでの利用者報告から）

「能登半島地震のリプレイで検知音が何度も鳴る」という報告を受けて調べた。実データで測ると、揺れ検知の
音のうち**「別地点で揺れ検知」だけが数秒おきに連続**していた（EEW あり条件で 16:21:28〜16:21:43 に
5 秒間隔で 4 連発）。原因は 3 つあり、いずれも「巨大地震で揺れが全国へ伝播する」場面で表に出る。

### 原因

1. **距離判定の起点が地域自身の初検知時刻だった** — 遠くて揺れ始めが遅い地域ほど経過時間が短く
   見積もられ、閾値が下限 300km に張り付く。伝播を吸収するための動的閾値が、いちばん吸収したい遠方で
   こそ育たないという逆転が起きていた。
2. **EEW による吸収が「今この瞬間 EEW があるか」しか見ていなかった** — 吸収した地域を配列から削除する
   実装だったため、次のフレームで新規地域として再登録される。EEW が最終報で解除された後は吸収されず、
   それまで抑えられていた地域が一斉に発報条件を満たした（実測: 解除の 1 秒後に発報）。
3. **距離だけでは表面波を抑えきれない** — 震央から 600〜1350km で震度2以下の揺れが次々確定する。
   これを距離で吸収しようとすると、上限を上げるほど「本当に別の場所で起きた地震」を取りこぼす。

### 対策

| 変更 | 内容 |
|---|---|
| `AlertRegion.absorbedByEew` | EEW の伝播範囲に一度入った地域を記憶し、解除後も発報しない（原因2） |
| `AlertRegionState.outbreakAtMs` | エピソード全体の起点を保持し、EEW が無いときの距離判定の基準にする（原因1）。個々の地域の生存とは切り離す（震源近傍が先に収束して刈られても起点が繰り上がらない） |
| `PROPAGATION_MAX_KM`(800km) | 伝播として吸収する距離の上限。S波半径は起点から4分で約1250kmに達するため、上限が無いと国内のどこで起きた地震も同一地震に見える |
| `NEW_REGION_MIN_INDEX`(11) | 遠さではなく揺れの強さで線を引く。震度3を下回る地域は音を鳴らさない（原因3） |

あわせて、判定を純関数 `stepAlertRegions` に切り出した（副作用はフック側に残す）。実データを流した回帰
検証とユニットテストが同じ経路を通せる。戻り値は発報した地域の座標と震度で、ブラウザ通知の「推定最大
震度」はこの値を使う（従来は検知全体の最大震度を出していた）。

### 実測

Yahoo 強震モニタの当時の実フレーム 960 秒分に、DMDATA archive の実電文（EEW 80 件）を重ねて測定した。

| 条件 | 修正前 | 修正後 |
|---|---|---|
| EEW あり | 5 回（うち 4 回が 5 秒間隔） | **0 回** |
| EEW なし | 7 回（最小間隔 5 秒） | 2 回（最小間隔 30 秒・どちらも震度5強相当） |

修正前の数値はブラウザでの実測と時刻・回数が一致する。EEW なし条件で 0 にならないのは、強震モニタ
だけでは震源も発生時刻も分からないため、揺れ始めから約 1 分間は閾値が下限を超えられない原理的な限界に
よる。この条件は DMDSS 版で API キー未設定のときだけ現れる（standard 版は強震モニタ経由の EEW が入る）。

**寄与は単純な足し算にならない**（EEW なし条件で計測）。`absorbedByEew` とエピソード起点だけなら 3 回まで
落ちるが、そこへ距離の上限を足すと 8 回へ跳ね返る（吸収できる範囲が狭まるため）。その 8 件のうち 6 件は
震度2以下・震央から 600〜1350km で、震度の下限がこれを打ち消す。最後に、下記の照合順序の修正で 2 回に
落ち着いた。

### 判定の順序依存

地域の代表点はマッチのたびに書き換わるため、素直に書くと同じフレームの後続の確定点が「直前の点で
動いた後の位置」と比較され、**確定点の処理順で結果が変わる**（レビュー指摘）。マッチングは
フレーム開始時の座標で行うようにした。同じフレームで新しく生まれた地域も、その場で基準点として
登録する（登録しないと、その地域だけ順序依存が残る）。

### 採らなかった案

どちらも実データで測ったうえで見送った。

- **発報済み地域を照合の対象から外す** — 一度「別地点」を鳴らした地域（`fired`）は二度と鳴らないため、
  その地域の閾値の内側で後から本当に別の地震が起きても無音になる（レビュー指摘）。そこで発報済みを
  エピソード起点による拡張から外してみたが、**発報が 1 回増えた**（2 回 → 3 回）。閾値が狭まったぶん、
  同じ地震の伝播が新規地域として登録し直され、**同じ場所が二度鳴る**方に振れたため。鳴りすぎを直す
  変更で鳴りすぎが増えては本末転倒なので採らなかった。既発報地域が別の地震を吸収しうる限界は、
  修正前から変わらないものとして残っている（音は鳴らないが、地図と検知カードには出る）。
- **クールダウン（`NEW_REGION_COOLDOWN_TICKS`）を 5 → 30 に延ばす** — 発報数が変わらなかった
  （どちらも 2 回。間隔だけが 6 秒から 30 秒に広がる）。延ばすと、クールダウン中に揺れが収まった地域が
  `REGION_PRUNE_TICKS`(3) で破棄されて発報の機会を失う窓が広がる。数を減らせないなら、その代償だけを
  負うことになるため据え置いた。

## 25. 欠測の瞬断で確定済みの検知点が明滅する（2026-08-20・能登半島地震リプレイでの利用者報告から）

**症状**: 2024-01-01 能登半島地震の本震付近を再生すると、確定済み（confirmed）の検知点が一部、**震度6強級を
含めて**一瞬消えて復活する動きを繰り返す。

**原因**: 上流データそのものが単発の欠測を混ぜている。Yahoo の秒データは観測点ごとの値に欠測センチネル
（実測 -1）を含み、**現に強く揺れている観測点でも 1〜2 秒だけ値を落とす**。表示側は欠測を「震度階級なし」
として描かない（`kyoshinIndexToJma` が null）ため、そのまま渡すと 1 秒消えて次の秒で戻る。

### 実測（欠測の継続長）

2024-01-01 16:10:00〜16:15:00（本震直後）の 300 秒・1133 観測点を秒ファイルから直接取得し、**前後に有効値が
ある欠測**（＝瞬断）を継続長別に数えた。

| 直前の震度帯 | 1秒 | 2秒 | 3秒 | それ以上 |
|---|---|---|---|---|
| 震度7 | 7 | 1 | – | 15秒:1 |
| 震度6強 | 9 | 2 | – | – |
| 震度6弱 | 22 | 5 | 1 | – |
| 震度5強 | 48 | 2 | 1 | – |
| 震度5弱 | 33 | 11 | – | – |
| 震度4 | 188 | 39 | 5 | 4秒:2 / 6秒:1 |
| 震度3 以下 | 2419 | 289 | 32 | 数件 |

全体では 1 秒 2726 回・2 秒 349 回・3 秒 39 回。**2 秒までで全体の約 99%**（3134 件中 3075 件）を占める。
一方で 15 秒・27 秒・44 秒・97 秒・115 秒の欠測も存在し、これらは本物の観測点停止として消えなければ
ならない。この分布から保持の上限を **2 秒**（`MISSING_HOLD_MS`）に決めた。

### 「消す」ではなく「薄く残す」を選んだ理由

直前値で埋めるだけだと、値が生きている点と区別が付かない。欠測は 3% 前後の観測点で常時起きているため、
「表示されている値がいつのものか」を示さないまま補完すると、データの欠落を隠す方向に働く。そこで
保持中は `stale` を立て、震度を読める描画物（検知点バッジ・震度1以上のドット）を不透明度 0.35 で描く。
利用者側の要望でもあった。

### 判定にも効かせた理由

保持値は表示のための補完だが、`deriveKyoshinView` を通るため音・通知・地域単位発報の入力
（`candidateMaxIndex` / `confirmedShocks`）にも入る。**これは意図した設計**。欠測を素通しすると、地域の
最大震度を担う観測点が 1 秒欠測した瞬間に最大値が次点まで落ち、復帰時に `useKyoshinAlerts` の
`postPeakMinLevel` 経路で「再エスカレーション」の更新音が誤って鳴る。検知エンジンが欠測を「揺れ 0」と
扱わない（§21）のと同じ理由で、表示側の最大値も欠測で落とさない。

### 修正後の実測

同じ窓（16:10:11〜16:11:50・100 フレーム）を DMDSS 版のリプレイで地図ソースから毎秒サンプリングした。

| 指標 | 修正前（生データから算出） | 修正後（アプリ実測） |
|---|---|---|
| 描画対象の点が 1 フレーム消えて戻る回数 | 581 回（1秒 487・2秒 94） | 9 回 |
| うち震度6強以上 | 18 回 | 0 回 |

残った 9 回は欠測ではなく、震度0未満への低下と孤立震度0点の間引き（§22）による従来どおりの挙動。

## 27. §16・§17 に合成配置の回帰テストを付ける（2026-08-21・実データを置かずに仕組みを固定する）

§16（`LIKELY_HOLD_MS`）と §17（`K` 7→12）は実データのリプレイで確かめたが、**その検証は CI に残らない**。
強震モニタの秒フレームをリポジトリに置かない方針（`.gitignore` が `public/data/test-scenarios/*.json` を

再現するテストを追加した。配置の詳細（間隔・点数・なぜ静穏点を緯度方向へ直交にずらすか）はテストコードの
`denseChainLayout()` の説明に置き、ここでは何を固定したかだけを記す。

| 固定した性質 | 置き場所（`src/utils/kyoshinDetector.test.ts`） |
|---|---|
| 密網で至近に静穏点が並んでも隣の揺れる点を近傍に含める | `buildStationMeta: 密網でも離れた点へ橋を架ける（K）` |
| K に余裕があっても近傍は `R_KM` の外へ広がらない | 同上 |

| likely はラッチせず、保持中に震度0級まで弱まれば faint に下がる | 同上 |

**`HOLD_MS` と混同しない作り**（テスト設計上の落とし穴）: イベントの解除は `now − lastOnsetAtMs ≤ HOLD_MS`
で決まり `LIKELY_HOLD_MS` を見ない。しかも震度0級の点は床＋`SUSTAIN_MARGIN` に届かず sustained になれない

`lastOnsetAtMs` の時計も止まり、ティア保持とイベント解除が同時に切れて**どちらの働きか区別できない**。
そこで faint のテストは 1 点だけを床下と震度0 の間で振動させて onset を継続させ（`windowRate` の起点は
now−2000 付近なので 1 秒交互では上昇量が 0 になる＝2 フレーム周期にする）、イベントを生かしたまま

（保持のテストは 2 つの describe に分かれている）。逆に `HOLD_MS` だけを 10s→3s に縮めても faint のテストは
通る＝上の切り離しが効いていることの裏取り。

カード側（`src/components/RealtimeTab/index.test.ts` の
`検知カードの枠色は最大震度で決まる（確信度ではない）`）も同時に固定した。枠は最大震度の気象庁配色・

## 28. 群発地震で余震検知の感度が徐々に落ちる（2026-07-29・熊本群発リプレイ・FLOOR_FREEZE_MS）

> **本節は後追いの記載**。実装（`PARAMS.FLOOR_FREEZE_MS` の追加）はコミット `1cd75b6`（2026-07-29）で
> 既に main へ入りリリース済みだが、当時この節を書き落としていた。2026-08-21 に実データで再検証した
> うえで経緯を記録し、あわせて境界・副作用のテストを 3 件足した。
> なお `1cd75b6` のコミットメッセージは非検知を「40件→4件」、母数を「M7.1本震+109件の余震」と
> 書いているが、これは**対策前と対策後を別々の突き合わせ条件で測った数字**で、母数の内訳も不正確
> だった。下記の表は `FLOOR_FREEZE_MS` だけを切り替えて同一条件で測り直したもので、こちらを正とする。

**問題**: 点別ノイズ床の学習は「揺れていない静穏点」だけで行い、(i) `levelActive` な点と
(ii) 近傍同時性を満たした確定揺れ点で凍結していた（§5-L0）。しかしこの 2 条件はどちらも
**現フレームの状態**しか見ておらず、`COINCIDENCE_MS`(4秒) を過ぎて揺れが収まったと判定された
瞬間から床学習が再開する。本震・大きめの余震の減衰過程では、値が実効床を割ったり超えたりしながら
緩やかに収まるため、その「割った」瞬間の値が静穏点のノイズとして学習され、
`floorMean + FLOOR_SIGMA_K・floorDev` を `FLOOR_CAP`(震度2相当) まで押し上げてしまう。
一度そこまで上がると震度1程度の後続の余震は `levelActive` にすらならず、検知が完全に消える。

単発の孤立した地震なら `FLOOR_TAU_MS`(15分) の時定数でゆっくり回復する余地があるが、数分おきに
余震が続く群発地震では床が戻る前に次の onset が来るため、**劣化が蓄積して時間とともに悪化する**。

**変更**: `PARAMS.FLOOR_FREEZE_MS`(600,000ms = 10分) を追加し、床学習の凍結条件に 3 つめを足した。
`triggeredAtMs`（最後に onset した時刻）から `FLOOR_FREEZE_MS` 以内の点は、揺れが収まった直後でも
学習をスキップする。対象は **onset した観測点のみ**なので、onset しない慢性ノイズ点を `FLOOR_CAP` まで
鈍くする本来の役目（特異度の第1軸）は妨げない。

**検証（2026-07-28 熊本群発地震のリプレイ）**: M7.1・震度7 の本震（16:27）以降 23:59 まで JMA カタログで
111 件の有感地震が記録された日を、Yahoo 履歴 RealTimeData 27,240 フレーム（7.5 時間・全国）でリプレイした。
111 件の内訳は熊本県熊本地方 79・熊本県天草・芦北地方 28（＝熊本圏 107）と、群発とは無関係な
和歌山県北部 2・鹿児島県薩摩地方 2。
`FLOOR_FREEZE_MS` だけを 0（＝対策前と等価）と 600,000 で切り替え、**同一の突き合わせロジック**で比較:

| | カタログ照合 非検知 | 検知スパン総数 | 広域分裂（既知・§10.4） | 時間的に孤立 |
|---|---|---|---|---|
| 対策前（freeze=0） | **36** / 111 | 136 | 8 | 14（うち confirmed 9） |
| 対策後（freeze=600s） | **4** / 111 | 189 | 9 | 45（うち confirmed 15） |

右 3 列は「検知スパン総数」を分割したものではない。`検知スパン総数` は likely 以上のスパン全件、
`広域分裂` はカタログ地震と時間は重なるが重心が 250km 超離れたもの（巨大地震の有感域が割れる §10.4 の
既知挙動）、`時間的に孤立` はどのカタログ地震とも時間が重ならないもの。残りがカタログと対応した検知。

- 非検知 36→4。残る 4 件は和歌山県北部 2 件（別窓・単点）と熊本 2 件（M2.0/M2.1）で、いずれも
  onset 点数律速の微小地震＝§17 と同じ「K を上げても救えない」型。
- 震度4以上の余震 13 件は対策前後とも 100% confirmed。
- 対策前は本震後 18:13〜18:21 の 8 分間、震度1相当の余震 5 件が完全に無反応だった（劣化の実例）。
- **留意点**: 「時間的に孤立した検知」が 14→45（うち confirmed 9→15）に増えている。感度回復の裏面だが、
  誤検知と断定はできない（M7.1 の余震は JMA が有感として載せる 111 件よりはるかに多く、小さいものは
  カタログに現れない）。ただし **confirmed は検知音とブラウザ通知を伴う階級**なので、仮に誤検知なら
  影響は表示上の残骸より大きい。切り分けには平常時窓での特異度検証が必要で、**本節時点では未実施**。
- 単体テスト: フリーズ機構そのもの（2 件）＋副作用・境界（3 件）。うち 3 件は凍結条件を外すと落ちる
  ことを確認済み（残る 2 件は、フリーズ期間の経過後に学習が再開すること・時刻の巻き戻しで
  `triggeredAtMs` が破棄されることの記録で、凍結条件の有無では変わらない）。

**副作用として確認したこと**:
- onset していない点の床学習は止まらない（`FLOOR_CAP` による慢性ノイズ抑制は健在）。
- 群発中に onset を繰り返すと、そのたびに `triggeredAtMs` が更新されフリーズ起点も延びる。
  つまり余震が続く限り床は守られ続ける。
- データ時刻が巻き戻る（アーカイブ再生など）と `dtMs <= 0` が不連続とみなされ `triggeredAtMs` は
  破棄される。これが無いと `now − triggeredAtMs` が負になりフリーズ条件が永久に真になるため、
  この不連続リセットは本機構の前提として効いている。
