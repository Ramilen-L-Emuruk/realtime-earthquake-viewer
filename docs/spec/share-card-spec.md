# 共有カード仕様書

> 本書は**現在の実装が表示中の地図をどう 1 枚の画像にするか**をまとめた仕様書。実コードと食い違う場合は実コードを正とする。
> 関連: [`map-rendering-spec.md`](map-rendering-spec.md) の地図の投影とカメラ、[`tsunami-spec.md`](tsunami-spec.md) の観測点、[`eew-spec.md`](eew-spec.md) の区分の呼び方。

## 1. 概要

表示中の地図に見出しと出典を添えて 1 枚の画像にし、共有または保存する。

| 対応ファイル | 役割 |
|---|---|
| `src/components/Map/gl/captureMap.ts` | 地図を指定寸法で撮る |
| `src/utils/shareCard.ts` | 見出し帯・地図・出典帯を合成し、共有または保存へ渡す |
| `src/utils/shareCardContent.ts` | 見出しと出典・注意文を組み立てる |
| `src/hooks/useShareCard.ts` | 撮影から共有までの流れと状態 |
| `src/components/ShareCardButton.tsx` | 地図に重ねるボタン |

## 2. 起動点

地図の右下に重ねたボタン 1 つ。

**撮るのは画面に見えている構図そのまま**で、中心とズームは動かさない。カード用の寸法は画面と縦横比が違うため見える範囲は横へ広がるが、利用者が合わせた視点は変えない——撮影のためにカメラを寄せ直すと、見ていたものと違う画が出てくる。

## 3. カードの構成

上から見出し帯・地図・出典帯の 3 段。**全体が 1600×900（16:9）**で、地図はその残りに割り当てる。

見出しの中身は地図のモードで変わる。

| モード | 見出し | 副見出し | 右上の時刻 |
|---|---|---|---|
| 地震 | 最大震度（震度の色つき） | 震源名・規模・深さ | 発生時刻 |
| 津波 | 最も重い等級 | 震源名・対象の区域数 | 発表時刻 |
| リアルタイム震度（発報なし） | リアルタイム震度 | — | — |
| リアルタイム震度（発報中） | 緊急地震速報／地震動予報 | 震源名・規模・予想最大震度 | 報番号・発生時刻 |

**値が無いものは項目ごと落とす。** 「不明」と書いても読み手には伝わらないため。震度が階級表に無い値で届いた場合（震度を伝えない電文）は、見出しを「地震情報」に落とす。

**「5弱以上・未入電」は断定形で出さない。** 見出しの最大震度に「以上」を添える
（`getIntensityLabelWithOrAbove`。判定は `points` から導く ―― → [`quake-spec.md`](quake-spec.md)
§4「震度5弱以上未入電」）。画像は後から訂正できないので、画面より強く言わない。

**規模を数値で出せないときは、電文が添えた言い回しをそのまま出す**（「Ｍ８を超える巨大地震」等）。
気象庁は規模が確定していない段階でこの形を使う。数値が無いことを理由に項目ごと落とすと、
「規模が判っていない」ことすら伝わらない。

**津波の原因地震が複数あるときは先頭だけを出す。** 電文は短い間に起きた複数の地震を 1 つの
津波情報にまとめることがある（→ [`tsunami-spec.md`](tsunami-spec.md) §4）。見出しは 1 行なので、
画面のカードと同じく先頭を主に扱う。

**仮定震源要素（震源未確定）の緊急地震速報では規模を出さない。** 電文には数値が入っているが地震学的に意味を持たない仮の値で、画面でも隠している（[`eew-spec.md`](eew-spec.md) §5）。共有された画像は後から訂正できないため、画面と同じ扱いにする。予想震度は区域ごとの発表値なのでそのまま出す。

## 4. 出典と注意文

画像は本文から切り離されて流通するため、**出典は画像そのものに焼き込む**。出典は 1 行にまとめる——行を増やすとそのぶん地図に割ける高さが減る。

| 挙げるもの | 出す条件 | 求める規約 |
|---|---|---|
| 気象庁 | 常に | 公共データ利用規約（第 1.0 版） |
| GEBCO・NOAA NCEI（Esri のタイルサービス経由） | 海底地形の表示が入りのとき | 配信元のサービスが `copyrightText` で求める帰属表示（GEBCO と NOAA NCEI の両方） |
| 産総研 活断層データベース | 地震／リアルタイム震度モードで、活断層の表示が入りのとき | 政府標準利用規約 2.0 |
| PB2002 (Bird, 2003) | 同上（プレート境界の表示が入りのとき） | Open Data Commons Attribution License |

**描いているものだけを挙げる。** 挙げないのは帰属表示の欠落になり、描いていないものを挙げても読み手は画像の中に見つけられない。活断層とプレート境界は地震／リアルタイム震度モードでしか描かれない（`JapanMapGL` の `showOverlayLines`）ため、モードと表示設定の両方を見る。海底地形は設定だけで決まる。

**「加工して作成」は全部に掛けない。** 境界線・区域・活断層・プレート境界は元データを GeoJSON へ変換して使うが、海底地形は配信されるタイルをそのまま描いている。まとめて括ると、加工していないものまで加工したと述べることになる。

**地図へ新しいデータのレイヤーを足したら、`shareCard.ts` の `ATTRIBUTION_SOURCES` へ出典を足し、載せる条件も見直すこと。** 出典の実体は各ローダーの冒頭コメント（`utils/activeFaults.ts`・`utils/plateBoundaries.ts` など）。

緊急地震速報を含む場合は、これに加えて注意文を 1 行足す。

**注意文の要否は地図のモードで決めない。** 緊急地震速報の予報円と震源はモードに関わらず描かれるため（`JapanMapGL` の `PsWaveGL` / `EewEpicentersGL`）、モードで判断すると「予報円が写っているのに注意文が無い」画像を作れてしまう。判定は「発報中の緊急地震速報があるか」で行う。

注意文は DM-D.S.S が配布時に求める注意事項をまとめたもの。**「震源に近い場所では間に合わないことがある」を落とさないこと**——精度の話だけを残すと、速報が届く前に揺れが来る場合があるという、行動に直結する留保が伝わらない。

## 5. 撮影の仕組み

### フレームバッファは同期の窓でしか読めない

WebGL のキャンバスは、合成が済むと中身が捨てられる。地図は `preserveDrawingBuffer` を既定の false で初期化しており（`JapanMapGL` の `new maplibregl.Map`）、`render` イベントの同期コールバックを抜けた時点で空になる。

実測では、`render` の中で読むと中身のある画が取れ、300ms 後に読むと 1 色・不透明度 0 の空画像しか返らなかった。

`preserveDrawingBuffer` を true にすればこの制約は消えるが、**Map の初期化オプションなので実行時に切り替えられない**——撮影のたびに地図を作り直すことになり、カスタムレイヤーもデータも積み直しになる。

したがって **`ctx.drawImage(glCanvas, ...)` は `render` コールバックの同期実行中に呼ぶ**。`toBlob()` のような非同期 API へ差し替えると、コールバックを抜けたあとに読むことになり空になる。写し取ったあとの加工（見出し・出典の合成）は 2D キャンバス上の話なので、いくら時間をかけてもよい。

### 寸法の決め方

| 項目 | 値 | 根拠 |
|---|---|---|
| 比率 | 16:9 | X のタイムラインは横長比率で切り抜く。**カード全体をこの比率にする**——地図だけを合わせると、上下に足した見出しと出典が切り抜きで落ちる |
| 寸法 | 1600×900 | X の推奨は 1200×675（16:9）。同じ比率で上回る値を採り、拡大しても文字が読めるようにした |
| 出力の画素数 | 寸法に固定 | 端末の解像度に任せると同じ操作でファイルサイズが数倍に振れ、X のファイルサイズ上限（モバイル 5MB）に触れる。実測で 1600×900 の PNG が 1.4MB |

**撮影は端末の解像度のまま高精細に行い、合成で寸法へ縮小する。** 縮小はスーパーサンプリングとして働くので、解像度の高い端末ほど滑らかな画になる。

寸法は `SHARE_CARD_FORMATS` に名前付きで定義してある（将来、設定で選べるようにする余地）。**足すときは全体の比率で定義すること**（地図の比率ではない）。

### 出力寸法でレンダーし直す

撮影は地図コンテナを一時的に出力寸法へ広げ、その寸法でレンダーさせてから写し取り、元へ戻す。別の Map インスタンスを立てないのは、レイヤーの登録が `Map/` 配下のコンポーネント十数個に分かれており、二つ目の地図に同じ絵を再現できないため。

**画面とは縦横比が変わるので、見える範囲は画面と一致しない。** 構図を渡さない場合も中心とズームは保たれるが、横方向に広がる。

**出力寸法は画面の地図領域より大きいことが多い。** 地図コンテナの親（`position:absolute` の枠）は overflow を持たないため、広げた分がそのまま隣のパネルへはみ出して見える（実測: 929×454 の地図領域に対し、下のパネルへ 176px かぶさっていた）。撮影中だけ親を切り抜く。

寸法を変えている間は画面がその寸法で描かれてしまうため、**撮影の直前の画を静止画として被せて隠す**。利用者には地図が一瞬止まったように見える。静止画は親と同じ大きさなので、上の切り抜きが無いと覆いきれない。

### 後始末は 1 つずつ

撮影後の復元（寸法・切り抜き・カメラ・静止画の除去）は**個別に囲って、1 つ失敗しても残りを実行する**。素直に並べると途中の 1 行が投げた時点で以降が飛び、とくに静止画の除去に届かないと**地図が撮影直前の画で覆われたままになる**。静止画は `pointer-events: none` なので操作は下の地図へ届くが、その結果が画面に現れない（リロードするまで戻らない）。加えて後始末の中で投げた例外は、撮影で起きていた元の例外を握り潰すため失敗の原因も失われる。

### カメラには触らない

撮影は寸法だけを変え、**カメラ（中心・ズーム・傾き・回転）には一切触らない**。地図の自動追従が動いている最中でも、撮影がその位置を奪ったり戻したりしない。

将来カメラを動かす経路を足すなら、**`camera.ts` の fit 系関数を通し、`beginProgrammaticFlight` の印を eventData へ渡すこと**。印の無いカメラ操作はユーザーの手動操作として扱われ（`ensureUserInteractionState`）、地図の自動追従が `INTERACTION_HOLD_SEC` 秒止まる。

### 地図キャンバスに写らないもの

津波の観測棒と到達確認マーカーは `maplibregl.Marker`（DOM 要素）なので WebGL のキャンバスには含まれない。撮影した 2D キャンバスへ同じ形を描き直す（`gl/tsunamiObsBar.ts` の `drawTsunamiObsBars` と `gl/tsunamiArrivalMarker.ts` の `drawTsunamiArrivalMarkers`）。形と不透明度はそれぞれ画面側の DOM（`updateBarEl` と `TsunamiArrivalMarkersGL` の `updateMarkerEl`）と対応させてある——**片方だけ変えると、画面と画像で見た目がずれる**。

描き足しは撮影の同期窓の中で行う。`map.project()` が撮影寸法で答える必要があるため、復元後に呼ぶと棒だけ別の場所に立つ。

球投影では `map.project()` が地球の裏側の点にも画面内の座標を返すため（[`map-rendering-spec.md`](map-rendering-spec.md) §6）、投影して戻す往復で手前の面にある点だけを描く。

## 6. 共有と保存

**画像と本文を一緒に渡す。** 共有シートから X などを選べば、画像が添付された状態で本文が入る。

`navigator.canShare({ files, text })` が真なら共有シートへ渡し、そうでなければ画像を保存する（保存へ落ちたときの本文の扱いは後述）。共有シートを閉じただけの取り消し（`AbortError`）は失敗ではないので、保存へは落とさずそのまま終える——**クリップボードも書き換えない**。共有をやめた利用者の手元を勝手に上書きしないため。

**判定は渡すものをすべて含めて行う。** 画像だけで `canShare` を確かめて本文を後から足すと、本文を受け取れない実装で `share()` が投げ、そこから保存へ落ちる遠回りになる。

保存名は種別と時刻から作る（例: `quake_20260830_190531+0900.png`）。**種別の語は ASCII に限る**——日本語のファイル名を扱えない環境があるため。

### 本文の中身

**見出しと同じ材料で組み立てる**（`buildShareText`）。画像と本文で違うことを述べないため。

| 行 | 中身 |
|---|---|
| 1 | 見出しと副見出し（例: 「最大震度 5弱　福島県沖　M6.1　深さ 50km」） |
| 2 | 時刻（発生・発表）。緊急地震速報では報番号が前に付く（「第3報　…」）。無ければ行ごと落とす |
| 3 | アプリの URL |

**緊急地震速報の注意文は本文に入れない。** 注意文は画像へ焼いてあり、本文と画像は共有シートで一緒に渡る。本文にも重ねると X の全角 140 字にほぼ届き、震源名が長ければ超える——利用者が削ることになり、削られた結果として注意文そのものが落ちうる。出典を本文へ出さないのも同じ理由。

**DMDSS 版から共有しても standard 版の URL を載せる**（`standardAppUrl`）。DMDSS 版は DMDATA.JP の API キーが要るため、受け取った人がそのまま開くと設定画面に突き当たる。

### 共有シートを持たない環境

画像を保存し、渡し先の無くなった本文はクリップボードへ置く（`copyToClipboard`）。**置けたかどうかを確かめてからボタンの表示を変える**——置けていないのに「コピーしました」と見せると、利用者は貼り付け先で初めて気づくことになる。

置けない理由は 2 つある。クリップボードの API が無い場合（安全な文脈でない配信）と、書き込みが拒否される場合（クリックからの猶予が切れたときを含む。画像の生成に手間取るとここへ来る）。**置けなかったこともボタンに出す**（「画像を保存しました（本文はコピーできませんでした）」）——記録だけに残すと、本文が入っていないことに貼り付け先で初めて気づくことになる。

**表示を分ける判定に `textCopied` だけを使わない。** 共有シートが応じた場合もクリップボードは使っていないため偽になり、正常系と「置けなかった」が同じ扱いになる。保存へ落ちたとき（`result` が `downloaded`）だけを対象にする。

## 7. 既知の限界

**起動直後に撮ると、過去の電文の取得を巻き込むことがある。** 撮影は出力寸法ぶんの地図タイルをまとめて要求するため、その通信が過去の地震の電文取得と競合する。実測では、起動 3 秒後に撮ると電文取得が多数失敗し、履歴が落ち着いた 12 秒後では 1 件も失敗しなかった。取得の失敗は画面の「データの一部を取得できませんでした」に出るため黙って欠けることはなく、読み込み直せば戻る。

**津波の観測棒と到達確認マーカーの見た目を確かめるには、過去の地震の再生が要る。** アプリのテスト機能には観測点のデータが無いため（[`settings-pwa-spec.md`](settings-pwa-spec.md) §7 のテストボタンは等級の発表のみを扱う）。画像に写ること自体は確認済み。
