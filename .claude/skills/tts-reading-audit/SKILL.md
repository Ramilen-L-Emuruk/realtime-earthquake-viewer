# 読み仮名の棚卸し

VOICEVOX の誤読を洗い出し、読み仮名辞書 `public/data/tts-phrase-break-dict.json` のエントリを作る手順。

**1 件の報告は、たいてい一族の一部でしかない。** 2026-08-22 に「長崎県西方（→ にしほう）」1 件の報告から始めた
棚卸しでは、同じ「方位＋方」の構成を筆頭に数十件の誤読が出た（件数は仕様書の改訂履歴に記録してある）。
報告された名前だけを直すと、次の地震で別の名前が同じ形で崩れる。

仕組み・記法の説明は [`docs/spec/audio-tts-spec.md`](../../../docs/spec/audio-tts-spec.md) §3「辞書（読み仮名の補正）」が正。
こちらは**作業の段取り**だけを書く。

## 使うとき

- 読み上げの地名が誤読されているという報告を受けたとき
- 上流データ（津波予報区の新設・観測点の増減）を取り込んだあと
- 辞書に手を入れる前（既存エントリの値が正しいかも併せて検定する）

## 前提

- VOICEVOX 実機が要る。この環境では `http://192.168.0.64:50021`・話者は四国めたん（ツンツン）＝ speaker 6
- API キーは不要。読ませるだけなら `POST /accent_phrases`（テキスト → 読みとアクセント）で足りる

## 1. 正解の出どころ

**推測で直さないこと。** VOICEVOX の読みと突き合わせる「正解」は 3 系統ある。

| 対象 | 正解の出どころ | 形式 |
|---|---|---|
| 一次細分区域・津波予報区 | 上流 GeoJSON の `namekana`（`scripts/build-subregions.mjs`・`build-tsunami-zones.mjs` が使っている [JMA-GIS-GeoJSON](https://github.com/Ichihai1415/JMA-GIS-GeoJSON) の release ブランチ） | JSON・依存なしで読める |
| 潮位観測点・震度観測点・長周期観測点 | 気象庁 [防災情報XML 技術資料](https://xml.kishou.go.jp/tec_material.html) の「個別コード表」zip 内 `地震火山関連コード表.xls` | xls・表計算ツールか Python（`xlrd`）で抽出 |
| 震央地名・都道府県 | **ふりがなが無い。** 読みを目視で確かめ、疑わしいものは公的資料で裏を取る | — |

`地震火山関連コード表.xls` のシート番号（`ふりがな` 列があるものだけ挙げる）:

| シート | 内容 |
|---|---|
| 24 | 一次細分区域・市町村・**震度観測点** |
| 26 | 長周期地震動観測点 |
| 31 | 津波予報区 |
| 34 | 沿岸地域 |
| 35 | **潮位観測点**（津波の観測情報で読む名前） |
| 41 / 43 | 震央地名 / 詳細震央地名（**ふりがな無し**・名称一覧として使う） |
| 62 | 固定付加文（読み上げに載る定型文。地名以外の語を調べるときに使う） |

zip 内のファイル名は cp932 のため展開時に文字化けする。名前で探さずインデックスで取るか、`ÆnÉk…` のような
化けた名前をそのまま開くこと。

疑わしい読みの裏取りには気象庁自身の別資料が使える。潮位表はローマ字を併記しているので、
[潮位表](https://www.data.jma.go.jp/kaiyou/db/tide/suisan/) の `DESHIMATSU`（弟子待）のように読みを確定できる。

## 2. どの文脈で読ませるか（最重要）

**誤読は後ろに続く文字で反転する。** 名前だけを読ませて正しくても実運用で崩れ、逆もある。

| 名前 | 読点が続くと | 助詞が続くと |
|---|---|---|
| 長崎県西方 | にしほう（誤） | せいほう（正） |
| 宮古 | みやこ（正） | みやふる（誤・「〜で10センチ」） |
| 福井県嶺北 | れいほく（正） | みねきた（誤・「〜を震源とする」） |

だから**読み上げ文が実際に作る形**で読ませる。文の組み立ては `src/utils/ttsText.ts` が正で、現状は次のとおり。

| 系統 | 名前の後ろに来る形 |
|---|---|
| 一次細分区域・都道府県 | `名前、` / `名前で観測しました。` / `名前、ほか3地域で観測しました。` |
| 津波予報区 | `名前、` / `名前で3メートルが予想されています。` / `名前にも津波注意報が発表されています。` |
| 潮位観測点 | `名前、` / `名前で10センチを観測しました。` / `名前で到達を確認しました。` |
| 震央地名 | `名前、`（深さを言う電文） / `名前を震源とする地震が発生しました。`（深さ不明の電文） / `名前で地震。`（EEW） |

**震度の句は名前より前に来る**（「最大震度4を〇〇、△△で観測しました。」）。名前の直後に震度が続く形は無いので、
そのつもりで読ませると実在しない語順を試すことになる。震央地名も同様に、深さが判っている電文では
名前の直後が読点になり（「〇〇、深さ10キロメートルを震源とする」）、深さ不明（遠地地震で多い）では
名前に「を」が直に付く。**両方を読ませること。**

**この表は文言を変えたら見直すこと。** 逆に、表に無い文脈でだけ崩れる名前は辞書に入れない。たとえば潮位観測点の
「名前＋を」は起きない（「を観測しました。」は波高の後ろに付く）ので、そこでだけ誤読する観測点名は放っておく。
入れるほど該当語の前後を別合成する経路と間の挿入が増えるため、実害の無いものは足さない。

## 3. 突き合わせ

ふりがな（ひらがな）と VOICEVOX の出力（カタカナ・長音は母音表記）を比べるので、正規化してから比較する。

```python
# ひらがな→カタカナ、おう→オオ、えい→エエ、ヅ→ズ、ヂ→ジ。記号は落とす
ODAN, EDAN = 'オコソトノホモヨロヲゴゾドボポョ', 'エケセテネヘメレゲゼデベペェ'
def norm(s):
    s = ''.join(chr(ord(c)+0x60) if 'ぁ' <= c <= 'ゖ' else c for c in s)
    s = re.sub(r'[^ァ-ヴ]', '', s)
    out = []
    for c in s:
        if c == 'ウ' and out and out[-1] in ODAN: out.append('オ')
        elif c == 'イ' and out and out[-1] in EDAN: out.append('エ')
        else: out.append(c)
    return ''.join(out).replace('ヅ', 'ズ').replace('ヂ', 'ジ')
```

VOICEVOX に読ませる部分:

```python
def kana(text):
    u = f"http://192.168.0.64:50021/accent_phrases?text={urllib.parse.quote(text)}&speaker=6"
    with urllib.request.urlopen(urllib.request.Request(u, method='POST'), timeout=20) as r:
        return ''.join(''.join(m['text'] for m in p['moras']) for p in json.load(r))
```

見るのは 3 種類。

1. **ふりがなと食い違うもの** — 全文脈で一貫して誤読するものはこれでしか見つからない
2. **文脈で読みが変わるもの** — 上の表の各文脈で読ませ、名前部分が一致しないものを拾う
3. **既存の辞書エントリの値** — ふりがなと突き合わせる。2026-08-22 の棚卸しでは既存 2 件の誤りがここで出た
   （白浜町堅田 カタダ→カタタ、那智勝浦町浦神 ウラカミ→ウラガミ）

**ふりがなが無い系統（震央地名）は読みを目で通す。** 1,063 件を通したときは「南東方＝ナントオカタ」「〜海＝〜ウミ」
「三重会合点＝ミエカイゴオテン」のような系統的な崩れが出た。1 件見つけたら**同じ構成の名前を全部当たること**。

## 4. エントリを作る

値は AquesTalk 風カナ表記（`POST /accent_phrases?is_kana=true` に渡す形）。`/` が句区切り、`'` がアクセント核。

- **アクセント句の割り方は既存の兄弟エントリに倣う**（`長崎県五島: ナガサキ'ケン/ゴトオ'` → `長崎県西方: ナガサキ'ケン/セエホオ'`）
- 正しく読める文脈があるなら、**その出力のモーラとアクセント核をそのまま写す**のが最も確実
- 長音記号「ー」は使えない（`UNKNOWN_TEXT`）。アクセント核は 1 句にちょうど 1 つ（0 個は `ACCENT_NOTFOUND`、2 個は `ACCENT_TWICE`）
- **キーに読点を含めない。** 辞書の照合はチャンク単位で、チャンクは読点の後ろで切れる。電文名が
  「インドネシア、スマトラ南西方」なら読点より後（`スマトラ南西方`）をキーにする
- 短いキーがより長い地名の一部になるなら、長い側を VOICEVOX が正しく読むかで決める。正しく読むなら
  `_standalone`（単独出現だけ一致）へ、誤読するなら部分一致のまま。判断の詳細は仕様書 §3「単独語キー」
- 逆に**部分一致を狙って短くする**手もある（`三重会合点` の 1 件で「インド洋三重会合点」「ガラパゴス三重会合点」を拾う）

書いたら 1 件ずつ `is_kana=true` に投げて、意図した読みとアクセント核に戻ることを確かめる。

## 5. 仕上げ

- `npx tsc -b` / `npm test`（`src/utils/ttsPhraseBreakDict.test.ts` が記法と単独語キーの境界を実データで検定する）
- ブラウザで**実際に合成へ渡る本文**を見る。dev サーバー（DMDSS 版）を起動して Playwright の `browser_evaluate` で:

```js
const mod = await import('/realtime-earthquake-viewer/dmdss/src/utils/voicevox.ts')
const sent = []
const orig = window.fetch
window.fetch = (...a) => {
  const u = String(a[0])
  if (u.includes('/synthesis') && a[1]?.body) {
    const q = JSON.parse(a[1].body)
    sent.push(q.accent_phrases.map(p => p.moras.map(m => m.text).join('') + '(' + p.accent + ')').join('/'))
  }
  return orig(...a)
}
await mod.speakWithVoicevox('http://192.168.0.64:50021', '長崎県西方、対馬海峡で1メートルが予想されています。', 6, 0.001)
window.fetch = orig
return sent   // → ["ナガサキケン(4)/セエホオ(4)", ...]
```

`is_kana` の逆引きだけでは「辞書が当たっているか」が判らない。**キーの一致・分割・繋ぎ直しまで通した本文**を見ること。

## 落とし穴

- **記法が壊れても静かに効かなくなるだけ**。VOICEVOX は 400 を返すが `synthesizeChunk` は辞書適用前の読みで
  合成を続けるので、音は出て誤読が直らない。ユニットテストが最後の砦
- **観測点名は読み上げに出ない。** 地震の読み上げは観測点を区域名へ丸める（`lookupStationRegion`）。
  誤読していても声にならないので、辞書に入れる必要はない（境界判定の当否だけテストで固定してある）
- **「町」の読み（ちょう／まち）は自治体ごとに違う。** 気象庁のふりがなに従うこと。推測すると外す
  （岬町＝みさきちょう／苓北町＝れいほくまち）
- **ふりがなが無い系統は目視なので、途中で打ち切っても気付けない。** 走査対象の件数を先に数え、
  最後まで通したことを確かめること（2026-08-22 は海外の詳細震央地名 683 件のうち 400 件で止めており、
  残りを通したら 9 件出た）
